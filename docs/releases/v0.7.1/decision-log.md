## 0. 授权与范围

**用户原话（本版指令来源）**

> 「我已在 pad 上完成验证，确认输入法功能已修改正常。请更新 GitHub 仓库中相关项目的说明文档，使其与当前
> 已验证的实现保持一致，并同步发布对应的 release 版本，确保版本号、更新日志与变更内容准确对应。完成后
> 简要说明更新了哪些内容及 release 版本信息。」

| 项 | 内容 |
|---|---|
| 授权类型 | 沿用此前的一次性前置授权（执行中需确认的环节默认自动确认，并生成可追溯的确认日志） |
| 自动确认范围 | 版本号选择、发布范围（是否全平台重打）、文档措辞、资产上传顺序、校验清单合并方式 |
| **不**自动确认范围 | ① 需要平板/蓝牙键盘的实测（本机没有，由用户完成）；② 破坏性操作；③ 覆盖既有 Release 的版本历史 |
| 生效判据 | 每条决策标注 `[自动确认]`，并在「证据」列给出可复现命令或实测数字 |

**本版新增的事实来源**：用户 2026-11-09 的实测结论——Android 平板接蓝牙键盘后，中文输入法能正常调起、
组词、上屏。这是本项目第一次拿到 Android 输入链路的**设备级运行证据**，此前只有代码层与包内证据。

## 1. 决策清单

### 1.1 版本与发布范围

| # | 决策点 | 备选项 | 采用 | 依据 | 证据 |
|---|---|---|---|---|---|
| D1 | 版本号定多少 | ① 仍是 `0.7.0`，只换包 ② `0.7.1` ③ `0.8.0` | **② `0.7.1`** | ① 让同一版本号对应两份不同字节，`SHA256SUMS.txt` 就失去意义，侧载用户无法判断装的是哪一份。③ 0.8.0 按语义化版本意味着新功能，而本版只修 bug、无新能力 | `core/package.json` / `desktop/package.json` = `0.7.1`；`versionCode 9`、`versionName 0.7.1` |
| D2 | 只发 APK，还是全平台重打 | ① 只发 APK，其余平台沿用 v0.7.0 资产 ② 全平台重打到 0.7.1 | **② 全平台重打** | 前端 bundle 确实变了：`main.ts` 多了「显示 → 虚拟键盘」菜单项、七个语言文件各多 3 个键。只是非 Android 平台条件不成立而不显示。留 0.7.0 的 Windows/macOS 包，等于让"版本号与变更内容对应"这句话失真 | `git diff 5e3bbea^ --stat` 含 `core/src/main.ts`、`core/src/i18n/locales/*.ts` |
| D3 | Linux 四件怎么出 | ① 本地想办法出 ② 打 tag 让 CI 出 | **② CI** | `dpkg-deb` / `rpmbuild` / `appimagetool` 都是 ELF，Windows 跑不了（v0.7.0 已确立的分工）。tag 触发还能顺带把 v0.7.0 建的那套容器安装验证再跑一遍，等于给新包做回归 | `.github/workflows/linux-installers.yml` 的 `push: tags: ['v*']` |
| D4 | 是否覆盖 v0.7.0 的 Release | ① 把 v0.7.0 的资产替换成 0.7.1 ② 新建 v0.7.1 Release，v0.7.0 原样保留 | **② 新建** | 已发布的版本是历史事实，用户可能已经下载并在用。改历史会让"我装的是哪个版本"这个问题失去答案 | 两个 Release 并存：`v0.7.0`（8 资产）、`v0.7.1`（8 资产） |

### 1.3 打包与上传

| # | 决策点 | 备选项 | 采用 | 依据 | 证据 |
|---|---|---|---|---|---|
| D9 | 下载表的体积/哈希怎么填 | ① 沿用 v0.7.0 的数字 ② 手抄新数字 ③ 占位符 + 脚本回填 | **③ 占位符 + 回填** | ① 是错的。② 手抄 64 位十六进制必错，而且 CI 每次重打都会变（v0.7.0 的 V47 教训）。③ `tools/backfill-v071.py` 从 Release API 读 `size` 与 `SHA256SUMS.txt` 回填 | 回填后 README 与 notes 的剩余占位符数为 0 |
| D10 | `SHA256SUMS.txt` 谁产出 | ① 本地算 ② CI 算，本地合并 | **②** | 本地算不了 Linux 四件（包在 CI 里生成）。用 CI 的合并逻辑（download 旧清单 → `grep -vE` 剥自己 → `sort -k2`）拼接，避免重跑冲掉别的平台条目 | CI 输出 + 本地 `publish-release.mjs` 追加 4 条 |
| D11 | 上传顺序 | ① 本地先发（含 notes）再让 CI 补 ② 让 CI 先建 Release，本地后补 | **②** | ① CI 的合并逻辑会以空清单为起点，把本地 4 条覆盖掉（v0.7.0 的 V47 已记录）。② CI 建 Release 时用 `--generate-notes`，本地随后 PATCH 成 `notes.md` 正文 | CI 步骤「生成校验并上传到 Release」→ 本地 `publish-release.mjs` |
| D12 | `GITHUB_UPLOAD_IP` 要不要设 | ① 和 `GITHUB_API_IP` 一样设成 140.82.112.6 ② 不设 | **② 不设** | `uploads.github.com` 与 `api.github.com` 是两套服务，共用 IP 会让附件上传返回 `404 Not Found`（2026-11-02 踩过） | 只设 `GITHUB_API_IP` |
