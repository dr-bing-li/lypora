# v0.8.1 决策记录

日期：2026-11-09 · 前置版本：v0.8.0（同日发布）

## 为什么紧接着发一个补丁版

v0.8.0 的发布说明里把「剪贴板粘贴」列进了已知限制。检查后发现实际比写的更严重：**粘贴路径从始至终
没有处理过图片**，`pasteClipboard()` 只调 `readText()`，键盘粘贴走 Chromium 原生行为、图片项无人读取。
也就是说 v0.8.0 花了整版做的三档路径策略，对「截图 → Ctrl+V」这个最高频的插图方式完全无效。

这属于"功能对用户当场失效"，不是可以放进下一版的增强，所以按补丁位发布（`0.8.1`，versionCode 11）。

## 关键取舍

### 1. 为什么在 window 上挂 capture 监听，而不是用 CM6 的 domEventHandlers

CM6 的 `EditorView.domEventHandlers({ paste })` 会在自己的 contenteditable 上处理事件，但它排在捕获阶段
之后。要在 CM6 之前把事件拿走来自己去读剪贴板、复制文件，只能用 `window.addEventListener('paste', h, true)`。

代价是这个监听器对整页生效，所以判断必须**极窄**：只有 `clipboardData.items` 里出现
`kind === 'file'` 且 `type` 以 `image/` 开头时才 `preventDefault()`。其余一律 `return`，文本粘贴完全交给
CM6 原有逻辑（V53 里有专门一条断言守着这个）。

### 2. 为什么 preventDefault 必须同步

这是整件事最容易踩死的地方：`document.execCommand` 时代的经验会让人想"先读剪贴板再决定"。但 paste 事件
是**同步派发**的，异步回调里调用 `preventDefault()` 没有任何效果——那时 CM6 已经把内容插进文档了。

所以判断只能基于同步可得的 `clipboardData`，真正的插入（读文件、复制、拼路径）全部异步，返回后再 dispatch。

### 3. 为什么让主进程把位图落成临时文件

三个方案对比：

| 方案 | 问题 |
|---|---|
| 直接用 `clipboardData` 里的 `File` 走管线 | 位图 `File` 没有磁盘路径，`webUtils.getPathForFile()` 返回空串 → 按 v0.8.0 规则降级成 base64，静默违背用户的「复制到附件目录」 |
| 渲染层读成 base64 再自造文件 | 同样拿不到路径，还是内嵌 |
| **主进程 `clipboard.readImage()` → 存临时 PNG → 回传路径** | 拿到真实路径，三种路径模式全部生效 |

选第三个。代价是多一次 IPC 与一次磁盘写（几百 KB 的截图可忽略），换来的是"设置说了算"。

**临时文件刻意不删**：`relative` / `absolute` 模式下正文引用的就是这个文件。删了图就断，而且用户不会知道
为什么。宁可留一个几 MB 的临时文件，也不能留一个指向空处的路径——那正是 v0.8.0 修掉的那个 bug 的形状。

### 4. 为什么 `withData` 是可选参数

`clipboard.readImage()` 的像素内容转 base64 是 4/3 倍体积，一张 3 MB 截图就是 4 MB 字符串过 IPC。
但只有「内嵌 base64」模式才需要像素，默认的「复制到附件目录」只认路径。所以做成 opt-in：
菜单粘贴时先看 `getImageRefMode()`，是 embed 才要数据。

### 5. 为什么动 `image:place` 加 preferredName

剪贴板落盘的文件名是 `clipboard-20261109-153000-1234.png`（带 pid，防并发撞名）。复制到附件目录时
若沿用这个名，用户看到的是运维日志味的一串东西。而 `image:place` 原本只认 `basename(srcPath)`，
没有覆盖入口。

加 `preferredName` 时顺手做了两件事：
- 只取 `path.basename`，天然挡掉 `../` 穿越
- 过滤控制字符与 `<>:"|?*`，避免 Windows 非法文件名

### 6. 为什么顺带修了「图片粘在段落里」

测试时发现插入的图片直接拼在光标处，光标在行尾时变成 `文字![图](./img/a.png)`，渲染后图和文字挤在
同一段、两张图会并排。这是 v0.8.0 就有的问题，只是当时测的都是空文档所以没暴露。

修法是在插入位置两侧按需补 `\n\n`。属于同一功能面，一起修，不单独开版本。

### 7. 打包脚本改用系统命令删除

本机宿主的「安全删除」钩子会把 node 的每次删除转成回收站操作，这次这个转运持续失败并 fail-closed，
`pack-win.mjs` 连 `fs.rmSync` 都过不去（报的是 safe-delete 错误，不是权限错误）。

`release/` 是纯构建产物（`.gitignore` 里就有），所以改用 `cmd /c rd|del`，绕开那层钩子。这不是
为了绕过保护，而是这层保护对生成物没有意义，且它坏了会直接卡住发版。

## 未做

- **Android 粘贴未真机验证**：走的是 `Filesystem` 写 `Documents/Lypora/<附件目录>/` 的分支，代码层与
  浏览器侧用例通过，但没有设备实测。已在发布说明的「已知限制」里写明。
- 剪贴板里的**图片 + 文本混合**内容：目前只取图片，文本丢弃。实际场景几乎不存在，不做。
- 不做粘贴去重：同一张图粘两次会落两个文件，第二次带时间戳前缀。语义上这是两次插入，不合并更符合预期。
