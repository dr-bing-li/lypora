## 1. 为什么是「一标签一份 `EditorState`」

最省事的实现是切标签时 `view.dispatch({ changes: 整篇替换 })`。它的问题不在性能，在**语义**：
撤销历史属于 `EditorState`，换内容会把 A 文档的历史连着换掉，于是你在 B 文档按 `Ctrl+Z`
退到的是 A 文档的编辑。这在编辑器里属于不可接受的错，而不是"体验差一点"。

代价与对策：

- **内存**：每份 state 各自持有历史与语法树。实测 5 个中等文档（每个 1–3k 行）无感；真正大的是图片装饰缓存，
  它挂在 ViewPlugin 上，切走时本来就会被丢弃。
- **ViewPlugin 运行时状态不跟着 state 走**：`setState()` 之后要**补发一个空事务**，否则图片尺寸缓存
  停在上一个文档的值上（表现为图片高度按前一篇的图算）。这条写进了 `applyTab()`，注释里标了原因。
- **滚动位置**：CM6 的 `scrollTop` 属于 DOM 而非 state，切走前 stash、切回后恢复。

## 2. 关键取舍

### 2.1 脏标记以磁盘为准，不做"编辑过就置脏"

两条路：编辑即置脏 + 保存时清；或每次比较内容。选了后者。

- 前者会出现"改了一个字又删回去，`*` 还在"，以及"撤销回到保存点，`*` 还在"——用户会认为标记在骗人。
- 后者的成本是一次字符串比较（10 万字文档上无感），换来的是**标记永远说真话**，而且撤销回保存点时
  `*` 自动消失，不需要额外记账。
- 反向依赖只有一处：`doSave()` 成功落盘后把 `tab.saved` 更新为当前内容。这是唯一的写入点。

判据也要挑对：**只读判断不能看 `textContent.length`**（CM6 虚拟滚动会让它随视口变化），要看
`contenteditable`；查 `*` 不能全局搜，要限定 `.tab-item.active .tb-dirty`，否则会读到别的标签。

### 2.2 三键确认必须自己画，不能用 `confirm()`

原生 `confirm()` 只有「确定 / 取消」两个按钮，而这里需要三选，且**默认动作必须是取消**——
把"丢弃"和一个"确定"按钮绑在一起是数据事故的常见形态。所以 `ui/confirm.ts` 自己画，并在**捕获阶段**
吃 `Esc`（取消）与 `Enter`（保存），点遮罩等同取消。

多标签同窗关闭时**一次列全**所有脏文档名，不一个标签弹一次——后者在 5 个脏标签时会变成连点 5 次，
用户第三次就会条件反射点"不保存"。

### 2.3 真窗口，不做"伪多窗口"

需求原文允许"多窗口和 tabs 两者并存方便多显示器"。伪实现（同一窗口里并排两栏）做不到"拖到第二块屏"，
而这正是多显示器场景的全部意义。所以：

- 每个窗口一个独立 `BrowserWindow`，各自跑一份前端、各自持有一组标签。
- **关闭守卫状态必须挂在窗口对象上**（`w.__allowClose` / `w.__askingClose`）。第一版用了模块级变量，
  结果第二个窗口一开就串味：在 A 窗口点「取消」，B 窗口也跟着不关了。这是"模块级状态 vs 多实例"的经典错，
  记在 docs/04 V60。
- **单实例保留**，但语义改了：第二次启动不再把文件塞进已有窗口，而是**开新窗口**。
- 浏览器与 Android 没有系统窗口可开 → 「仅多窗口」「两者并存」置灰。给一个点了没反应的开关比不给更糟。

### 2.4 整屏面板的顶边必须算，不能写死

模态时代 `.ce-mask` 是 `fixed; inset: 0`，铺满视口是对的。改成"占满编辑区、保留菜单栏"之后，
顶边成了一个**运行时可变量**：菜单栏在窄屏会折行，标签栏可能被隐藏。

- 用 `100vh` 再减固定值：手机上 `100vh` 含地址栏，底部三个导出按钮被推出屏外。
- 写死 `44px`：窄屏菜单栏折成两行就错位。
- 所以 `open()` 里实测「菜单栏 bottom + 可见标签栏高度」写进 `--ce-top`，CSS 只用
  `inset: var(--ce-top, 0px) 0 0 0`。`0px` 兜底是给"JS 没跑起来"的降级，不是正常路径。

另外两条必改项：`.ce` 要去掉圆角与阴影（否则整屏后是一圈奇怪的边框，验收会量到 `radius=12px`）；
窄屏媒体查询必须确认没被文件末尾的同特异性规则顶掉（0.10.0 在同一条沟里翻过车，见 docs/04 V56/V58 系列）。

### 2.5 帮助 = 数据，不是代码

8 篇 `.md` 用 `?raw` 编译进包内，`help/index.ts` 只做两件事：标题查 `MessageKey`、按当前语言取正文。
好处是加一篇帮助等于加两个文件，不碰逻辑；代价是**内容要跟着代码核对**，所以写的时候逐条对了
`shortcut:` 字段与 `PARAM_SPECS`。运行时零网络请求（与模板引擎同一条约束）。

只读标签的实现有个坑：`EditorState.readOnly` + `EditorView.editable` 装在同一个 `Compartment` 里，
**同一个 Compartment 实例只能 `of()` 一次**，第二次会抛 `Duplicate use of compartment in extensions`。
所以这组扩展只在 `createEditorState()` 里出现一次，靠 `readOnly` 选项决定内容。记在 docs/04 V62。

第二条坑是"只读文档不该有活动行源码态"：`selectionLineSpans()` / `isTouched()` 原来不区分只读，
于是帮助页的一级标题上挂着一个 `#`、表格第一行露出一排管道符。修法是对 `EditorState.readOnly` 一票否决
（V61）。这个 bug 是截图肉眼看出来的，不是断言抓到的。

## 3. 实现过程中真正踩到的坑

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | `Duplicate use of compartment in extensions` | `readOnlyComp` 同时在 `buildExtensions` 与 `createEditorState` 里 `of()` | 只保留 `createEditorState` 一处（V62） |
| 2 | 帮助页标题挂 `#`、表格露管道符 | 活动行源码态没排除只读文档 | `selectionLineSpans` / `isTouched` 对 `readOnly` 返回空（V61） |
| 3 | 第二窗口跟着第一窗口的"取消"一起不关 | 关闭守卫用了模块级变量 | 改挂 `w.__*`（V60） |
| 4 | 撤销回保存点 `*` 不消失 | 脏标记按"编辑动作"置位 | 改成 `内容 !== tab.saved`（V59） |
| 5 | 关标签选「取消」后，界面停在临时切过去的标签 | `closeTab()` 先切后问 | 加 `backToPrev()`，问之前不动激活态 |
| 6 | 打开文件后多出一个标签 | 首屏示例文档被当成"要保留的文档" | 复用条件从"空白且未改"放宽为**未改且无 path** |
| 7 | 验收断言假通过（只读用 `textContent` 长度判） | CM6 虚拟滚动让长度随视口变 | 改查 `contenteditable="false"` |
| 8 | 验收里排版 `top` 少算 34px | 只比了菜单栏，漏了标签栏 | 改比 `chromeBottom`（菜单栏 + 标签栏） |
| 9 | `beautify-check` 卡死 `spawnSync ETIMEDOUT` | 脚本里 `fs.rmSync(目录)` 撞上宿主安全删除钩子 | 输出目录改时间戳子目录，不再删（docs/04 既有坑） |

## 4. 验证与证据

同一台机器（Windows 11 / Edge / Node 22.22.2）：

```
tsc --noEmit    0 错
vite build      通过（产物 0.11.0，sw 缓存名 lypora-v5）
tabs-check      7 组断言全过（详见 notes.md 的验证一节）
verify / export-check / theme-check / mobile-check / beautify-check / i18n-check   全 pass，errors []
--selftest      ok，windows 1→2、传入文件到达、bridgeApi.newWindow、consoleErrors []
closetest       五场景，dirty-multi 报 names: ["功能演示.md","未命名.md"]
```

`--selftest` 里的多窗口取证是这次新加的：它真的调一次 `window.lyporaDesktop.newWindow({name,content})`，
然后读 `BrowserWindow.getAllWindows().length` 从 1 变 2，并核对新窗口收到的文件名。
只断言"IPC 注册了"是不够的——那只能证明通道存在，不能证明窗口真的开出来了。

## 5. 这次没有做的事

- **标签不跨重启恢复**：需求里没提，且"恢复上次所有标签"要处理"文件在外部被删/改名"的一堆情形。
  未保存内容仍然会被拦截，不会静默丢。
- **手机上的标签管理**：手机上整条标签栏隐藏，一次一个文档。手机端"多文档"另有做法（文档列表页），
  不在本次范围。
- **macOS / Linux 的多窗口真机验证**：代码是同一份主进程，但只在 Windows 打包版上点过。
  写文档时按"结构证据"表述，没有拔高成"已验"。
