## 本版新增：多语言界面

**支持的语言**（7 种）：简体中文、English、日本語、한국어、Español、Français、Deutsch。

**切换入口**：顶部菜单栏最右侧多了一个「语言 / Language」菜单。第一项是「跟随系统」，
下面分隔线之后是七种语言，当前生效的那项打勾。语言名一律用**母语写法**，不做翻译——
否则在你看不懂的界面语言里，你反而找不到自己的语言。

**两处细节值得说明**：

- **运行时切换不重建文档**。切换语言时编辑器实例不销毁，只重配 CM6 的 `placeholder` 扩展，
  所以**撤销历史、选区、滚动位置全部保留**，不会像刷新一次那样回到文件开头。
- **跟随系统是对 `navigator.languages` 逐项匹配**，取第一个能对上的语言；
  `zh-Hans-CN` / `zh-TW` / `zh-HK` 一律落到简体中文（本版未做繁体中文界面）。
  选过一次具体语言后就不再跟随系统，想回去选「跟随系统」即可。
- 偏好写在 `localStorage['lypora:locale']`（存 `'system'` 或语言 id），重启后恢复。

**翻译覆盖范围**：8 个顶级菜单 + 全部下拉项（66 项）、状态栏（字数/行数/预览模式/专注模式/打字机模式）、
侧栏三个视图与空态提示、移动端底部 6 键操作栏与 8 个面板分区、全部 toast 与确认弹窗、
编辑区占位符、链接/图片/表格插入的默认文字、字数提示的 tooltip、相对时间（「3 分钟前」）。

**没翻译的**：文件名、文档内容、主题名（GitHub / Night / Pixyll 等是专有名词）、
Markdown 语法本身（`**粗体**` 之类）、导出 HTML 里的文档内容。

**语言资源怎么组织的**：`core/src/i18n/locales/*.ts`，一个语言一个文件，扁平到命名空间下；
`zh-CN.ts` 是**键集合的唯一真源**，其余语言文件用 `Dict = typeof zhCN` 做编译期类型约束——
少一个键、多一个键、把 `{ one, other }` 写成字符串，`tsc` 当场报错。加一门新语言 =
新建一个 locale 文件 + 在 `index.ts` 的 `DICTS` 和 `LANGUAGES` 各加一行，不需要改任何调用点。

## New in this release: a multilingual UI

**Seven languages:** Simplified Chinese, English, Japanese, Korean, Spanish, French, German.

**Where to switch:** a new **Language** menu sits at the far right of the menu bar. The first entry is
*Follow System*; below a separator are the seven languages, with a check mark on the active one.
Language names are always shown **in their own script** and never translated — otherwise, stuck in a UI
language you don't read, you couldn't find your own.

**Two details worth spelling out:**

- **Switching does not rebuild the document.** The editor instance survives; only the CM6 `placeholder`
  extension is reconfigured. **Undo history, selection and scroll position are all preserved** — no jump
  back to the top of the file as a reload would cause.
- **Follow System walks `navigator.languages` in order** and takes the first match; `zh-Hans-CN` / `zh-TW` /
  `zh-HK` all resolve to Simplified Chinese (there is no Traditional Chinese UI in this release).
  Once you pick a concrete language, it stops following the system; pick *Follow System* to go back.
- The preference lives in `localStorage['lypora:locale']` (`'system'` or a language id) and is restored on restart.

**What is translated:** the 8 top-level menus and all 66 dropdown items, the status bar (word/line counts,
preview mode, focus mode, typewriter mode), the three sidebar views and their empty states, the mobile
bottom dock (6 actions) and all 8 panel sections, every toast and confirmation dialog, the editor
placeholder, default text for inserted links/images/tables, the word-count tooltip, and relative
timestamps ("3 minutes ago").

**What is not:** file names, document content, theme names (GitHub / Night / Pixyll are proper nouns),
Markdown syntax itself, and document content inside exported HTML.

**How the resources are organised:** one file per language under `core/src/i18n/locales/`.
`zh-CN.ts` is the **single source of truth for the key set**; every other file is type-constrained by
`Dict = typeof zhCN`, so a missing key, an extra key, or a plural written as a plain string is a
compile-time error. Adding a language = one new locale file + one line each in `DICTS` and `LANGUAGES` —
no call site changes.

## Installation

### Windows 10/11 x64

1. Unzip `Lypora-0.5.0-win-x64.zip` into a `Lypora\` folder (**keep the folder intact** — don't copy just the exe).
2. Double-click `Lypora\Lypora.exe`.
3. If SmartScreen complains on first run: *More info* → *Run anyway*. The exe is **not code-signed**; that's why.
4. To associate `.md` files: right-click any `.md` → Open with → Choose another app → browse to `Lypora.exe` → *Always use this app*.
5. Uninstalling = delete the folder. Settings live in `%APPDATA%\lypora-desktop`; delete that too if you want a clean slate.

### Android 10 and later

1. Copy `Lypora-0.5.0-android.apk` to the phone (USB, a file-transfer chat, or cloud storage — all fine).
2. Tap to install. Android will warn about unknown sources; that's normal for sideloaded APKs — allow that source in the dialog.
   (Or from a computer: `adb install -r Lypora-0.5.0-android.apk`)
3. First launch spends 1–2 seconds warming up the WebView, then you land in the editor.
4. Uninstalling **deletes the documents stored inside the app**. Export what you want to keep first.

## Notes and caveats

**General**

- No auto-update. Upgrading = download and overwrite (replace the Windows folder; install the same-signed APK over the old one).
- This is a **vibe coding** project: broad feature coverage, uneven code quality. Treat it as a draft, and open an issue when something breaks.
- Very large documents (>1 MB or tens of thousands of lines) may drop frames while scrolling. Exported HTML references images
  by relative path, so moving the HTML alone will break them.
- All seven translations were written by hand, but none was proofread by a native speaker. Awkward phrasing and
  inconsistent terminology are possible — PRs against `core/src/i18n/locales/*.ts` are very welcome.

**Windows only**

- Not code-signed: SmartScreen will block once; corporate group policy may block it outright.
- No installer, no registry writes, no admin rights required.

**Android only**

- **Files live in the app-specific directory**: `Android/data/app.lypora.editor/files/Documents/Lypora/`.
  That needs no storage permission, but Android 11+ file managers can't browse into it. To hand a file to
  someone else (save to Files, send via chat, upload to cloud), use **Export → system share sheet**.
- The first *Open* goes through the system file picker, so any file on the phone is reachable; saving writes back to the app directory above.
- The touch UI is a separate shell, not a squeezed desktop layout: two bottom rows (a formatting bar plus
  open/save/outline/export/theme/menu), the **8 top-level menus folded into a bottom sheet**, and the left
  sidebar turns into a drawer.
- These are **greyed out** on phones (unreliable in Android WebView): export to PDF (export HTML instead),
  open folder, import third-party theme CSS.
- This build has **not** been tested on a physical device for cold start, native file I/O or the share sheet
  (no device was attached to the build environment). Layout and hit areas were verified in Chromium at five
  viewports — 360/393/430/800/1440 — with touch emulation. If a real device misbehaves, please open an issue
  with the model and OS version.
