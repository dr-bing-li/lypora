**用户原话（唯一指令来源）**

| 项 | 内容 |
|---|---|
| 授权类型 | 一次性、前置、覆盖本次任务全流程 |

## 1. 决策清单

### 1.1 技术选型

| # | 决策点 | 备选项 | 采用 | 依据 | 证据 |
|---|---|---|---|---|---|
| D1 | i18n 运行时用什么 | ① `i18next` ② `@formatjs/intl` ③ 自研 | **③ 自研（190 行、0 依赖）** | 需求只有「查表 + `{name}` 插值 + 单复数」，任何库的体积与概念负担都超过收益；项目定位是零框架运行时 | 产物体积增 ≈9KB（gzip ≈4KB）；`core/src/i18n/index.ts` 无 import |
| D2 | 词表组织方式 | ① 一份大 JSON 按语言分块 ② 一语言一文件 ③ 一模块一文件（跨语言） | **② 一语言一文件**（`locales/zh-CN.ts` … `de.ts`） | 加语言 = 加一个文件 + 两行注册；按模块切会让"某语言漏了一整块"无法被单文件 diff 发现 | `core/src/i18n/locales/` 7 个文件 |
| D3 | 类型约束策略 | ① 不做（靠脚本查） ② 每语言手写 interface ③ `Dict = typeof zhCN` 反推 | **③ 反推** | 中文词表即契约：少键/多键/形状不符全部编译期报错，不必等运行时 | `tsc --noEmit` 通过；D18 记录了一次真实拦截 |
| D4 | 查表实现 | ① 运行时递归嵌套对象 ② 加载时扁平化成 `Map` | **②** | `t()` 在状态栏每帧会被调用（字数/行数），单次查表必须 O(1) | `i18n/index.ts` 模块级 `FLAT` Map |
| D5 | 查不到键时的行为 | ① 返回空串 ② 返回 `zh-CN` 兜底 ③ 返回键名本身 | **③ 返回键名** | 漏翻要在界面上**看得见**；返回空串会让界面静默少一块，最难排查。兜底链仍保留 `['en','zh-CN']` 处理"键存在但该语言整块缺失" | 验收脚本专门断言"界面不出现键名" |
| D6 | 单复数方案 | ① `Intl.PluralRules` ② 写死 `{one,other}` 两型 | **②** | 7 种语言里只有 en/es/fr/de 需要区分，中/日/韩恒为单型；引入 `Intl.PluralRules` 为 4 种语言换一套 API 不划算 | `status.words` 等 4 处 |
| D7 | 无复数语言怎么写 | ① 只写一个字符串 ② 两份相同文案 | **② 两份相同** | ① 会让 `typeof zhCN` 反推出 `string`，与中文的 `{one,other}` 冲突（TS2719）；② 保住"七份词表形状完全一致"这条不变量 | 见 D18 |
| D8 | 运行时切换如何避免丢撤销历史 | ① `location.reload()` ② 重建 `EditorState` ③ 只重配 `Compartment` | **③** | ① 丢滚动位置与撤销栈；② 丢撤销栈；占位符是编辑器内唯一需要改的文本，`Compartment.reconfigure` 是一次普通事务 | `core/src/editor/setup.ts` `placeholderComp` |
| D9 | 静态文案怎么落地 | ① JS 里逐个 `querySelector` ② 在 HTML 打 `data-i18n*` 标记 | **②** | 41 处静态文案逐个查找必然漏，且改 HTML 就要改 JS；标记法让 HTML 自己声明"我这段是文案" | `core/index.html` 中 `data-i18n` / `-title` / `-aria` 三类 |
| D10 | 结构锚点怎么做 | ① 继续用文案文字定位 ② 换 `data-*` 稳定 id | **②** | 换语言后文字定位全线失效且**静默失败**（`querySelector` 只返回 null），验收脚本也无法跨语言复用 | 菜单 `data-menu` / 菜单项 `data-mi` / 分区 `data-section`；详见 docs/04 V40 |

### 1.2 产品与界面
