## 1. 决策清单

### 1.1 需求边界（由三轮问询确定，均来自用户选择）

| # | 决策点 | 备选项 | 采用 | 依据 |
|---|---|---|---|---|
| D1 | 状态栏开关形态 | 三态循环按钮 / 下拉菜单 / 三段式分段控件 | **三态循环按钮** | 与状态栏既有的「源码模式」「专注模式」同款，零新组件 |
| D2 | 默认路径模式 | 拷贝到附件目录 / 相对 / 绝对 | **拷贝到附件目录** | 用户选择。理由是"插完就能用"，不依赖源图位置 |
| D3 | 附件目录怎么定 | 固定 `assets` / 复用已有 `img`·`images`·`assets` | **复用已有目录** | 用户选择。避免在一个已有 `img/` 的仓库里凭空造 `assets/` |
| D4 | 重名怎么处理 | 覆盖 / 加序号 / 加时间戳前缀 | **仅重名时加 `YYYYMMDD-HHmmss-` 前缀** | 用户选择。不重名就保留原名，文件名可读性优先 |
| D5 | 目录探测优先级 | 固定顺序 / 正文已有引用优先 | **正文已有引用多数派优先** | 用户选择。已有文档的既成约定比工具偏好更重要 |
| D6 | Android 是否纳入 | 纳入并允许降级 / 本期不做 | **纳入，接受降级** | 用户选择。拿不到源路径时降级内嵌，而不是报错 |
| D7 | Android 的相对根 | 设备根 `/` / 应用 `Documents/Lypora` | **应用 Documents 为根** | Android 10+ 的分区存储不允许任意路径；`Documents` 是用户可见、其他应用可读的唯一合理落点 |
| D8 | 内嵌 base64 是否设体积上限 | 不限制 / 超 2MB 提示 / 超 2MB 拒绝 | **不限制** | 执行侧默认（用户未反对）。语义最简，与 Typora 的 base64 行为一致 |
| D9 | 设置项放哪 | 新增顶级「设置」菜单 / 文件→偏好设置 / 塞进格式菜单 | **新增顶级「设置」** | 用户原话"在'设置'项里头"，说明确实要有一个「设置」入口 |

### 1.2 实现选择（执行侧判断，附理由）

| # | 决策点 | 备选项 | 采用 | 依据 |
|---|---|---|---|---|
| D10 | 路径解析放哪 | 直接写在 `live-preview.ts` / 抽纯函数 | **抽 `io/image-path-core.ts`（零 import）** | 路径规则有 20+ 条边界（`../`、盘符、中文、`#`、跨盘、Android URI）。塞进渲染层就只能靠肉眼验；抽出来后 `image-check.mjs` 能跑 38 条断言，且不依赖 DOM |
| D11 | 相对路径怎么变成可加载 URL | 直接拼字符串 / 用 `new URL()` | **逐段百分号编码后拼 `file:///`** | `new URL('./a b.png', base)` 只编码部分字符，`#` 会被当锚点截断；手工编码每段才能覆盖 `#`、`?`、`%`、中文、空格 |
| D12 | 绝对路径的识别范围 | 只认 `C:/` / 加上 `C:\` | **两种都认** | 用户在 Windows 上复制路径常带反斜杠。不认就等于"能显示却插不进去" |
| D13 | 另存为后已渲染图片怎么办 | 不管 / 强制重载 / 空事务触发重算 | **空事务触发重算** | `ViewPlugin.update` 只在有事务时重建装饰；`dispatch({})` 是最小代价的重算信号 |
| D14 | 设置里父项要不要 `disabled` | 父项禁用 / 只禁子项 | **只禁子项** | 第一版把父项设了 `disabled`，结果子菜单连 `mouseenter` 都收不到，整块展不开——`<button disabled>` 不派发鼠标事件。改为父项可点、三个子项禁用，仍可展开看当前值 |
| D15 | 状态栏开关在内嵌模式下 | 隐藏 / 置灰 / 保持可点但无效 | **置灰 + `aria-disabled` + hover 提示** | 隐藏会让用户以为功能丢了；可点但无效是欺骗性 UI |
| D16 | 拖放取源路径 | `File.path` / `webUtils.getPathForFile` | **`webUtils.getPathForFile`** | Electron 32 起 `File.path` 已被移除，直接读是 `undefined`。这里静默失败会退化成"永远是内嵌"，很难发现 |
| D17 | 拷贝动作放渲染进程还是主进程 | 渲染层 `fs` / 主进程 IPC | **主进程 `image:place`** | 渲染进程开着 `contextIsolation` 且没有 Node 集成；目录探测、重名、复制需要真实文件系统。IPC 只暴露一个语义化方法，不把 `fs` 放给页面 |
| D18 | 浏览器 / PWA 怎么办 | 假装支持（写相对路径）/ 维持原行为 | **维持原行为并在文档标注** | 浏览器没有"文档目录"这个概念（FSA 拿到的是 handle，不是路径）。假装支持只会产出坏链接 |
| D19 | 粘贴剪贴板图片是否一起改 | 本期一起做 / 留到下一版 | **留到下一版** | 剪贴板图片没有源路径，走新管线也只能内嵌，收益为零；真正需要的是"粘贴时按当前设置落盘"，属独立改动 |
| D20 | 版本号 | 0.7.2（补丁）/ 0.8.0（功能） | **0.8.0** | 新增顶级菜单、新增两条设置、新增插入管线，属功能新增；同时 Android `versionCode` 9→10 保证可覆盖升级 |
| D21 | 发布范围 | 只发 Windows / 全平台 | **全平台 8 件** | 前端 bundle 变了（新菜单、新译文、新管线），留旧版包会让"版本号与内容对应"失真 |
| D22 | Linux 四件怎么出 | 本地 / CI | **CI（tag 触发）** | `dpkg-deb` / `rpmbuild` / `appimagetool` 都是 ELF，Windows 跑不了。分工与 v0.7.0 一致 |

## 3. 未覆盖与已知风险

1. **Android 插入图片没有真机验证**：只有代码层与浏览器侧证据。落盘走 `Filesystem`、渲染走
   `convertFileSrc()`，两段都各自被验证过，但没有在设备上串起来跑（H28）。
2. **macOS / Linux 包没有真实桌面启动证据**：仍是结构断言 + 容器安装，措辞与 v0.7.1 保持一致，
   不因为"这次没改这两端的代码"就放宽。
3. **粘贴图片未接入新管线**：剪贴板图片仍走 base64（D19）。
4. **浏览器 / PWA 不支持文档相对路径**：这是平台限制，不是遗漏（D18）。
