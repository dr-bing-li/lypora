## 2. 技术栈

| 层 | 选型 | 版本 | 理由 |
|---|---|---|---|
| 语言 | TypeScript | 7.x | 装饰层逻辑复杂，类型是最低成本的正确性保障 |
| 构建 | Vite | 8.x | 秒级构建，原生 ESM，代码分割（Mermaid/KaTeX 按需） |
| 编辑器内核 | CodeMirror 6 | state 6.5 / view 6.43 | 源码模型 + 装饰层原语 + 中文 IME 成熟（见 `01` §4） |
| Markdown 解析 | `@codemirror/lang-markdown`（GFM） | 6.5 | 增量解析，节点名已实测（`02` §3.3） |
| 数学 | KaTeX | 0.16 | 同步渲染、无 DOM 依赖、体积可控 |
| 图表 | Mermaid | 运行时探测 | 未静态依赖（安装不可靠），缺失时优雅退化为源码 |
| 桌面外壳 | Electron | 33.x | 本机无 Rust/MSVC，Tauri 不可行；Electron 预编译即用 |
| Android | PWA + Capacitor | — | PWA 立即可用；Capacitor 作为 APK 打包路径 |

**核心运行时不依赖任何 UI 框架**（无 React/Vue），产物 840KB / gzip 278KB。

## 4. 各模块职责与关键设计

> - `core/src/io/native.ts` —— Capacitor 能力桥。只暴露 `isNative() / writeDoc / readDoc / listDocs /

### 4.1 `editor/live-preview.ts` —— 全工程的核心

装饰层拆成**两个来源**，这是被 CM6 的硬约束逼出来的架构（实测踩坑，见 `04` V3）：

| 来源 | 类型 | 承载 | 为什么 |
|---|---|---|---|
| `blockDecosField` | StateField | 表格 / 分割线 / 块公式 / Mermaid 的**块级 widget** | CM6 禁止 ViewPlugin 提供 `block:true` 的 replace |
| `livePreview` | ViewPlugin | 其余全部**行内装饰 + 行装饰** | 需要视口信息做懒计算 |

两者通过 `BlockState.covered`（已被块级 widget 覆盖的行起始位置集合）协作，避免同一行被两个来源同时装饰导致 RangeSet 冲突。

**两态判定三件套**（StateField 与 ViewPlugin 共用同一套函数，保证视觉一致）：

```
isLineActive(state, pos)  块级：选区跨越该行 → 活动
isRangeActive(state, a, b) 多行块（表格/公式）：选区跨越块范围 → 活动
isTouched(state, a, b)    行内：光标落入 span 或选区相交 → 活动
```

**装饰产出规则**

| 非活动态 | 活动态 |
|---|---|
| `Decoration.replace({})` 隐藏定界符 | `Decoration.mark({class:'md-mark'})` 灰显 |
| 同时登记进 `atomics`，供 `EditorView.atomicRanges` 使用 | 不登记 |
| 用 widget 替代（复选框/圆点/表格/公式/图片） | 还原源码，施加等宽/弱化样式 |

**性能与正确性约束**

- 行内装饰只算 `view.viewport` 范围；
- `update()` 必须响应 `viewportChanged`（滚动不产生事务，漏掉就会滚动后露源码 —— `04` V5）；
- 块级 StateField 只遍历**块级容器**（`Document/Blockquote/*List/ListItem` 下钻，其余节点 `return false` 剪枝），复杂度约 O(行数)，且与视口无关；
- 中文 IME：光标所在行天然处于活动态，装饰不会改写该行结构，因此组合输入不被打断。

### 4.2 `editor/widgets.ts` —— 活动控件

| Widget | 交互 | 与参考实现的差异 |
|---|---|---|
| `TaskBoxWidget` | 点击直接切换 `[ ]`↔`[x]`（`mousedown` preventDefault，不移动光标） | 一致 |
| `BulletWidget` | 用 `•` 替换 `-`，宽度 `1ch` 保持缩进不变 | 一致 |
| `TableWidget` | 渲染真实 `<table>`；点击 → 光标落到表格首行 → 切回源码态可编辑 | **降级**：非单元格内联编辑 |
| `InlineMathWidget` / `BlockMathWidget` | KaTeX 渲染；点击 → 光标进入公式源码区间 | 一致 |
| `ImageWidget` | `<img>` 内联，加载失败降级为文字 | 一致 |
| `MermaidWidget` | 探测 `window.mermaid` 渲染，缺失则展示源码 + 提示 | **降级**：需外部注入 |
| `HrWidget` | 块级 `<hr>` | 一致 |

### 4.3 `io/files.ts` —— 能力适配层

四级降级，接口对上层同构：

```
window.lyporaDesktop（Electron 原生对话框 + 完整目录树）
  → showOpenFilePicker/showSaveFilePicker（FSA，桌面 Chrome/Edge、Android Chrome）
    → <input type=file> + Blob 下载（旧浏览器 / iOS）
      → Capacitor Filesystem（APK 宿主注入，未注入跳过）
```

工作区统一抽象为 `WorkspaceEntry = { label, open(): Promise<OpenResult> }`，桌面桥与浏览器句柄两种来源同构，UI 层无需区分。

### 4.4 `io/export.ts` —— 导出管线

- **Markdown**：原文直出，零转换（保证无损）；
- **HTML**：自研 `mdToHtml`（块级解析 + `inlineToHtml` 行内解析，含 KaTeX 服务端渲染与 HTML 块透传），并把当前主题的 CSS 变量从 `getComputedStyle` 复制进 `<style>`，产出**单文件、带主题、离线可看**的 HTML；
- **PDF**：把导出的 HTML 写入隐藏 iframe 后调用 `print()`，交给 Chromium 打印引擎 —— 与参考实现的 `printToPDF` 同构。

### 4.5 `style.css` + `ui/themes.ts` —— 主题系统

纯 CSS 变量驱动，**加一套主题 = 加一个 `[data-theme=xxx]` 块**。变量清单：

```
底色/前景/边框/强调/代码底/引文字色/选中色/高亮底
字体族（正文、等宽、标题）
内容宽度、正文字号、行高
```

内置 **6 套**（与参考实现内置主题同名同序）：`github`（默认）/ `night`（深色）/ `pixyll`（衬线极简）/
`whitey`（极简）/ `vue`（绿）/ `newsprint`（报纸）。
切换时同步 `<meta name="theme-color">`，移动端状态栏跟随。

**自定义主题**：对应参考实现的"把 CSS 丢进主题文件夹"。

| 能力 | 实现 |
|---|---|
| 导入 | 「主题 → 导入自定义主题…」选 `.css`，或直接把 `.css` 拖进窗口 |
| 生效方式 | CSS 文本注入 `<style id="lypora-custom-theme">`，叠在内置变量之上，只需覆盖想改的变量 |
| 持久化 | `localStorage`（`themes:custom`），重启仍在 |
| 切换/删除 | 主题菜单里以 `custom:<名称>` 列出，可单独删除 |
| 模板 | 菜单「自定义主题说明」把变量模板拷到剪贴板 |

排版数值（`02` §4 测量值）：

```
正文 16px / 行高 1.75
H1 2.0em  H2 1.6em  H3 1.32em  H4 1.13em  H5 1em  H6 0.92em
标题上间距 1.3em（H1）/ 1.15em（H2）/ 1.0em（H3），下间距 0.2-0.35em
内容最大宽度 860px
引用左边框 3px；代码块圆角 6px；表格边框 1px
空行非活动态行高压缩至 0.7（对齐参考实现紧凑观感）
```

### 4.5.1 布局：为什么改成「顶部菜单栏 + 左侧栏页签」

第一版把大纲放在**右侧独立面板**、把"打开文件"放进侧栏按钮区。这与参考实现不一致：

- 参考实现的侧栏在**左侧**，且**文件树和大纲是同一侧栏里的两个视图**，用图标切换（`Ctrl+Shift+1` 大纲 / `Ctrl+Shift+2` 文件树 / `Ctrl+Shift+L` 收起侧栏）；
- 打开文件走**菜单**（文件 → 打开 / 打开文件夹），不是侧栏按钮。

现在的结构：

```
┌───────────────────────────────────────────────┐
│ 菜单栏  文件 编辑 段落 格式 显示 主题 语言 帮助   │ ← menubar.ts（数据驱动）
├───────────────┬───────────────────────────────┤
│ 侧栏 (250px)  │  编辑区                        │
│ [大纲][文件树]│                                │
│ [最近]        │                                │
├───────────────┴───────────────────────────────┤
│ 状态栏  大纲 文件树        字数 行数 UTF-8 模式 │
└───────────────────────────────────────────────┘
```

关键实现点：

- **菜单是数据驱动的**：`buildMenus()` 每次打开时现取，所以勾选态（当前主题、侧栏是否展开、源码/专注/打字机是否开）永远准确，不需要任何"刷新菜单"的通道。
- **下拉层用 `fixed` 定位**挂到 `body`，避免被侧栏或编辑区的 `overflow` 裁切；窄屏会自动夹到视口内。
- **状态栏的两个切换按钮**（大纲/文件树）与菜单项、快捷键走同一个 `togglePane()`：已是当前视图则收起，否则切过去并展开——这是参考实现的手感。
- 移动端（≤860px）菜单栏变成可横向滑动的紧凑条：**功能入口一个不丢**，只是改变排布。

### 4.6 `i18n/` —— 多语言（0.5.0 新增）

**为什么不用 i18next / vue-i18n 之类**：需求只有"查表 + 插值 + 复数"，任何库的体积和复杂度都超过收益。
自研运行时 190 行、0 依赖，产物体积增加约 9KB（7 份词表全打进去，gzip 后约 4KB）。

**键集合的唯一真源是 `zh-CN.ts`。** 其余六份用编译期类型约束同一形状：

```ts
export type Dict = typeof zhCN            // 以中文词表反推结构
const DICTS: Record<LocaleId, Dict> = { 'zh-CN': zhCN, en, ja, ko, es, fr, de }
```

少一个键、多一个键、把 `{ one, other }` 写成裸字符串，`tsc` 当场报错（TS2719 / TS2322），
不需要等到运行时才发现。这条比任何 lint 规则都硬。

**扁平化查表**：模块加载时把嵌套词表压成一次 `Map<string, string | {one,other}>`，
键形如 `status.words`。`t()` 只做一次查表 + 一次正则替换，没有运行时递归。

| 导出 | 职责 |
|---|---|
| `t(key, params?)` | 查表 + `{name}` 插值；**查不到时返回键名本身**（漏翻在界面上直接可见，不静默变空） |
| `initI18n()` | 读偏好 → 解析 → 写 `<html lang>` 与 `data-lang`；必须在任何 `t()` 之前调用 |
| `setLocale(pref)` | 持久化到 `localStorage['lypora:locale']` + 通知订阅者 |
| `onLocaleChange(cb)` | 订阅语言变更，返回退订函数 |
| `applyStaticDom(root)` | 落地 `data-i18n` / `data-i18n-title` / `data-i18n-aria` 三类静态标记 |
| `LANGUAGES` / `localeName()` | 语言清单与母语名（菜单里**不翻译**语言名） |

**复数**：词表里写成 `{ one, other }`，`t()` 按 `params.n === 1` 选型。
中日韩无复数，但仍写两份相同文案——保持类型形状一致，否则 TS2719 会把整个 `DICTS` 判为不合规。
数值千分位由 `status.*` 的 `{value}` 占位符承载，`{n}` 只承担单复数判定，不出现在文案里
（否则英文 "1,050 word" 会在插值后又拼一次数字）。

**运行时切换为什么不会丢撤销历史**：切换语言不做 `location.reload()`，也不重建 `EditorState`。
唯一需要改的编辑器内文本是占位符，它挂在 CM6 的 `Compartment` 上：

```ts
export const placeholderComp = new Compartment()
export function setEditorPlaceholder(view) {
  view.dispatch({ effects: placeholderComp.reconfigure(placeholder(t('editor.placeholder'))) })
}
```

重配 Compartment 是一次普通事务，`history()` 不受影响，选区与滚动位置原样保留。

**静态 DOM 与动态 DOM 分开处理**：

- `index.html` 里写死的文案（侧栏页签、空态提示、状态栏按钮、移动端工具栏）在标签上加
  `data-i18n="键名"`，由 `applyStaticDom()` 一次性落地；语言变更时再跑一遍即可，不需要重建 DOM。
- 运行时生成的文案（toast、菜单、面板、状态栏数字）在 `main.ts` / `mobile.ts` 里直接 `t()`。
  `refreshLocaleUi()` 负责把它们全部重算一遍：`applyStaticDom()` → 菜单 `redraw()` →
  移动端 `refreshMobileLabels()` → 占位符 → 标题 / 字数 / 大纲 / 最近文件 / 状态栏勾选态。

**稳定标识替代文案做锚点**：所有靠"文字内容"定位的地方都换成了 `data-*` id，否则一换语言，
菜单和面板的查找逻辑就集体失效（这也是验收脚本能跨语言跑通的前提）：

| 位置 | 属性 | 例 |
|---|---|---|
| 顶级菜单按钮 | `data-menu` | `file` / `edit` / `language` |
| 菜单项 | `data-mi` | `file-export-html` / `lang-ja` |
| 面板分区 | `data-section` | `file`（原来是菜单标题文字） |
| 面板行 | `data-mi` | 同上 |

**跟随系统**：`resolveSystemLocale()` 逐项遍历 `navigator.languages`，`zh*` 一律落 `zh-CN`，
其余按主语言标签匹配；全不命中时走 `FALLBACK_CHAIN = ['en', 'zh-CN']`。
选过具体语言后不再跟随系统，回菜单选「跟随系统」恢复。

## 5. 数据流

```
用户按键 / IME
   ↓ Transaction
① 源文档字符串（唯一真源，落盘的就是它）
   ↓ 增量解析
② 语法树 SyntaxTree（只读）
   ↓ 装饰计算（依赖选区 + 视口）
③ DecorationSet（派生数据，可随时丢弃重算）
   ↓
DOM patch

旁路：
  ② → 大纲树（防抖 150ms）→ 侧栏
  ① → 字数统计（防抖随输入）→ 状态栏
  ① → IndexedDB（防抖 4s）→ 最近文件
```

**核心不变量：③ 永远是 ② + 选区 + 视口 的纯函数结果，不持有状态。**
这条保证了"源代码模式 = 关掉装饰层"这种实现零成本，也是 Markdown 往返无损的技术前提。

## 6. 构建与运行

```bash
# 1. 构建核心（产物在 core/dist）
cd core
npm install
npx tsc --noEmit        # 类型检查
npx vite build          # 生产构建

# 2. Windows 桌面版（开发）
cd ../desktop
npm install
npm start               # 开发运行（--dev 走 5183 热更）

# 3. Windows 便携版（可分发）★ 一条命令出包
cd ..
node tools/pack-win.mjs          # 产出 release/Lypora/Lypora.exe
node tools/pack-win.mjs --zip    # 额外产出 release/Lypora-0.7.1-win-x64.zip

#    自检（不用人工点，退出码即结论：0 全绿 / 1 加载失败 / 2 有控制台错误）
env -u ELECTRON_RUN_AS_NODE ./release/Lypora/Lypora.exe --selftest --shot=selftest.png

# 4. 浏览器 / PWA 预览
cd core
npx vite preview --port 4173
# 手机访问：把 dist 部署到任意 HTTPS 静态站点，用 Chrome 打开 → 添加到主屏

# 5. Android APK（需 JDK 21 + Android SDK 35，见 android/README.md）
node tools/build-android.mjs
# -> release/Lypora-0.7.1-android.apk

# 6. macOS / Linux（构建机可以是 Windows，原因与方法见 docs/06）
python tools/pack-mac.py   --zip .tmp-elec/electron-v33.4.11-darwin-arm64.zip --arch arm64
python tools/pack-mac.py   --zip .tmp-elec/electron-v33.4.11-darwin-x64.zip   --arch x64
python tools/pack-linux.py --zip .tmp-elec/electron-v33.4.11-linux-x64.zip
python tools/check-package.py     # 跨平台结构校验（不启动，只验包内事实）

# 6b. Linux 安装包（deb / rpm / AppImage）——封包工具是 ELF，只能在 Linux 上跑
python tools/linux-stage.py --zip .tmp-elec/electron-v33.4.11-linux-x64.zip --stage build/stage --deb
dpkg-deb --build --root-owner-group build/stage release/lypora_0.7.1_amd64.deb
sudo chown -R root:root build/stage && sudo chmod 4755 build/stage/opt/lypora/chrome-sandbox
rpmbuild -bb --define "_version 0.7.1" --define "_stage_root $PWD/build/stage" \
         --define "_topdir $PWD/build/rpm" packaging/lypora.spec
# 或者在 Windows 上只算树、让 CI 封包：git push origin v0.7.1（详见 docs/07）

# 7. 四套验收（前两套需先起 `vite preview --port 4173`，还要装 Playwright 的 Chromium）
node verify.mjs          # 15 步功能回归
node mobile-check.mjs    # 5 档视口触屏外壳
node i18n-check.mjs      # 151 键 × 7 语言 + 七语言浏览器实渲染
python tools/check-package.py    # macOS / Linux 包结构（不需要预览服务）
```

**便携包的目录约定**（`pack-win.mjs` 产出，可直接拷贝/U 盘分发）：

```
Lypora/
├── Lypora.exe                   ← 双击运行，图标/版本信息已写入
├── 使用说明.txt
├── *.dll / *.pak / locales/       ← Electron 运行时（原样拷贝）
└── resources/app/
    ├── main.js / preload.js       ← 主进程与桥
    ├── package.json
    └── web/                       ← 就是 core/dist（前端真源产物）
```

`main.js` 用 `resolveIndex()` 两级探测 `web/index.html` → `../core/dist/index.html`，
所以**同一份主进程代码既能在源码目录调试，也能在打包目录里跑**，不需要环境变量区分。
