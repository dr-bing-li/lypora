# 08 · 美化输出与卡片模板

> 版本：`0.11.0`　起点：`feature/card-export`（v0.8.2）　模板化：0.9.0 合并自 `Lypora-NEXT`；0.10.0 扩到 20 套模板 + 背景与装订；0.11.0 面板改整屏
> 目标：把「Markdown → 可直接发布的图文卡片（图片 / PDF）」做成 Lypora 的原生能力，
> 而不是让用户写完还要去第三方网站贴一遍。
> 模板引擎的内部机制（41 字段契约、编译器、校验白名单、离线条件）见 [docs/09](09-美化输出与模板引擎.md)。

> 原 `文件 → 美化输出` 与 `设置 → 语言`（降为二级）都已调整；手机底栏加第 7 个按钮。
> **0.11.0 只改形态不改契约**：面板从居中对话框改成铺满编辑区（菜单栏保留），
> 模板、19 项参数、`.lyt.json` 格式、分页与出图链路一个字都没动；新增的三条坑见 §4.5 的 18–20。
>
> 命名说明：界面上的功能名叫**「排版」**，文档标题与文件名沿用「美化输出」——为了不让
> 已有链接和交叉引用失效。代码里的标识符（`beautify-panel.ts`、`lypora:beautify:*`、
> `beautify-check.mjs`）一律不改，改名的只是用户可见文案。

## 1. 调研对象：md2card.cn/zh/editor

### 1.1 它是什么

一个纯浏览器端的 Markdown → 知识卡片工具。左侧写 Markdown，右侧实时出「一屏一张」的
卡片图，导出 PNG / SVG，或直接复制到剪贴板贴进小红书、公众号。

> 本节只记录"同类产品解决什么问题、怎么解决"，用来判断我们自己缺什么 —— 不是抄的依据。
> 卡片排版本身，用它比用我们强，理由见 `docs/10` §12.7。

抓取方式：`curl` 拿到 Next.js 的 HTML 骨架（页面是 CSR，正文全在 JS 里），再下载全部
46 个 chunk 做静态分析，最后用 Playwright + 系统 Edge 无头跑起来读真实 DOM 与截图。

### 1.2 页面结构

```
┌─ 顶栏：编辑 / 封面 / 文字转图片 / 主题商店 / 定价 / 博客 / 文卡网 ┊ 分享 · 导出 · 主题 · 登录 ─┐
├──────────────┬────────────────────────────────┬──────────────────────────┤
│ Markdown     │ 卡片预览区                     │ 设置面板                 │
│ 编辑器       │  · 卡片标题栏（主题名 / 上传 /  │  · 公众号模式 / API      │
│ + 格式工具栏 │    更多）                      │  · 分页：长图文/自动/横线 │
│ + 行号       │  · 卡片正文（实时渲染）         │  · 尺寸 w/h + 显示页码    │
│              │  · 卡片右侧竖排动作             │  · 高度超出隐藏 + 预设    │
│              │    （下载/图片/编辑/视频/上传） │  · 字体族 / 字号 / 行距    │
│              │  · 底部卡片翻页                │  · 光影 / 背景            │
│              │                                │  · 主题：系统/付费/自定义  │
└──────────────┴────────────────────────────────┴──────────────────────────┘
```

工具栏：标题、粗体、斜体、删除线、下划线、高亮、链接、图片、代码块、引用、无序列表、
有序列表、表格、分割线、插入空白行、AI、帮助、设置。

### 1.3 输出风格（核心）

主题在 JS 里的数据结构是：

```js
{ name, enName, id, thumbnail, className, code, css }
// 例：{ name:"复古打字机", enName:"Vintage Typewriter", id:"typewriter",
//       thumbnail:"/img/assets/img/demo/typewriter.webp",
//       className:"typewriter", code:"solarized-light", css:"..." }
```

24 套系统主题（`id` 沿用其原名，便于对照）：`apple-notes` 苹果备忘录、`instagram` Instagram 风格、
`coil-notebook` 线圈笔记本、`pop-art` 波普艺术、`bytedance` 字节范、`alibaba` 阿里橙、
`art-deco` 艺术装饰、`glassmorphism` 玻璃拟态、`warm` 温暖柔和、`minimal` 简约高级灰、
`minimalist` 极简黑白、`dreamy` 梦幻渐变、`nature` 清新自然、`xiaohongshu` 紫色小红书、
`notebook` 笔记本、`business` 商务简报、`japanese-magazine` 日本杂志、`darktech` 暗黑科技、
`typewriter` 复古打字机、`watercolor` 水彩艺术、`traditional-chinese` 中国传统、
`fairytale` 儿童童话、`cyberpunk` 赛博朋克、`meadow-dawn` 青野晨光。
另有「付费主题」「自定义主题」两栏，以及背景（无 / 纯色 / 渐变 / 纹理 / 图片 / 组合 /
自定义上传）与「光影」开关。

**机制结论：所谓「风格」就是一段 CSS + 一个 class。** 所有主题共用同一套 DOM 契约：

```
.card                      卡片容器
.card-cover                封面页
.card-cover-<className>    封面页的主题化样式
.card-<className>          内容页的主题化样式
.card-header / .card-header-left / .card-header-right
.card-content / .card-content-inner
.card-footer / .page       页脚与页码
--spacing                  尺度基准，所有 padding/font-size 走 calc(var(--spacing) * n)
```

纹理（纸张、网格、水彩）用 CSS 内联 SVG data-uri 实现，不加载外部图片。代码高亮由
shiki 提供，每个主题配一个 `code` 配色 id。渲染管线是 `remark/marked → HTML → DOM →
foreignObject/SVG → canvas → PNG`，`toDataURL`、`XMLSerializer`、`foreignObject` 都在
chunk 里，数学公式用 KaTeX、图表用 mermaid、HTML 过 DOMPurify。

### 1.4 交互与数据流

```
Markdown 源 ──(编辑/工具栏/AI)──► 解析器 ──► 卡片分页器 ──► 卡片 DOM ──► 截图 ──► PNG/SVG
                                     │            │                         └─► 剪贴板
                                     │            └─ 主题 CSS + 背景 + 字号
                                     └─ 代码高亮配色 / 公式 / 图表
```

分页三种：长图文（一页到底）、自动拆分（按渲染高度切）、横线拆分（`---` 处强制切）；
另可关掉分页做单张。导出是**按卡片分文件**（`md2card-<ts>-1.png`、`-2.png`…），点一次
「导出」直接下载，再用弹层给出备用下载链接。

### 1.5 服务端依赖

chunk 里出现的服务端痕迹只有三类：`获取分享数据失败`、`获取上传凭证失败`、
`获取扩容信息失败`，加一个「API」入口。**排版与出图 100% 在浏览器里完成，不请求后端。**

这条结论决定了后面能不能搬：能，因为它没有服务端黑盒。

## 2. 迁移到 Lypora 的评估

### 2.1 结论

**可以，而且契合度很高；但不能复用 Lypora 现有的"主题"概念，必须新建一层。**

| 维度 | 判断 | 依据 |
| --- | --- | --- |
| 架构契合 | ✅ 高 | 两边都是「CSS 驱动渲染 + 浏览器出像素」，Lypora 已有自研 `mdToHtml`，卡片排版只需要在它的输出上做顶层块切分 |
| 输出风格可移植 | ✅ 是 | 风格 = CSS + class 契约，纯客户端，无后端 |
| 主题系统能否复用 | ❌ 不能 | Lypora 的 6 套主题改的是 `--bg/--fg` 这套**编辑器**变量（作用在 `.cm-line`），卡片要的是纸张、边框、装饰、标题字体，两者混用会互相绑架：暗色界面主题会污染导出图 |
| 公式/代码 | ⚠️ 需额外处理 | KaTeX 的 HTML 只是骨架，离开 `katex.min.css` 会退化成平铺文字（`∫₀¹` 变 `∫01`）；截图时必须把 `KATEX_CSS` 一并内联 |
| 图片 | ⚠️ 需额外处理 | foreignObject 内不能有跨源资源，否则 canvas 被标记 tainted，`toDataURL` 直接抛 SecurityError |
| PDF | ✅ 可自研 | PDF 1.4 嵌 JPEG 是 DCTDecode 直通，60 行写入器即可，不必引 jsPDF |

### 2.2 不做的事

- 不做主题商店 / 付费主题 —— 与 Lypora「本地优先、零账号」的定位冲突。
  （v0.10.0 开始支持**本地上传背景图**，但它只存在模板 JSON 里、不上传、不同步，仍然没有账号与云端。）
- 不做视频合成（MediaRecorder 合成 mp4）—— 与「文档工具」无关，成本全是边缘情况。
- 不复制 md2card 的任何 CSS。**本项目所有模板都是自己写的**——思路可以借鉴，样式是自己画的，
  只借鉴了「模板 = 一份数据 + 固定 DOM 契约」这一工程结构。
- 反过来也要说清楚：**想要它那些现成的排版效果，请直接去用它。** 它主题更多、版式控制更细，
  做卡片这件事比我们专业得多（见 `docs/10` §12.7）。我们这里只解决"写东西时顺手出一张图"。

## 3. 实现

> v0.8.2 的第一版是「8 套风格 = 8 段手写 CSS」。0.9.0 合并 `Lypora-NEXT` 的模板引擎后，
> 重写为**「12 套模板 = 12 份数据 + 一个编译器」**，并新增 17 项可调参数与模板导入导出。
> **v0.10.0 再扩到 20 套**（补苹果备忘录 / Instagram / 线圈笔记本 / 波普艺术 / 艺术装饰 /
> 杂志跨栏 / 霓虹 / 手账），参数表增到 19 项，并加了两个新维度：**背景**（6 种内置底纹 + 本地
> 上传图片）与**装订**（线圈 / 票夹 / 订书钉）。
> 本章描述 0.10.0 的状态；第一版的踩坑保留在 §4.5，那些坑与模板化无关，现在仍然成立。

### 3.1 技术栈（沿用，无新增运行时依赖）

Vite 8 + TypeScript 7 + CodeMirror 6 + KaTeX；渲染全部走浏览器原生能力：
`XMLSerializer` / `foreignObject` / `canvas` / `Blob` / `ClipboardItem`。
**零新增 npm 依赖**（PDF 与 ZIP 写入器均为自研，共约 160 行）。模板引擎也是纯 TypeScript
字符串拼接：没有模板语言、没有求值、没有 CSS 框架——`compileTemplate()` 只吐 `--c-*` 变量块。

### 3.3 与 md2card 的功能对应（0.10.0）

| md2card | Lypora 0.10.0 | 差异 |
| --- | --- | --- |
| 24 套系统主题 | **20 套原创模板**：素纸/便签/杂志/暗夜/渐变海报/打字机/方格笔记/水墨/暖沙/极简黑白/钴蓝/林间 + 苹果备忘录/Instagram 风格/线圈笔记本/波普艺术/艺术装饰/杂志跨栏/霓虹/手账 | 0.9.0 时刻意做少（12 套）；0.10.0 按你点名的四款（苹果备忘录、Instagram、线圈笔记本、波普艺术）补齐到 20，另加 4 套补足「深色 / 大字 / 手账」三个缺口 |
| 自定义主题 / 付费主题 | 不做商店，但**模板可调可导入**（19 项 + `.lyt.json`） | 参数化替代模板包 |
| 长图文 / 自动拆分 / 横线拆分 / 单张 | `auto` / `rule` / `none` 三种 | 一致 |
| 尺寸 w/h 自定义 + 预设 | 4 种预设（竖版 3:4、方版 1:1、长竖 9:16、A4） | 先给固定预设，避免任意尺寸下排版失控 |
| 显示页码 / 高度超出隐藏 | 页码可开关；超出走长块按行二分拆分，拆不动才裁切并计数提示 | 比「静默裁掉」诚实 |
| 字体族 / 字号 / 行距 | **全部可调**：字体族 4 预设、字号 12–22、行高 1.4–2.2 | 由参数表 clamp 住，不会调到崩 |
| 背景：纯色/渐变/纹理/图片/自定义 | 颜色 4 项 + 8 种纹理 + **6 种底纹**（牛皮纸 / 横线本 / 方格 / 点阵 / 水彩 / 宣纸，`BG_PREVIEW` 与编译器共用同一份 CSS）+ **本地上传背景图** + 背景不透明度 0–100% | 底纹用 CSS 渐变生成（不落图片、缩放不糊、导出天然内联）；上传图只收 `data:image/*` base64，存模板 JSON 里，不上云 |
| 装订装饰 | **4 档**：无 / 线圈（圆孔 + 重复纵列）/ 票夹 / 订书钉 | md2card 无独立装订位，这是一层额外的「这是本子的一页」暗示 |
| 4 个强调位 + 折角/胶带/印章 | 强调位：无 / 顶栏 / 左边线 / 角标；另有三枚贴纸位 | 一致 |
| 导出 PNG（分卡多文件） | 单页直接 PNG，多页打 ZIP | 避免浏览器「阻止多个文件下载」 |
| 导出 SVG | 不做 | 卡片含位图与字体，SVG 交付价值低 |
| 复制到剪贴板 | `ClipboardItem` 复制当前页 | 一致 |
| 导出 PDF | 自研 PDF 写入器，一卡一页 | md2card 无（它只出图） |
| 视频合成 / 公众号模式 / 分享链接 / 开放 API | 不做 | 与本地工具定位冲突 |

### 3.4 数据流（Lypora 内）

```
CM6 doc ──mdToHtml()──► HTML ──DOMParser──► 顶层块数组
                                              │
                          ┌───────────────────┴───────────────────┐
                          │ paginate() 离屏卡片逐块实测 scrollHeight │
                          │  超了换页；单块超整页 → 按行二分再拆      │
                          └───────────────────┬───────────────────┘
                                              ▼
                                       CardPage[]（纯 HTML 字符串）
                                              │
              ┌───────────────────────────────┼───────────────────────────────┐
              ▼                               ▼                               ▼
      renderPagePreview()            renderPagesToPng()              renderPagesToPdf()
        （面板预览）                  （单页 PNG / 多页 ZIP）           （JPEG → 手写 PDF）
              └───────────────┬───────────────┴───────────────────────────────┘
                              ▼
                    saveBinary()：Electron 对话框 / Capacitor 分享 / 浏览器下载
```

模板只影响两处输入：测量容器与截图容器都注入**同一份** `stylesheetFor(template)`，
所以「调参数 → 页数变 → 出图变」是一条链路，不是两次渲染。

### 3.5 模板化的三条硬约束

1. **只能改变量**。`compileTemplate()` 的输出只有 `--c-*` 变量块；谁想改 `display` /
   `width` / `padding`，分页的测量基准立刻不可控。
2. **参数即数据**。面板不写死控件，遍历 `PARAM_SPECS`；加一套模板 = 加一条数据。
3. **校验按语法形态**。模板字符串会进 `<style>`，一个 `}` 就能改写整页，所以白名单是
   「允许的字符形态」，不是「能解析」。（细节见 docs/09 §3.4。）

## 4. 验证

### 4.1 一键验收

```bash
cd core
npm run build
npx vite preview --host 127.0.0.1 --port 4173 &   # 注意：build 会清空 dist，必须先停 preview

PAGE_URL=http://127.0.0.1:4173/index.html node verify.mjs         # 编辑器主链路回归
```

### 4.2 beautify-check 的硬指标

1. **交互**：一级菜单 `排版 → 打开排版面板` 能开面板，**20 套模板**按钮齐全，20s 内出预览，Esc 能关。
2. **模板逐个出图**：20 套全部出图，且采样后颜色数 > 8（防「白图假通过」）；
   模板按钮上的**三色小样**（纸 / 强调 / 墨）必须真的画出来，能一眼看出配色。
3. **参数链路**：改字号必须让**页数变化**（证明「参数 → 重排」真的通了，不是只换 CSS）。
4. **装饰链路（v0.10.0 重写）**：**同一字号**下 `texture=none` 截图 → 切 `grid` 截图 → 像素签名必须变，
   再切回 `none` 必须**回到基线**。后一步排除「差异来自重排而不是纹理」——0.9.0 的旧用例
   因为基线取自改字号之前，纹理完全没画出来也照样通过，是**假通过**（见 V56）。
5. **背景链路**：**6 种底纹逐个**都要与空背景产生可见差异（不只是「像素签名不同」——
   白纹画在白纸上签名也会变）；牛皮纸与横线本互不相同；换装订样式后像素有变化；
   上传一张自造图后缩略图出现且与内置底纹不同。
6. **模板进出**：导出 `.lyt.json`（`schema=3`，`decor` 含 `bg/bgImage/bgOpacity/binding`）
   → 再导入 → 出现在「我的模板」并成为当前模板。
7. **自定义命名（v0.10.0 新增）**：「存为我的模板」必须弹命名框、带默认名（`原名·改`）、
   重名自动加序号；改名后的模板能在画廊里找到。弹窗必须**点得到**（见 V57）。
8. **离线**：整场操作**零外部网络请求**（除本机 127.0.0.1 静态资源）。
9. **产物真实**：ZIP 解出来的图必须是 1080×1440（竖版 3:4 @2x）；PDF 头 `%PDF-1.4`、
   页数 == 卡片数、MediaBox `[0 0 405 540]`、`%%EOF` 存在。

### 4.5 必须知道的坑（踩过，第二次别再踩）

1. **blob URL 的 SVG 会污染 canvas**：`<img src="blob:...">` 画到 canvas 后
   `toDataURL` 抛 `SecurityError: Tainted canvases may not be exported`。
   必须用 `data:image/svg+xml;charset=utf-8,` + `encodeURIComponent`。
2. **KaTeX 不带 CSS 就是废的**：测量容器和截图 SVG 两处都要注入 `KATEX_CSS`，
   否则公式高度量不准、图里退化成一串平铺字符。
3. **拉不到的图片必须摘掉**：留在 SVG 里同样会让 canvas 变脏，整张卡报废。
4. **`vite build` 会清空 `dist`**：preview 在跑时构建会互相打架，先停服务再构建。
5. **Electron 里 `<a download>` 不可靠**：默认静默落下载目录，必须走
   `dialog.showSaveDialog` 的 IPC。
6. **Capacitor 写二进制**：`Filesystem.writeFile` 传 base64 且**不传 encoding**，
   传了 UTF8 图片会被写成替换字符。
7. **模板字符串会进 `<style>`**：不在校验层挡住 `}`、`<`、`@`、`url(`，一个手改的模板就能
   改写整页样式。校验层按字符形态白名单，不做「解析后信任」。
8. **改参数等于换页数**：只重绘 CSS 而不重跑 `paginate()`，会出现内容溢出或被裁掉；
   面板必须把「参数变更」当成「整份重排」的触发器（160ms 防抖）。
9. **`<input type="color">` 表达不了渐变**：编辑渐变模板的「纸张」会退化成纯色。
   不拦，但「恢复默认」要能一键救回。
10. **纹理线色要按「纸色」判，不能按「墨色」判**（0.10.0 修的 bug）。浅纸配深字是常态，
    拿 `ink` 亮度算线色会得到白线画白纸 —— 8 种纹理里 5 种完全看不见，用户看到的就是
    「纹理与装饰整组无效」。先 `gradientSolid(paper)` 取纸色实色再判亮度。详见 V56。
11. **面板里弹的模态框必须比面板高**（0.10.0）。`.ce-mask` 是 420，`.modal-mask` 原来 300，
    导致「存为我的模板」的命名框看得见、点不到，Playwright 报 `intercepts pointer events`。
    已把 `.modal-mask` 提到 460。详见 V57。
12. **flex 布局里 9:16 预览会把设置区顶出屏幕**（0.10.0）。竖图按 `aspect-ratio` 撑高时，
    预览区没有确定高度就会无限长。窄屏下必须给预览区 `flex: 0 0 auto; height: 34vh`，
    设置区 `flex: 1 1 auto; min-height: 0; overflow-y: auto`。对应手工用例 H33。
13. **后写的同特异性规则会静默顶掉媒体查询**（0.10.0 修上一条时踩到）。`@media (max-width:760px)`
    里的 `.ce-wide .ce-preview { height: 34vh }` 被文件末尾同特异性的 `.ce-wide .ce-preview
    { flex: 0 0 38% }` 覆盖，于是「给确定高度」实际没生效 —— 量出来是 239px（38% 的 flex-basis），
    不是 287px。**CSS 注释写的是意图，浏览器执行的是层叠结果**，改完必须量一次。
    修法：把桌面那条 38% 收进 `@media (min-width:761px)`。
14. **自动验收里的像素断言要控变量**。0.9.0 的「换纹理像素必变」用例，基线取自改字号之前，
    字号变化本身就改了像素 —— 纹理没画出来也通过。凡是「改 A 之后像素变了」，都要能排除 B。
15. **「枚举里有一项，CSS 与词表里没有」是最阴的一类空转**（0.10.0）。`BG_PRESETS` 里第六个写的是
    `wire`，而 `BG_PREVIEW`（CSS）与 `tpl.bg.*`（文案）里叫 `paper` —— 面板会照常生成那个按钮，
    点下去既没图案也没 tooltip 文案，用户看到的就是「这个底纹坏了」。三处必须一一对应，
    所以现在验收会遍历 DOM 里所有 `.ce-bg[data-bg]`，逐个要求与空背景有可见差异。
16. **「浅到量不出来」也算没效果**（0.10.0）。牛皮纸原来只有 alpha 0.055 的斜纹，白纸上几乎看不出，
    等于招牌写着牛皮纸、给的是白纸。现在最底层加了一层半透明牛皮色（0.58–0.62），
    白纸透出浅牛皮、牛皮纸模板透出深牛皮。
17. **细纹理的像素比对要先看分辨率够不够**（0.10.0）。点阵是 16px 网格上 1.35px 的点，
    把预览缩到 120×120 再比会把它平均成 0（「画了」和「没画」算出同一个数）。比对提到 240×240，
    顺手把点阵从 1.1px/alpha .11 提到 1.35px/alpha .17，让它在 2× 出图里真的看得见。
18. **面板从模态改成整屏后，顶边不能再写 `0`**（0.11.0）。`.ce-mask` 原来是
    `position: fixed; inset: 0`，铺满整个视口就因为它是模态。改成"铺满编辑区、保留菜单栏"以后，
    顶边必须让出菜单栏，而菜单栏高度是**运行时可变的**（手机上会折行、标签栏可能隐藏）。
    所以 `.ce-mask` 用 `inset: var(--ce-top, 0px) 0 0 0`，`--ce-top` 由 `open()` 现场量
    「菜单栏底边 + 可见标签栏高度」写进 `documentElement`。**别用 `100vh` 减固定数**：手机
    WebView 的 `100vh` 含地址栏，参数区底部的三个导出按钮会正好被推出屏外（H36）。
19. **面板内元素要跟着改成"填满"而不是"居中"**：模态时代 `.ce` 有 `border-radius` 和 `box-shadow`，
    整屏后这些会变成一圈奇怪的圆角边框；`.ce { width: 100%; height: 100%; border: 0;
    border-radius: 0; box-shadow: none }` 是必须的，否则验收里量出来的 `radius` 会是 12px。
20. **窄屏不能再靠 `flex-direction: row` 挤**：整屏后改成一列——预览 `flex: 0 0 42%`、
    参数区 `flex: 1 1 auto; overflow-y: auto`。这条与第 13 条同一个坑的延续：新写的
    `@media (max-width: 760px)` 规则必须确认没有被文件末尾的同特异性规则顶掉，改完量一次高度。
