# 08 · 卡片导出与输出风格

> 分支：`feature/card-export`　基线：`main@94415e3`（v0.8.2）
> 目标：把「Markdown → 可直接发布的图文卡片（图片 / PDF）」做成 Lypora 的原生能力，
> 而不是让用户写完还要去第三方网站贴一遍。

---

## 1. 调研对象：md2card.cn/zh/editor

### 1.1 它是什么

一个纯浏览器端的 Markdown → 知识卡片工具。左侧写 Markdown，右侧实时出「一屏一张」的
卡片图，导出 PNG / SVG，或直接复制到剪贴板贴进小红书、公众号。

抓取方式：`curl` 拿到 Next.js 的 HTML 骨架（页面是 CSR，正文全在 JS 里），再下载全部
46 个 chunk 做静态分析，最后用 Playwright + 系统 Edge 无头跑起来读真实 DOM 与截图。

### 1.2 页面结构

```
┌─ 顶栏：编辑 / 封面 / 文字转图片 / 主题商店 / 定价 / 博客 / 文卡网 ┊ 分享 · 导出 · 主题 · 登录 ─┐
├──────────────┬────────────────────────────────┬──────────────────────────┤
│ Markdown     │ 卡片预览区                     │ 设置面板                 │
│ 编辑器       │  · 卡片标题栏（主题名 / 上传 /  │  · 公众号模式 / API      │
│ + 格式工具栏 │    更多）                      │  · 分页：长图文/自动/横线 │
│ + 行号       │  · 卡片正文（实时渲染）         │  · 尺寸 w/h + 显示页码    │
│              │  · 卡片右侧竖排动作             │  · 高度超出隐藏 + 预设    │
│              │    （下载/图片/编辑/视频/上传） │  · 字体族 / 字号 / 行距    │
│              │  · 底部卡片翻页                │  · 光影 / 背景            │
│              │                                │  · 主题：系统/付费/自定义  │
└──────────────┴────────────────────────────────┴──────────────────────────┘
```

工具栏：标题、粗体、斜体、删除线、下划线、高亮、链接、图片、代码块、引用、无序列表、
有序列表、表格、分割线、插入空白行、AI、帮助、设置。

### 1.3 输出风格（核心）

主题在 JS 里的数据结构是：

```js
{ name, enName, id, thumbnail, className, code, css }
// 例：{ name:"复古打字机", enName:"Vintage Typewriter", id:"typewriter",
//       thumbnail:"/img/assets/img/demo/typewriter.webp",
//       className:"typewriter", code:"solarized-light", css:"..." }
```

24 套系统主题（`id` 原样抄录）：`apple-notes` 苹果备忘录、`instagram` Instagram 风格、
`coil-notebook` 线圈笔记本、`pop-art` 波普艺术、`bytedance` 字节范、`alibaba` 阿里橙、
`art-deco` 艺术装饰、`glassmorphism` 玻璃拟态、`warm` 温暖柔和、`minimal` 简约高级灰、
`minimalist` 极简黑白、`dreamy` 梦幻渐变、`nature` 清新自然、`xiaohongshu` 紫色小红书、
`notebook` 笔记本、`business` 商务简报、`japanese-magazine` 日本杂志、`darktech` 暗黑科技、
`typewriter` 复古打字机、`watercolor` 水彩艺术、`traditional-chinese` 中国传统、
`fairytale` 儿童童话、`cyberpunk` 赛博朋克、`meadow-dawn` 青野晨光。
另有「付费主题」「自定义主题」两栏，以及背景（无 / 纯色 / 渐变 / 纹理 / 图片 / 组合 /
自定义上传）与「光影」开关。

**机制结论：所谓「风格」就是一段 CSS + 一个 class。** 所有主题共用同一套 DOM 契约：

```
.card                      卡片容器
.card-cover                封面页
.card-cover-<className>    封面页的主题化样式
.card-<className>          内容页的主题化样式
.card-header / .card-header-left / .card-header-right
.card-content / .card-content-inner
.card-footer / .page       页脚与页码
--spacing                  尺度基准，所有 padding/font-size 走 calc(var(--spacing) * n)
```

纹理（纸张、网格、水彩）用 CSS 内联 SVG data-uri 实现，不加载外部图片。代码高亮由
shiki 提供，每个主题配一个 `code` 配色 id。渲染管线是 `remark/marked → HTML → DOM →
foreignObject/SVG → canvas → PNG`，`toDataURL`、`XMLSerializer`、`foreignObject` 都在
chunk 里，数学公式用 KaTeX、图表用 mermaid、HTML 过 DOMPurify。

### 1.4 交互与数据流

```
Markdown 源 ──(编辑/工具栏/AI)──► 解析器 ──► 卡片分页器 ──► 卡片 DOM ──► 截图 ──► PNG/SVG
                                     │            │                         └─► 剪贴板
                                     │            └─ 主题 CSS + 背景 + 字号
                                     └─ 代码高亮配色 / 公式 / 图表
```

分页三种：长图文（一页到底）、自动拆分（按渲染高度切）、横线拆分（`---` 处强制切）；
另可关掉分页做单张。导出是**按卡片分文件**（`md2card-<ts>-1.png`、`-2.png`…），点一次
「导出」直接下载，再用弹层给出备用下载链接。

### 1.5 服务端依赖

chunk 里出现的服务端痕迹只有三类：`获取分享数据失败`、`获取上传凭证失败`、
`获取扩容信息失败`，加一个「API」入口。**排版与出图 100% 在浏览器里完成，不请求后端。**

这条结论决定了后面能不能搬：能，因为它没有服务端黑盒。

## 2. 迁移到 Lypora 的评估

### 2.1 结论

**可以，而且契合度很高；但不能复用 Lypora 现有的"主题"概念，必须新建一层。**

| 维度 | 判断 | 依据 |
| --- | --- | --- |
| 架构契合 | ✅ 高 | 两边都是「CSS 驱动渲染 + 浏览器出像素」，Lypora 已有自研 `mdToHtml`，卡片排版只需要在它的输出上做顶层块切分 |
| 输出风格可移植 | ✅ 是 | 风格 = CSS + class 契约，纯客户端，无后端 |
| 主题系统能否复用 | ❌ 不能 | Lypora 的 6 套主题改的是 `--bg/--fg` 这套**编辑器**变量（作用在 `.cm-line`），卡片要的是纸张、边框、装饰、标题字体，两者混用会互相绑架：暗色界面主题会污染导出图 |
| 公式/代码 | ⚠️ 需额外处理 | KaTeX 的 HTML 只是骨架，离开 `katex.min.css` 会退化成平铺文字（`∫₀¹` 变 `∫01`）；截图时必须把 `KATEX_CSS` 一并内联 |
| 图片 | ⚠️ 需额外处理 | foreignObject 内不能有跨源资源，否则 canvas 被标记 tainted，`toDataURL` 直接抛 SecurityError |
| PDF | ✅ 可自研 | PDF 1.4 嵌 JPEG 是 DCTDecode 直通，60 行写入器即可，不必引 jsPDF |

### 2.2 不做的事

- 不做主题商店 / 付费主题 / 自定义上传背景 —— 与 Lypora「本地优先、零账号」的定位冲突。
- 不做视频合成（MediaRecorder 合成 mp4）—— 与「文档工具」无关，成本全是边缘情况。
- 不复制 md2card 的任何 CSS。**本项目 8 套风格全部原创**，只借鉴了「风格 = 一份 CSS +
  固定 DOM 契约」这一工程结构。

## 3. 实现

### 3.1 技术栈（沿用，无新增运行时依赖）

Vite 8 + TypeScript 7 + CodeMirror 6 + KaTeX；渲染全部走浏览器原生能力：
`XMLSerializer` / `foreignObject` / `canvas` / `Blob` / `ClipboardItem`。
**零新增 npm 依赖**（PDF 与 ZIP 写入器均为自研，共约 160 行）。

### 3.2 新增模块与职责

| 文件 | 职责 | 关键决策 |
| --- | --- | --- |
| `core/src/export/card-themes.ts` | 8 套输出风格 + 4 种尺寸预设 + 基础排版骨架 | 风格只允许覆盖变量，禁止改盒模型，保证分页与截图管线不随风格变化 |
| `core/src/export/card-layout.ts` | markdown → 卡片页数组：封面提取、分页、长块拆分 | **用真实 DOM 测量**，不估算；复用 `mdToHtml`，不写第二套解析器 |
| `core/src/export/card-capture.ts` | DOM → canvas → PNG / JPEG → PDF / ZIP | `foreignObject` 交给浏览器排版引擎画，与屏幕像素一致 |
| `core/src/export/save-binary.ts` | 二进制产物三平台落盘 | Electron 原生对话框 / Capacitor base64+分享 / `<a download>` |
| `core/src/ui/card-export-panel.ts` | 导出面板（预览 / 风格 / 尺寸 / 分页 / 三个出口） | 预览走的就是导出管线，不另画一套 |
| `core/card-check.mjs` | 自动化验收 | 见 §4 |
| `desktop/main.js` · `preload.js` | 新增 `file:save-binary` IPC | 导出产物必须让用户选位置，不静默写下载目录 |
| `core/src/io/native.ts` | 新增 `shareBinary` | Capacitor 只认 UTF-8 或 base64，二进制必须走 base64 且不传 encoding |
| `core/src/i18n/locales/*.ts` | 7 语言各补 23 个键 | 键集合以 zh-CN 为真源，少一个键 typecheck 就红 |

### 3.3 与 md2card 的功能对应

| md2card | Lypora 分支 | 差异 |
| --- | --- | --- |
| 24 套系统主题 | 8 套原创风格（素纸/便签/杂志/暗夜/渐变海报/打字机/方格笔记/水墨） | 刻意做少做精，风格之间是「纸张材质」维度而不是「换个色」 |
| 自定义主题 / 付费主题 | 不做 | 定位不同 |
| 长图文 / 自动拆分 / 横线拆分 / 单张 | `auto` / `rule` / `none` 三种 | 一致 |
| 尺寸 w/h 自定义 + 预设 | 4 种预设（竖版 3:4、方版 1:1、长竖 9:16、A4） | 先给固定预设，避免任意尺寸下排版失控 |
| 显示页码 / 高度超出隐藏 | 页码固定显示；超出走长块按行二分拆分，拆不动才裁切并计数提示 | 比「静默裁掉」诚实 |
| 字体族 / 字号 / 行距 | 不做（跟随风格） | 少一个失控维度 |
| 背景：纯色/渐变/纹理/图片/自定义 | 不做（风格自带纸感） | 同上 |
| 导出 PNG（分卡多文件） | 单页直接 PNG，多页打 ZIP | 避免浏览器「阻止多个文件下载」 |
| 导出 SVG | 不做 | 卡片含位图与字体，SVG 交付价值低 |
| 复制到剪贴板 | `ClipboardItem` 复制当前页 | 一致 |
| 导出 PDF | 自研 PDF 写入器，一卡一页 | md2card 无（它只出图） |
| 视频合成 / 公众号模式 / 分享链接 / 开放 API | 不做 | 与本地工具定位冲突 |

```
                                              │
              ┌───────────────────────────────┼───────────────────────────────┐
              ▼                               ▼                               ▼
      renderPagePreview()            renderPagesToPng()              renderPagesToPdf()
        （面板预览）                  （单页 PNG / 多页 ZIP）           （JPEG → 手写 PDF）
              └───────────────┬───────────────┴───────────────────────────────┘
                              ▼
                    saveBinary()：Electron 对话框 / Capacitor 分享 / 浏览器下载
```

## 4. 验证

### 4.1 一键验收

```bash
cd core
npm run build
npx vite preview --host 127.0.0.1 --port 4173 &   # 注意：build 会清空 dist，必须先停 preview
node card-check.mjs                                # 卡片导出专项
node i18n-check.mjs                                # 7 语言一致性
node export-check.mjs                              # 原导出链路回归
node verify.mjs                                    # 编辑器主链路回归
```

### 4.2 card-check 的硬指标

1. **交互**：菜单 `文件 → 导出卡片` 能开面板，20s 内出预览，Esc 能关。
2. **8 套风格逐个出图**：PNG 宽度 ≥ 200，且缩略采样后颜色数 > 8（防「白图假通过」）。
   同时翻到第 2 页截正文页，验证代码块/表格不崩。
3. **分页三模式**：`none` = 1 张内容卡（+封面）；`auto` 比 `none` 多出内容页；`rule` ≥ 2 页。
4. **产物真实**：导出 ZIP 解出来每张必须是 1080×1440（竖版 3:4 @2x）；
   PDF 头 `%PDF-1.4`、页数 == 卡片数、MediaBox `[0 0 405 540]`、`%%EOF` 存在。

### 4.4 必须知道的坑（踩过，第二次别再踩）

1. **blob URL 的 SVG 会污染 canvas**：`<img src="blob:...">` 画到 canvas 后
   `toDataURL` 抛 `SecurityError: Tainted canvases may not be exported`。
   必须用 `data:image/svg+xml;charset=utf-8,` + `encodeURIComponent`。
2. **KaTeX 不带 CSS 就是废的**：测量容器和截图 SVG 两处都要注入 `KATEX_CSS`，
   否则公式高度量不准、图里退化成一串平铺字符。
3. **拉不到的图片必须摘掉**：留在 SVG 里同样会让 canvas 变脏，整张卡报废。
4. **`vite build` 会清空 `dist`**：preview 在跑时构建会互相打架，先停服务再构建。
5. **Electron 里 `<a download>` 不可靠**：默认静默落下载目录，必须走
   `dialog.showSaveDialog` 的 IPC。
6. **Capacitor 写二进制**：`Filesystem.writeFile` 传 base64 且**不传 encoding**，
   传了 UTF8 图片会被写成替换字符。
