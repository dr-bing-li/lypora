# 艺术系主题是怎么做出来的 —— md2card「波普艺术」观察笔记与 Lypora 实现方案

> 版本：v0.13 预研 → **已在 v0.13.0 落地**（落地记录与偏差见 §11）→ **另外四套已在 v0.14.0 落地**（见 §12）　日期：2026-11-13
> 目的：回答三个问题——① md2card 那些"很有特色"的主题靠什么机制成立；② 波普艺术逐条怎么画出来的；
> ③ Lypora 现有模板模型要补什么，才能做出同类的观感，而不是照搬一套别人的样式。
> 结论先行：**不缺颜色，缺三种结构能力**（双面卡片、元素级排版、自由装饰层）。补齐这三点，
> 波普能做出 90%，剩下的 10% 属于"要不要支持旋转与手绘感"的取舍。

## 1. 一句话结论

md2card 的艺术感不是"复杂"，是**三层叠出来的错觉**：

1. **外层是一张有图案的纸**（黄底 + 点阵），靠 30px 内边距露出；
2. **中间是一块白卡**（2px 墨色描边 + 右下 10px、零模糊的硬阴影），压在纸上；
3. **卡上再做标题色块、斜纹分隔线、角上贴纸**。

另外四套（§3）换的不是这三层结构，而是"标题那一块怎么长"：药丸、渐变块、菱形金标、衬线轻字。
0.14.0 把这一路也做成了数据（§12）。

看起来是"边框 + 装饰"，实际是**阴影与留白伪造的厚度**。Lypora 现在是"一张纸、一层内容"，
所以无论怎么调 token，都不可能长出那个厚度——这是结构性差距，不是参数差距。

## 2. 波普艺术逐条解剖

### 2.1 卡片基底：黄纸 + 点阵

| 观察项 | 取值 | 说明 |
| --- | --- | --- |
| 纸色 | 亮黄（偏绿，Lypora 取 `#fde041`） | 整卡底色 |
| 图案 | 圆点，点色比纸深两档（`#d3b000`），单点直径约 3px | 内联 SVG，不是图片文件 |
| 平铺网格 | 24px（源图 20px 被放大） | 点更疏 |
| 起始偏移 | 12px，即半格 | 让点阵不跟内容边缘对齐 |
| 外圈宽度 | 30px | **由内边距造出来，不是描边** |
| 字体 | Comic Sans 系系统字体栈 | 未内嵌字体文件 |

**关键点：黄边不是 `border`，是 `padding`。** 边框只能是一条纯色；`padding` + `background-image`
才能让点阵一路铺到边上，这才是"印刷纸"的观感。`background-size` 故意放大到 24（原图 20）让点更稀，
`position` 偏移 12px 让它不跟卡片边缘对齐——这两个小偏移是"手工感"的来源。

### 2.2 白卡：硬阴影造厚度

| 观察项 | 取值 | 说明 |
| --- | --- | --- |
| 内卡底色 | 纯白 | 与外圈彩纸形成两个层面 |
| 描边 | 2px 墨色 | 硬边、无圆角 |
| 阴影偏移 | 右下各 10px | 30px 的边减去 10px，右下只剩 20px 彩纸 |
| 阴影模糊 | **0** | 「贴纸感」的定义特征 |
| 阴影不透明度 | 约 80% | Lypora 改成**不透明**（见 §11.2） |
| 内边距 | 12px | 文字到描边的距离 |
| 高度 | 撑满外层 | 分页时靠它撑满版面 |

`box-shadow` 的模糊半径是 **0**。带模糊的阴影是"浮起来"，0 模糊的实心位移阴影是"贴纸"——
波普/漫画/丝网印刷的通用语法。10px 位移配合 30px 的边，右下两侧的黄边只剩 20px，
视觉上立刻产生"这张白卡被斜着拍在黄纸上"的错觉。

### 2.3 截图实测：反推出来的参数与量到的像素逐条吻合

截图 545×778，卡片区取 y=620 行与 x=260 列扫色块游程：

| 位置 | 实测 | 反推参数 | 结论 |
| --- | --- | --- | --- |
| 左侧黄带 | x 31–60，**30px** | 外层内边距 30px（4px 网格 × 7.5） | 完全一致 |
| 白卡左边框 | x 61–62，**2px `#242430`** | 2px 墨色描边 | 一致（抗锯齿后偏暗） |
| 右侧偏移阴影 | x 441–450，**10px 深灰** | 偏移 10px、模糊 0 | 一致，且**模糊确实为 0** |
| 右侧剩余黄带 | x 451–470，**20px** | 带 30 − 阴影 10 | 阴影吃掉 10px，成立 |
| 点阵单点 | y 32–34，**3px `#cca800`** | 圆点半径 2、色 `#d3b000` | 一致 |
| 斜纹分隔线 | y 378–383，**6px 高** | 线高 6px（4px 网格 × 1.5） | 一致 |
| H2 蓝块 | y 409–475，**67px（两行）** | 青底 + 内边距 4×10 | 一致 |
| H3 珊瑚块 | y 497–529，**33px（一行）** | 珊瑚底 | 一致 |
| 思考框上边框 | y 690–691，**2px** | 2px 描边 | 一致 |

这条证据很重要：**说明主题的全部魔法都在那一段样式里，没有额外运行时**。所以只要 Lypora 的数据模型
能表达这些参数，那种观感就能还原出来；反过来说，表达不了的部分就是模型的缺口。

### 2.4 标题三级三样

| 级别 | 形态 | 参数 |
| --- | --- | --- |
| 一级 | 文字本体 + 粉色位移重影 + 45° 双色斜纹下划线 | 字号 32 / 字重 800 / 全大写 / 字距 1px / 重影偏移 3px（模糊 0）/ 下划线高 6px、条纹周期 20px |
| 二级 | 青色**实色块** + 轻微逆时针旋转 | 字号 24 / 内边距 4×10 / 旋转 −2° |
| 三级 | 珊瑚色块 + 4px 圆角 | 字号 20 / 内边距 4×10 |

三级标题的处理是**逐级换"形态"**而不是逐级缩字号：一级靠重影，二级靠斜色块，三级靠圆角色块。
这正是"艺术主题"和"排版主题"的分水岭——后者只会改粗细和大小。

### 2.5 分隔线：45° 双色条纹

| 观察项 | 取值 |
| --- | --- |
| 线高 | 6px（不是 1px 细线） |
| 圆角 | 3px |
| 图案 | 45° 双色斜纹，粉 / 墨交替 |
| 条纹周期 | 20px（各 10px） |
| 上下外边距 | 25px |

一条 `repeating-linear-gradient` 就把"分割线"升级成"装饰带"。同一个函数换个角度就是别套主题的虚线
（typewriter 用 90° 透明间隔做打字机虚线，art-deco 用 `linear-gradient(90deg, transparent, gold, transparent)` 做金线渐隐）。

### 2.6 引用：粗竖线 + 斜体 + 浅底（浅底其实失效了）

| 观察项 | 取值 | 结果 |
| --- | --- | --- |
| 左侧竖线 | 8px 粉色 | 生效 |
| 字重 / 字形 | 600 + 斜体 | 生效 |
| 底色 | 主观想用 10% 粉 | **未生效**：拼 `rgb()` 用的那个变量全文"用了 1 次、声明 0 次"，整条声明被丢弃 |
| 圆角 | 右上 / 右下 8px | 生效 |

那个用来拼 `rgb()` 的变量 **用了 1 次、声明 0 次**（表格斑马行是同一套手法、同样的结果）。
`rgb()` 里套一个不存在的变量 = 无效值，整条声明被丢弃——所以线上波普的引用块**没有浅粉底**，
表格**没有斑马纹**。这条不是要嘲笑它，而是给 Lypora 一条反对意见：**裸 CSS 字符串没有校验**，
写错了不会报错、不会崩，只是"某天有个效果不见了"。我们用数据模型 + 生成器，这类错误在类型层就被拦住。

### 2.7 角饰与徽标：伪元素塞 SVG

| 观察项 | 取值 | 说明 |
| --- | --- | --- |
| 载体 | 两个伪元素盒子 | 右上 80×80；另一个铺满整卡 |
| 图形 | 内联 SVG | 右上气泡一枚 + 五角星三枚 |
| 出血 | −20px、105% 这类负/越界偏移 | 星星压在纸边外，"贴歪了"的手工感 |
| 层级 | 高于正文 | 贴纸可以压字 |

三点值得借鉴：

1. 贴纸是 **SVG data URI**，不是图片文件——离线可用、导出天然内联、缩放不糊、包体零增长。
2. 位置用 `-20px`、`105%` 这种**故意出血**的偏移，让星星压在纸边外，像"贴歪了"。
3. 数量受限于伪元素个数——想放 5 枚就得再加 DOM。/ 这是它这套做法的天花板，我们不必继承。

### 2.8 列表与表格

| 元素 | 形态 | 参数 |
| --- | --- | --- |
| 无序 | `★` 字符作项目符号 | 18px 粉色 |
| 有序 | 圆形序号徽标 | 25×25 / 圆形 / 粉底白字 / 2px 墨边；序号取自 DOM 上的属性 |
| 表格 | 圆角描边框 + 偏移阴影 | 3px 墨边 / 8px 圆角 / 阴影右 5px 下 5px |

`attr(data-index)` 说明它的渲染器会给每个 `<li>` 写 `data-index`——**这是渲染器与主题之间的隐式契约**。
我们不必跟着走这条：Lypora 的 `cjk` 项目符号已经在用 `counter(list-item)`（Chromium 预定义计数器），
圆形序号照样能画，**可以完全不改渲染器**：

```css
.ly-card[data-listno="circle"] .ly-body ol > li::before {
  content: counter(list-item);
  width: 1.55em; height: 1.55em; border-radius: 50%;
  background: var(--c-accent); color: var(--c-on-accent);
  border: 2px solid var(--c-ink); text-align: center;
}
```

## 4. Lypora 现有模型（schema 4）的能力边界

现在一套模板 40 来个字段、0 行 CSS，编译成 `--c-*` 变量 + `[data-*]` 选择器。已有的：

- 色彩 13 个 token、度量 8 项、纹理 9 种、底纹 8 种、强调位 4 种、角处理 3 种、装订 3 种、
  印章 4 预设、引用框 5 式、项目符号 6 式、标题装饰 5 式、外边框 5 式。

对照波普需要的，逐条列缺口：

| 波普的手法 | 参照方向里的做法（观察值） | Lypora 现在 | 判定 |
| --- | --- | --- | --- |
| 黄色带 + 点阵 | 卡片 `padding:30px` + `background-image` 点阵 | `--c-pad-x` 是**内容**留白，`.ly-inner` 只有 padding、无背景无边 | **缺：外圈带** |
| 白卡厚度 | 内容层白底 + 2px 边 + 10px 硬阴影 | `--c-shadow` 存在（`box-shadow: var(--c-shadow)`），但作用在**整张卡**上，没有内面板 | **缺：内面板** |
| 三级标题三种形态 | h1/h2/h3 各自独立规则 | `decor.title` 5 式，只对 h1/h2 同时生效 | **缺：逐级独立** |
| 斜纹 hr | 自定义 `hr` | 无 hr 装饰（只有 `--c-rule` 1px 线） | **缺：分隔线样式** |
| 星 / POP 徽标 | 伪元素 + SVG | 印章 1 枚（4 预设），位置 4 角 | **缺：多枚任意贴纸** |
| 圆形序号 | `attr(data-index)` + 圆形徽标 | 无序符号 6 种；有序列表无样式 | **缺：有序样式 + 渲染契约** |
| 表格/代码/图片外框 | 每套主题定制（阴影、描边、圆角） | 只有基础样式 + token | **缺：外框风格** |
| 四套配色 | 同 class 子类只覆盖变量 | 一套模板一套色 | **缺：配色变体** |

## 5. 为什么"照搬一套样式"不是答案

四条硬理由，任何一条都够否掉：

1. **参数面板会失效。** 面板调的是 token，用户把 `paper` 从黄改成绿，CSS 里写死的 `#fde041`
   不跟着变——用户会认为"这个模板改不动"，这正是 v0.11.2 报的那类问题的翻版。
2. **跨平台要渲染一致。** 我们有三套运行时：Electron（Chromium）、Edge `--app`、Android WebView。
   裸 CSS 里只要用了 `clip-path`、`mix-blend-mode`、`backdrop-filter`，老 WebView 直接白屏，
   而模板包里没有任何东西能表达"我需要哪个引擎版本"。
3. **分页会被打破。** `paginate()` 靠"量真实 DOM 高度 → 切块"工作。任意 CSS 可以造出
   `position: absolute`、负 margin、`transform: scale` —— 量出来的高度和画出来的不一致，
   结果是内容被切在半个色块里。md2card 是固定 1080×1440 画布 + 溢出裁切，没有这个约束，
   我们的约束比它严。
4. **没有校验的错误是静默的。** §2.6 那个「拼 `rgb()` 的变量从未声明」就是活证据：写错了不报错，
   只是某天"某个效果不见了"。数据模型有 TS 类型 + `normalizeTemplate()` 白名单 + 现值夹取，
   这类错误进不了库。

所以路线是：**把这些手法翻译成"可校验的数据 + 一套固定生成器"**，模板仍然 0 行 CSS。

## 6. 方案：schema 5「艺术层」

新增 5 组字段（其余全部沿用）。原则：**每组字段都能被面板映射成一个控件，都能被 `normalizeTemplate()`
夹取，都只产出 CSS 变量，不产出任意 CSS**。

### 6.1 数据结构

```ts
// 1) 双面卡片：外圈带 + 内面板
interface PanelSpec {
  band: number          // 外圈宽度 px（0 = 单面，等价于旧行为）
  bandInk: string       // 带上的图案色（点/纹），'auto' = 由 rule 混合出来
  bg: string            // 内面板底色，'paper' = 跟随 tokens.paper
  border: number        // 面板描边 px
  borderColor: string
  radius: number
  shadow: string        // 位移与颜色，如 '10px 10px 0 <ink>'；支持 'none'
  pad: number           // 面板内边距 px（替换原 padX/padTop/padBottom 的语义）
}

// 2) 逐级标题：每级一套形态
interface HeadSpec {
  bg: string            // 'none' 表示不铺底
  fg: string            // 'inherit'
  padX: number; padY: number
  radius: number
  rotate: number        // -3..3，试做；0 = 不转
  shadow: string        // 位移重影：'3px 3px 0 #ff2e63' 或 'none'
  caps: boolean         // text-transform: uppercase
  tracking: number      // letter-spacing px
  italic: boolean
  align: 'start' | 'center'
  inline: boolean       // true → display:table 收窄到内容宽（色块只包字）
  rule: 'none' | 'solid' | 'stripe'    // 标题下的线
}
interface HeadingsSpec { h1: HeadSpec; h2: HeadSpec; h3: HeadSpec; h4: HeadSpec }

// 3) 分隔线
interface RuleSpec {
  style: 'none' | 'solid' | 'dashed' | 'stripe' | 'tape'
  height: number
  color: string
  color2: string
  angle: number         // stripe/tape 用
}

// 4) 角饰贴纸（数组，最多 6 枚）
interface OrnamentSpec {
  shape: 'star5' | 'star4' | 'burst' | 'badge' | 'blob'
  text: string          // 仅 badge/blob 用，≤6 字符
  pos: 'tl' | 'tr' | 'bl' | 'br'
  size: number
  rotate: number
  fill: string
  stroke: string
  bleed: number         // 出血 px，负偏移多少（0..40）
}

// 5) 支撑面：表格 / 代码 / 图片
interface SurfaceSpec {
  table: 'flat' | 'boxed' | 'pop'
  code: 'flat' | 'boxed' | 'pop'
  image: 'plain' | 'framed' | 'taped'
}
```

外加两个 token：`panelBg`（面板色，白卡用）与 `patternInk`（黄底上的点色 `#d3b000`）。
现在只有 13 个 token，加这两个正好补上"带上的图案"和"面板"这两个色位。

### 6.2 编译产物：只出变量 + 固定选择器

```css
.ly-card { padding: var(--c-band, 0); }
.ly-card .ly-inner {
  background: var(--c-panel-bg, transparent);
  border: var(--c-panel-border, 0) solid var(--c-panel-border-color, transparent);

  border-radius: var(--c-panel-radius, 0);
  padding: var(--c-pad-top) var(--c-pad-x) var(--c-pad-bottom);  /* 面板内边距 */
}
.ly-body h2 {
  background: var(--h2-bg, transparent); color: var(--h2-fg, inherit);
  padding: var(--h2-pad-y, 0) var(--h2-pad-x, 0);

  box-shadow: var(--h2-shadow, none);
```

**不改盒模型的地方**：`--c-band` 只加外层 padding，`.ly-inner` 仍是 flex 列，`paginate()` 量的还是
同一棵树，只是内层高度变小了——量一次即准。这条守住了现有架构不变量（模板不改盒模型，

### 6.3 贴纸用 DOM，不用伪元素

```ts
function ornHtml(tpl): string {
  return tpl.decor.ornaments.map(o =>
    `<i class="ly-orn" data-shape="${o.shape}" data-pos="${o.pos}" ` +
    `style="--o-size:${o.size}px;--o-rot:${o.rotate}deg;--o-fill:${o.fill};` +
    `--o-stroke:${o.stroke};--o-bleed:${o.bleed}px">${glyph(o)}</i>`).join('')
}
```

内联 SVG（不是 data URI）——好处是颜色、旋转、大小都走变量，导出时 `foreignObject` 照样画得出来
（我们的捕获器就是浏览器自己渲染，伪元素、渐变、SVG 全都在，这点比 html2canvas 省事）。
为什么不用伪元素：`.ly-card::before` 已被纹理占用、`::after` 被强调位占用，且伪元素最多 2 个。

### 6.4 渲染器要不要动

**不用动。** 圆形序号用 `counter(list-item)`（见 §2.8），不需要 `data-index`。
唯一需要确认的是 `<ol start="n">` 的起始号——`counter(list-item)` 会跟随 `start` 属性，
所以从 3 开始编号也正确。这条比 md2card 的做法省一处改动。

### 6.5 参数面板长什么样

新增 3 组：

| 分组 | 控件 |
| --- | --- |
| 面板（新） | 带宽度滑块 0–40 · 面板底色 · 描边粗细 0–4 · 阴影预设（无/贴纸/浮起）· 内边距 8–28 |
| 标题形态（新，逐级折叠） | 每级：底色 · 文字色 · 内边距 · 圆角 · 字距 · 大写 · 斜体 · 居中 · 收窄 · 下划线样式 |
| 装饰（扩） | 分隔线样式 5 选 1 + 双色 + 角度 · 贴纸（形状/位置/大小/旋转/颜色，可加可删） |

### 6.6 要不要留 raw CSS 逃生舱

**建议：不做。** 理由见 §5 四条。若将来确实要给"我的模板"作者放开，最低限度的沙箱是：

```ts
sanitizeCss(css)  // 丢掉 @import / url(http…) / position:fixed / expression( / behavior /
                  // 并把顶层选择器强制前缀为 [data-tpl="<id>"]（不做这个就会污染整个 App）
```

即使做了，也只能用于"我的模板"，不能进 `.zip` 样式包分发——否则第三方样式包能在我们所有页面里
自由布局，一条 CSS 就能把编辑器盖住。

### 验收断言（全部量"现象"，不量中间量）

| 断言 | 判据 |
| --- | --- |
| 带宽度真的存在 | 选 popart 后取预览第 1 行像素：x=6 必须 ≈ `#fde041`；把 band 从 30 改 0，面板左边界位移 ≥ 25px |
| 面板是白的且有描边 | 沿 y 中线扫：白色游程两侧各有一段 2px 深色（`#252a34` ±12） |
| 硬阴影是 0 模糊 | 面板右侧 10px 区域全部为深色（标准差 < 8，若有模糊则边缘会是渐变） |
| 三级标题三种形态 | 采样 h2 行左侧外 6px = 蓝（±10）；h3 = 珊瑚（±10）；h1 下方 6px 内有粉色/深色交替（斜纹周期 20px） |
| hr 是斜纹 | 沿 hr 中线上每 2px 采样，20px 内必须出现 ≥2 次双色交替 |
| 贴纸画出来了 | 左上 80×80 区域内 `#ff2e63` 像素数 > 150；右上区域 `#51bafa` > 150 |
| 有序序号 | `<ol>` 第 2 项前 28px 内有 ≥60 个 accent 色像素（圆形徽标） |
| 变体只换色 | 切 mint → 纸色变、面板边框宽与 band 宽度**不变**（diff 区域只落在背景上） |
| 分页不被破坏 | 同一文档在 band=0 与 band=30 下页数差 ≤ 1，且每页 `.ly-body` 溢出 = 0 |
| 四路导出都保留 | PNG / PDF / 复制 / zip 样式包往返后，band 宽度与阴影offset 不变（zip 里 `schema: 5`） |

### P1

- `surface` 三态推广到 8 套老模板（news / magazine / chalk 最受益）；
- `variants` 给现有 6 套彩色模板各配 2 个变体；
- 面板里加"从当前模板复制配色"。

### P2（可选，看用得上不上）

- 标题 `rotate`：视觉重叠风险。`transform` 不改布局高度，所以分页不会错，但 **2° 会让 540px 宽的
  色块上下各溢出约 9px**，在页边界上会被 `overflow: hidden` 切掉。要开就得同时给 `.ly-body`
  加上下各 10px 的补偿内边距，或把角度限制在 ±1.5°。
- `burst`/`blob` 贴纸、贴纸自定义上传；
- 手绘描边（SVG `filter: turbulence`）——Android WebView 性能会掉，先不做。

## 9. 风险与明确不做的事

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 字体：`Comic Sans MS` 在 Android WebView 没有 | 波普的"卡通感"退化为系统无衬线 | 中文本来就没有 Comic Sans，图形感靠色块+描边+斜纹，字体只是加成；模板里写清 fallback，并在面板提示"艺术字体不跨平台" |
| 硬阴影在 PDF 里被光栅化 | PDF 是 405×540 pt 的位图页 | 已确认：PDF 走 canvas 渲染，阴影没有矢量保真问题，但打印分辨率下 10px 阴影会显得笨重——P1 给 PDF 单独降一档 |
| `display: table` 收窄色块 | 在 flex 容器里可能被拉伸 | 用 `align-self: flex-start` 兜底；`inline` 开关只有色块类标题需要 |
| 贴纸压在文字上 | 长标题 + 右上徽标重叠 | 贴纸层 `pointer-events: none`；面板给"出血量"滑块，默认 16px；`beautify-check` 加"贴纸与文字包围盒不相交"断言 |
| 变体把对比度改坏 | 浅色纸上白字 | `normalizeTemplate()` 对变体做与主模板相同的对比度检查（复用 `ui-check` 的亮度公式） |

**明确不做**：

1. 不引入任意 CSS（§5）；
2. 不做 `position: absolute` 的自由排版（分页会失效）；
3. 不把 md2card 的 CSS 文件收进仓库或样式包（许可证 + 可维护性）；
4. 不做"主题商店"式的远端拉取（离线优先是我们现在的卖点）。

## 10. 一句话回答"能不能拿到同样的效果"

能。波普那套视觉里，**没有任何一项技术是 Lypora 现有渲染管线做不到的**——我们的捕获器是
`foreignObject`（浏览器自己画，伪元素/渐变/内联 SVG 全保真），模板编译是数据→变量，
加"带 + 面板 + 逐级标题 + 分隔线 + 贴纸"五组字段就够。真正的工作量不在渲染，在
**参数表、面板控件、以及 10 条"量现象"的验收断言**——这三样是让它"能改、能验、不静默失败"的东西。

确认后按 §8 的 P0 六步走，预计改动 5 个源文件 + 1 个验收脚本，新增 1 套模板 + 3 个配色变体。

### 11.3 顺带修掉的三个真 bug

1. **整张卡片渲染失败**：`compile.ts` 里一句 CSS 注释写了 `ol 的 start 属性` 的尖括号形式，
   而 `card-capture.ts` 会把整份样式表内联进 SVG 的 `<style>` —— XML 解析器把 `<` 当标签开头，
   报 `Unexpected token inside qualified name`，预览与导出**一起**变空白。根治办法是给
   `<style>` 加 CDATA（`]]>` 按规范切段），这样以后任何 CSS 注释都不会再炸。
2. **缩略图内容溢出 21px**：缩略图卡的 `--c-band-k` 只压了带、没压面板内边距，12px 内边距在
   170px 卡上等于 7%。新增 `--c-pad-k` 并在 `panelVars()` 里写成
   `calc(<pad>px * var(--c-pad-k, 1))`（模板侧默认 1，28 套老模板分毫不动）。
3. **数值列右移 30px**：给"可为空"的颜色加了 `∅` 清除键后，它被追加在 hex 码位之后，
   于是"有清除键的行"整列左移 22+8px，`ui-check` 的 `value-column-align` 立刻报警。
   改成 `色板 → ∅ → 码位`（码位永远最右）；同时把 `.ce-sub` / `.ce-orn-item` 的横向内边距

## 12. 落地记录（v0.14.0，2026-11-13）：另外四个方向

§3 那张「同一元素四种写法」的观察表，在 0.14.0 逐行变成了数据。**一句话：灵感来自 md2card 另外四套
免费样式（§3 观察到的四种写法），落成了四套内置模板，全部只用 schema 6 的字段表达 —— 思路是借鉴的，
实现是从我们自己的 schema 里长出来的，仓库里没有对方一行样式。**

### 12.1 观察 → 字段：一张一一对应的表

| §3 的观察 | 落成的模板 | 用到的字段（全部 0.14.0 新增或扩展） |
| --- | --- | --- |
| 橙金渐变胶囊，居中，宽度收到文字 | `pillorange` 橙光胶囊 | `h2.bg` = `linear-gradient(135deg,…)`、`h2.radius/radiusAlt` = 30/30、`h2.elev` = soft、`h2.inline` = true、`h2.align` = center |
| 蓝青渐变，四角不对称圆角 8/24/8/24 | `cyanflow` 青蓝流线 | `h2.radius` = 8、`h2.radiusAlt` = 24 → 编译成 `border-radius: 8px 24px 8px 24px` |
| 不铺底，只描金 + 加字距 + 左侧竖线 | `deco` 黑金菱纹 | `h1.caps/track` = true/3、`h2.fg` = 金、`h2.mark` = diamond + `markColor`、`rule.style` = fade、`texture` = lattice、`topBar` |
| 居中斜体小字，靠"轻"制造年代感 | `typograph` 米纸铅字 | `h2.italic` = true、`h2.weight` = 400、`h2.align` = center、`rule.style` = dot、`panel` = 12/1/2/float |
| 分隔线换图案 | 四套各用一式 | `rule.style` 新增 `fade`（两端透明、中间实色）与 `dot`（10px 周期） |
| 顶部色条（四套都有） | 四套各一个色对 | `decor.topBar = {height, from, to}` → `--c-topbar-h/--c-topbar-bg` + `[data-topbar]` |
| 标题下划线换成"短条" | `pillorange` 的 h1 | `h1.rule` = bar（46×4px 实心短条，不占行高） |

**为什么不是"再加 4 套 CSS"**：这四套一共动了 9 个字段、0 行 CSS。模板仍然是纯数据，
`compileTemplate()` 出变量、`CARD_BASE_CSS` 出骨架，四套模板之间的差别全在 `d:` 里那几十行数值。
反过来说，如果给每套写一段 CSS，这四套就会变成四段不可复用的字符串 —— 那正是 §5 拒绝的路。

### 12.5 实施中踩的四个坑（写下来省得下次再踩）

1. **id 撞车**：新模板一开始起名 `artdeco`，而 0.10.0 的第 17 套「鎏金几何」就叫这个 ——
   于是 `builtinById('artdeco')` 返回了老那套，探针量到的 `tex: halo / quote: quad` 全是老模板的值。
   现在叫 `deco`。**加模板前先 `grep` 一遍 id**。
2. **`'0'` 是 truthy**：下拉的 `value` 永远是字符串，写回时 `if (v)` 放过了 `'0'`，于是"字重：继承"
   会真的产出 `font-weight: 0`（标题变隐形）。`ParamSpec.numeric` 就是为这个加的。
3. **缩略图是静态样例**：`renderGallery()` 只在换模板时重建，所以改参数后缩略图**不会变**。
   想验证"控件点了有没有用"只能看落盘数据 + `.ce-img` 像素；量缩略图会得出"所有改动都无效"的假结论。
4. **色块判定必须带高度**：一条 1px 的浅色分隔线也是"有色横带"，宽度可以盖过标题色块 ——
   胶囊第一版因此量到 680px 的分隔线，取 84.9% 险过 85% 的阈值（真实值 32%）。
   现在先按"连续行 ≥12 行"拼块，再在块内取最宽行；高度另用竖带法量（块里压着字，
   逐行连续色段被字切碎，69px 的胶囊会被量成 18 行）。

### 12.7 致谢与推荐（写给人看的，不是写给法务看的）

上面几节全是"我们怎么做到的"，容易让人以为重点在"我们也能"。把话说直白一点：

- **这四个方向的功劳是 md2card 的。** 是它先把"卡片标题可以是一块图形""分隔线可以是一串点"
  这些事做出来、做成产品，我们才有得借鉴。观察别人的成品、把设计意图翻译成自己的数据模型，
  是正常的工程学习；假装是自己发明的，那才是问题。
- **做卡片这件事，md2card 比我们专业得多。** 主题更多、版式控制更细、导出选项更全，
  整个产品就是围着"把一段 Markdown 排成好看的卡"设计的。Lypora 是个 Markdown 编辑器，
  卡片刻画只是它顺手带上的一小块。
- **如果你要的就是好看的卡片排版，请直接去用 [md2card](https://md2card.cn/zh/editor)。**
  我们这里的四套模板只解决一个很窄的问题：正在写东西，想配一张图，不想为了这张图切出去。
  它不替代 md2card，也不打算替代。

这条同样适用于 0.13.0 的「波普撞印」：那是照着波普艺术这个**通用艺术流派**做的，
但它当初确实是看了 md2card 的波普主题之后才决定做的，功劳一样要记在人家头上。
