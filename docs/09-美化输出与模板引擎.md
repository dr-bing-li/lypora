## 1. 这一层解决什么问题

v0.8.2 的输出能力是「8 套风格 = 8 段手写 CSS」。三个问题在真实使用里立刻显形：

1. 用户**没法调**。想改字号，得会写 CSS 并找到对应选择器。
2. 加模板要**重抄一遍**排版规则，抄漏一处就是两套模板行为不一致。
3. 分页与截图依赖 CSS 的测量基准，模板一多，基准就漂。

0.9.0 的答案是：**模板 = 一份 JSON + 一个编译器**。

```ts
interface CardTemplate {
  schema: 3                                                          // 2 → 3（0.10.0 加背景/装订）
  id, name, enName, dark?
  tokens:  { paper, ink, muted, faint, accent, onAccent, rule,
             codeBg, codeInk, quoteBg, quoteRule, mark, shadow }     // 13 个颜色/底色
  metrics: { padX, padTop, padBottom, fontSize, lineHeight,
             radius, titleSize, headRule, pageNo, brand }            // 10 个度量与开关
  decor:   { texture, accent, corner, tape, stamp, cover,
             binding, bg, bgImage, bgOpacity }                       // 10 个装饰位
  code:    { com, str, num, kw, fn }                                  // 5 个高亮色
  font:    { body, head, mono }                                       // 3 个字体栈
}
```

41 个字段，全部可序列化、可校验、可导入导出。

`schema` 从 2 升到 3 **不是破坏性变更**：`normalizeTemplate()` 对缺字段一律回落默认值
（`binding: 'none'` / `bg: 'none'` / `bgImage: ''` / `bgOpacity: 100`），所以 0.9.0 导出的
`.lyt.json` 和旧 localStorage 里的模板照旧能读进来。

## 2. 分层与职责边界

```
┌─────────────────────────────────────────────────────────────┐
│  外壳层：Electron（desktop/）· Capacitor（core/android/）· Web/PWA │
├─────────────────────────────────────────────────────────────┤
│  界面层：menubar · beautify-panel · outline · statusbar        │
├─────────────────────────────────────────────────────────────┤
│  能力层：io/（文件、图片、原生桥）· save-binary（二进制落盘）      │
├─────────────────────────────────────────────────────────────┤
│  输出层：template（模板）→ card-layout（分页）→ card-capture（光栅化）│
├─────────────────────────────────────────────────────────────┤
│  编辑器层：CM6 + live-preview + 高亮 + KaTeX + mdToHtml          │
└─────────────────────────────────────────────────────────────┘
```

**关键边界：输出层绝不反向依赖界面层。** `export/` 里没有任何 DOM 选择器指向编辑器，
只吃一段 markdown 字符串。好处是同一套输出能力可以被菜单、快捷键、未来的 CLI 或
批量导出复用；坏处是它不知道「当前滚动到哪」，所以封面标题要从文档首 h1 推断——这是
刻意的取舍。

### 2.1 集成方式（只有三处触点）

| 位置 | 改动 | 说明 |
| --- | --- | --- |
| `core/src/main.ts` | `import { createBeautifyPanel }` | 引入面板工厂 |
| `core/src/main.ts` | `const beautify = createBeautifyPanel({ getContent, getDocName })` | 注入两个取值函数，面板不碰编辑器实例 |
| `core/src/main.ts` | 文件菜单新增 `{ id: 'file-beautify', action: () => beautify.open() }` | 唯一入口，移动端菜单自动继承（移动端按 id 遍历同一份菜单定义） |

面板本身是**零框架的手写 DOM**，与项目其余 UI 一致（不引入 React/Vue）。它对外只暴露
`open()`，内部状态（当前模板、尺寸、分页模式、页码）自己管，关掉即销毁，不残留监听。

## 3. 模板机制

### 3.1 正交设计：骨架 × 变量 × 装饰位

```
CARD_BASE_CSS（一份，写死排版规则，只读 var(--c-*)）
        +
compileTemplate(t)（每套模板生成一段变量块）
        +
DECOR_CSS（一份，9 纹理 + 4 强调位 + 3 种角处理，全部靠 data 属性命中）
```

渲染时只看这几个属性：

```html
<div class="ly-card" data-tpl="note" data-tex="grain" data-acc="none"
     data-corner="fold" data-cover="center" data-bg="kraft" data-bind="spiral">
  <i class="ly-bg"></i><i class="ly-bind"></i> …        <!-- 背景层 / 装订层 -->
</div>
```

好处是**组合爆炸但不重复代码**：33 套模板 × 9 底纹 × 4 强调位 × 2 折角 × 7 背景 × 4 装订
≈ 6.7 万种外观组合（还没算 46 项参数的连续取值与 h1–h4 各自的 18 项），而 CSS 总量只有一份骨架 +
一份装饰表 + 33 段变量块 —— 全是字符串常量，零额外依赖、零构建期生成。

> **背景层与装订层用真实元素 `<i class="ly-bg">`，不是 `::before`**：`::before` 已被纹理占用，
> 再用一次会和纹理抢同一个伪元素。两个 `<i>` 由 `card-layout.ts` 的 `pageAsFragment()` 插进
> 每张卡片，`z-index: 0`，正文 `z-index: 1` 压在上面。

约束（写在 `compile.ts` 头部注释里，评审时按这条卡）：模板**只能改变量，不能改盒模型**。
一旦允许模板写 `display` / `width` / `padding`，分页的测量基准就不可控了。

### 3.2 参数：46 项表驱动，面板自动生成

`params.ts` 里是一张表：

```ts
{ path: 'metrics.fontSize', kind: 'number', labelKey: 'tpl.p.fontSize', min: 12, max: 22, step: 0.5, unit: 'px' }
{ path: 'decor.texture', kind: 'select', options: [none, grain, grid, dots, ruled, fiber, halo, stripe, perf, lattice] }  // lattice 0.14.0
{ path: 'decor.topBar.height', kind: 'number', min: 0, max: 24, step: 1, unit: 'px' }          // 0.14.0
{ path: 'metrics.headRule', kind: 'toggle' }
{ path: 'metrics.headText', kind: 'text', placeholderKey: 'tpl.p.textHint', maxLength: 40 }   // 0.12.0
{ path: 'decor.quote', kind: 'select', options: [bar, card, quad, bubble, quotemark, none] } // quotemark 0.14.0
{ path: 'decor.binding', kind: 'select', labelKey: 'tpl.p.binding' }                          // 0.10.0
{ path: 'decor.bgOpacity', kind: 'number', min: 0, max: 100, step: 5, unit: '%' }             // 0.10.0
```

面板遍历这张表 → 生成滑块 / 色盘 / 开关 / 胶囊组 / 文本框。**加一套模板不需要写任何 UI**，
加一个可调项也只需要在表里加一行。读写走 `getPath/setPath`（点路径），不 eval、不拼字符串。

| 分组 | 参数 |
| --- | --- |
| 颜色（7） | 纸张、正文、次级、强调色、代码底色、引文底、引文线 |
| 版面度量（5） | 正文字号、行高、标题字号、左右留白、圆角 |
| 版面元素（2） | 页眉细线、页码 |
| 背景（1 + 专用控件） | 背景不透明度（滑块）；7 种纸纹预设（∅ + 牛皮纸 / 横线 / 方格 / 点阵 / 水彩 / 宣纸 / 柔光）与「上传 / 清除图片」走**缩略图按钮**，不占参数行；9 种底纹在「纹理与装饰」组里 |
| 排版风格（4） | 引用框 **6 式**（0.14.0 加「大引号」）、项目符号 7 式、标题装饰 5 式、外边框 5 式（0.12.0 新增） |
| 印章（4） | 开关、4 枚预设、四角位置、大小（0.12.0 从「一个开关」扩成一组） |
| 页眉页脚（3） | 页眉左、页眉右、页脚，支持 `{doc} {sec} {date} {page} {total}` 占位符（0.12.0 新增） |
| 外带与内面板（6） | 带宽度、内面板底色、描边、圆角、阴影形态（无/贴纸硬阴影/软阴影）、内边距（0.13.0 新增） |
| 分隔线（7） | 细线 / 虚线 / 斜纹 / 胶带 / **渐变 / 点线** / 无，配高度、双色、角度（0.13.0 新增，0.14.0 补两式） |
| 表·码·图（3） | 表格与代码块各 3 态（平/框/立体），图片 3 态（平/相框/胶带）（0.13.0 新增） |
| 有序序号（1） | 纯数字 / 圆形徽标 / 方形徽标（0.13.0 新增） |
| 分级标题（18 × 4） | 底色（可为渐变）、字色、左右/上下内边距、圆角、**对角圆角**、旋转、投影、**块投影（无/轻/光晕）**、**字重**、**字距**、**前置标记（无/竖条/菱形）与标记色**、下划线（无/实线/斜纹/**渐变**/**短条**）、大写、斜体、对齐、行内收窄——**h1~h4 各一套**（0.13.0 新增 12 项，0.14.0 补 6 项） |
| 顶部色条（3） | 高度、起色、止色——起止两色不同就自动成渐变；高度 0 = 不画（0.14.0 新增） |
| 贴纸（8 × n） | 形状、四角位置、尺寸、旋转、填充、描边（描边色兼作徽标文字色）、文字、出血量；最多 6 枚（0.13.0 新增） |

表外另有一行**字体族**选择（无衬线 / 衬线 / 楷体 / 等宽，4 种预设）——它换的是整条
`font.stack`，三处同时改，不适合走「单字段」那套 `path`，所以单独占一行。

**页眉页脚为什么要占位符而不是纯文本**：页码与总页数在分页完成前根本不知道。做法是先写
一个不会出现在正文里的哨兵字符 `TOTAL_MARK = '\u0000'`，等 `paginate()` 收尾时统一
`split/join` 换成真实页数——否则「共 N 页」里的 N 永远是上一版的数字。

**背景为什么不做成参数行**：底纹要「看得见」才好选。面板直接用 `BG_PREVIEW` 里同一份 CSS
画 7 个缩略色块（外加一个 `∅`），选中态加边框；上传的自定义图替换第一个色块为图片缩略。参数表里只留
浓度滑块，因为那是唯一天生适合滑块的维度。`BG_PREVIEW` 与 `compile.ts` 的 `buildBgVars()`
**共用同一份 CSS**，避免「面板看到的花纹和出图不一样」这类漂移。

**自定义背景图的安全边界**：只放行 `data:image/(png|jpeg|webp|gif);base64,`，长度上限 3.2 MB
（`sanitizeBgImage()`）。两条理由 —— 一是 `url()` 是 CSS 注入的经典入口；二是卡片光栅化走
`<svg><foreignObject>`，外部图片会让 canvas 变 tainted，`toDataURL` 直接抛 SecurityError。
上传前还会过一遍 `createImageBitmap` → canvas → `webp` 重编码，长边压到 1600px，
手机拍的 8 MB 原图落进模板也就 200 KB 上下。

### 3.3 改参数为什么必须重新分页

字号从 15 调到 21，每页能装的段落数就变了。所以参数一变走的不是「重绘 CSS」，而是
**完整重跑 `paginate()`**：离屏卡片重新测量 → 重新切页 → 重新出图。检查脚本用
「页数变化」来验证这条链路真的接通（实测 4 页 → 5 页）。

代价是每次改动要 100~300ms。用 160ms 防抖合并连续拖动；渲染用递增 token 丢弃过期结果，
快速拖滑块时旧图不会覆盖新图。

### 3.4 模板的进出与安全

| 能力 | 实现 | 关键点 |
| --- | --- | --- |
| 内置模板 | `builtin.ts` 常量数组（28 套） | 前 8 套 id 与 v0.8.2 完全一致，视觉由 token 重新表达 |
| 我的模板 | localStorage `lypora:beautify:userTemplates`（上限 40 套） | 存整份模板对象，含微调；改过名就丢掉 `names`/`enName`，否则卡片上永远显示内置名 |
| 导出样式包 | `.zip`（`pkg.ts` + `zip-read.ts`） | 图抽成 `bg.png`/`stamp.png`，json 里写 `@bg.png`；附 `README.txt` |
| 导入样式包 | 按文件头 `PK\x03\x04` 分流 → 解 zip 还原图；否则按旧 `.lyt.json` 处理 | **id 冲突加后缀，绝不覆盖内置** |
| 恢复默认 | 用同 id 的内置/用户模板替换当前 | — |

**为什么要自己写 zip 读写**：样式包里只有几十 KB，为它引 jszip 会让 bundle 多 90 KB，还要
过一遍许可证。`zip-read.ts` 用 `DecompressionStream('deflate-raw')` + 手写 EOCD / 中央目录解析
（约 70 行），零依赖；写 zip 用 `CompressionStream` 走同一套。store（method 0）与 deflate（method 8）
两种都认，够对付「用户用系统压缩包另存一遍」这种常见情况。

**校验是安全边界，不是格式检查。** 模板里的字符串最终会被拼进 `<style>`，一个 `}`
就能跳出变量块改写整页样式。所以 `io.ts` 按**语法形态**白名单：

```ts
if (/[;{}<>@\\]/.test(s)) return null            // 结构性字符直接拒
if (/url\s*\(|expression\s*\(|javascript:/i.test(s)) return null
// 只放行：具名色白名单 / #hex / rgb(a) / hsl(a) / linear|radial-gradient / 投影
```

数值一律 `clamp` 到区间，枚举一律取白名单内的值，字体栈只允许字母、空格、逗号、引号、连字符。
非法字段**丢弃并回落到默认值**，不是整份拒绝——用户手改 JSON 时最多是「某个参数没生效」，
不会得到一份坏模板或一个坏页面。

`popart` 用的是新加的「艺术层」——外带、内面板、硬阴影、分级色块标题、斜纹线、贴纸。
0.12.0 新增的 8 套补的是「体裁」而不是「配色」：作业本、旧报纸、胶片、黑板、水彩、和纸、
瑞士栅格、金属渐变——原来 20 套里没有一档能直接当"手写笔记"或"电影截帧"用。

0.14.0 新增的 4 套补的是「标题当图形」这一路：前 29 套的标题再变也是"字"，这 4 套的 h2 是
**色块/药丸/渐变条**。为了让它们只靠数据就能表达，schema 6 补了六个字段（对角圆角、块投影、
字重、字距、前置标记、标记色）和一条顶部色条——**依然是零行模板 CSS**，全部编译成
`--c-*` 变量 + `[data-topbar]`。跟 `popart` 的关系：`popart` 用的是"厚度"（硬阴影 + 外带），
这四套用的是"渐层 + 圆角 + 字距"，同一套骨架的两种极端用法。

**画廊缩略图是真排版**，不是色块：面板把 `CARD_BASE_CSS` + 每套 `compileTemplate()` 的结果
一次性塞进一张 `<style>`，缩略图就是真的 `.ly-card`，只把字号压到 `2.55cqw`（跟着卡片宽度走）。
配 `IntersectionObserver`（`rootMargin: 240px`）懒挂载，进视口才 `innerHTML`。

为什么不用「整页等比缩到 0.33 倍」：540px 的卡片压到 180px，15px 正文只剩 5px，屏幕上是一片
灰糊，28 套看起来都一样。也不用 canvas 光栅化：28 套 × 一次 SVG→canvas，开面板要等好几秒。

## 4. 数据流

```
CM6 doc ──mdToHtml()──► HTML ──DOMParser──► 顶层块数组
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    │ paginate()：离屏卡片逐块实测 scrollHeight          │
                    │   装不下 → 换页；单块超整页 → 按行二分再拆          │
                    │   页眉/页脚/留白全部来自模板，直接影响可用高度       │
                    └─────────────────────────┬─────────────────────────┘
                                              ▼
                                   CardPage[]（纯 HTML 字符串）
                                              │
        ┌─────────────────────────────────────┼─────────────────────────────────────┐
        ▼                                     ▼                                     ▼
renderPagePreview()                  renderPagesToPng()                    renderPagesToPdf()
  （面板预览，≤320px 宽）              （单页 PNG / 多页 ZIP）                （JPEG → 手写 PDF）
```

## 5. 离线运行所需条件

「完全本地离线」不是一句承诺，是七个具体条件同时成立：

| # | 条件 | 实现 | 违反会怎样 |
| --- | --- | --- | --- |
| 1 | **无后端依赖** | 全流程在渲染进程内完成 | 断网即不可用 |
| 2 | **字体只用系统栈** | 正文/标题用 `-apple-system / Segoe UI / 微软雅黑 / PingFang / 思源黑体`，楷体用 `KaiTi / STKaiti`，等宽用 `Consolas / Courier New`；**不引任何 webfont** | 缺字、豆腐块、导出图与预览不一致 |
| 3 | **公式样式内联** | `katex-inline.ts` 由 `gen-katex-css.mjs` 生成：20 个 woff2 转 base64 内联，共 360 KB，构建期产物 | 公式退化成平铺文字（`∫₀¹` → `∫01`） |
| 4 | **图片转 data URL** | 截图前 `inlineImages()` 把所有 `<img>` 换成 data URL；拉不到的**直接摘掉** | 外链残留 → canvas tainted → `toDataURL` 抛 SecurityError |
| 5 | **零第三方运行时** | PDF 写入器（DCTDecode 直通）与 ZIP 写入器（store 模式）自研，共约 160 行；不引 jsPDF/html2canvas | 依赖树膨胀、行为不可预测 |
| 6 | **无账号 / 无遥测** | 无登录、无统计上报、无主题商店；模板与设置只落 localStorage | 需要联网才能用 |
| 7 | **资源打包进安装包** | 前端产物在 `resources/app/web`（Windows）、`assets/public`（Android）内，构建时逐文件哈希比对 | 运行时才去下载 |

### 5.1 离线审计（可复现）

`beautify-check.mjs` 在整场操作里拦截所有网络请求，只允许 `127.0.0.1` / `data:` / `blob:` / `file:`：

```js
page.on('request', (req) => {
  const u = req.url()
  if (!u.startsWith('http://127.0.0.1') && !/^(data|blob|file):/.test(u)) external.push(u)
})
```

实测结果：`externalRequests: []`，`count: 0`。覆盖了「灌文档 → 33 套模板逐个出图 →
调 46 项参数 → 换背景 / 换装订 / 上传自定义图 → 导入导出模板 → 导出 PNG/PDF」的全过程。

### 5.2 离线下的能力边界（诚实说明）

- **字体不再「可选」**。用户机器上没有楷体，水墨模板的标题会回落到宋体/衬线，风格会打折。
  这是「不引 webfont」的必然代价；如果将来要保证跨机一致，唯一办法是把字体也打进包（每款增加 2–10 MB）。
- **图片插不了远程图**。Markdown 里的 `https://…` 图片在无网环境拉不到，会被摘掉（卡片少一张图，不报错）。
  本地相对路径图片在 Electron 下可读；Web/PWA 下受浏览器安全策略限制。
- **模板分享靠文件**，不靠链接。`.lyt.json` 可以微信传、U 盘拷，但没有一键分享链接——这是没有服务端的结果。

### 8.3 从 v0.10.0 来（0.11.0 的改动）

**模板契约、参数表、`.lyt.json` 格式一个字都没动**（schema 仍是 3，19 项参数，20 套模板）。变的只有面板
挂在哪里：

| 项 | 0.10.0 | 0.11.0 |
| --- | --- | --- |
| 面板形态 | 居中模态对话框（最大 1180px，`.ce-mask` 铺满视口） | **整屏面板**：铺满编辑区、保留菜单栏作标题，`.ce` 无圆角无阴影 |
| 顶边定位 | `inset: 0` | `inset: var(--ce-top, 0px) 0 0 0`，`--ce-top` 由 `open()` 实测菜单栏 + 标签栏 |
| 窄屏（≤760px） | 仍按行平铺，参数区被挤成一条 | 上下分段：预览 `flex: 0 0 42%`、参数区可滚动 |
| 打开时机 | 独立模态，与文档无关 | 仍是独立面板，但**每份文档各自独立状态**（当前标签切换不影响已渲染的预览） |

比稿时最容易犯的错：以为"改成整屏"只是把 `max-width` 去掉。真正要改的是**定位基准**——原来的
`fixed; inset: 0` 之所以能用，是因为模态本来就该盖住菜单栏；现在菜单栏要留在外面，就得把"菜单栏 + 标签栏
到底多高"变成运行时可读的量。`100vh` 不能用（手机含地址栏），固定像素也不能用（菜单栏在窄屏会折行）。

**升级不丢设置**：老的 `lypora:beautify:*` 键照常读入，`normalizeTemplate()` 对缺字段回落默认值，
所以 schema 3 存的模板打开后只是"新装饰都是默认值"。id 全部沿用，用户的"我的模板"不受影响。

**两处用户可感知的修复**（0.11.2 报的）：

1. 「圆角」滑块与「圆切角」选项看着没反应 —— 真因有两层：`.ce-img` 写死白底把圆角填平了；
   `captureCard` 又把 `border-radius` 抹成 0。现在预览走透明底 + 保留圆角，导出 PDF 时才拉平。
   顺带把预览出图从 320px 提到 800px（2 倍屏要 800 设备像素才不糊）。
2. 回形针/订书钉"显示错误" —— 原来是用三个 CSS 边框拼的口袋。现在回形针是一条线走完的 SVG 路径
   （内圈收在中段，不是拖到底部以外），订书钉是填充路径画的扁金属带（冠腿比 1:2，接近真实 24/6 钉）。

### 8.5 从 v0.12 来（0.13.0 的改动）

0.13.0 是**纯增量**：老模板、老样式包、老参数一个没动。

| 项 | 0.12.0 | 0.13.0 |
| --- | --- | --- |
| 模板 schema | 4 | **5**（`decor` 新增 `panel/headings/rule/ornaments/surface/listNo`，`tokens` 新增 `panelBg/patternInk`） |
| 内置模板 | 28 套 | **29 套**（`popart` 波普撞印，带 3 个配色变体） |
| 参数 | 29 项 / 7 组 | **44 项 / 11 组**（+ 4 级标题 ×12、+ 每枚贴纸 ×8；波普在面板上是 107 个控件） |
| 项目符号 | 6 式 | 7 式（加 `★`） |
| 样式包 | schema 4 | **schema 5**（schema 4 的包照常导入，新字段回落默认值） |

**为什么老模板一个像素都不会变**：新字段的默认值全部是"不画"——`--c-band: 0`、
`--c-panel-bg: transparent`、`--c-panel-border: 0`、`--c-panel-shadow: none`；
`headCss()` 对"全是默认值"的级别**直接不生成规则**；`hr` 的默认背景与原来
`border-top: 1px solid var(--c-rule)` 视觉等效。所以 28 套的出图与 0.12.0 逐像素一致
（`beautify-check` B 组的采样色数与 sig 都没变）。

**三个已知坑（写在这里省得下次再踩）**：

1. `card-capture.ts` 会把整份样式表内联进 SVG 的 `<style>`，那里**不能出现裸的小于号**——
   连 CSS 注释里写 `ol 的 start 属性` 都不行。现在 `<style>` 包了 CDATA，从根上解决。
2. 给缩略图加装饰要同时压三个系数：`--c-band-k`（外带）、`--c-pad-k`（内面板内边距）、
   `--o-k`（贴纸）。只压带不压内边距，170px 的缩略图里 `.ly-body` 会溢出 21px。
3. `∅`（清除颜色）这类小按钮必须放在数值列的**左边**。放右边会把整行右移，`ui-check`
   的 `value-column-align` 会立刻红。

0.14.0 同样是**纯增量**：29 套老模板、老样式包、老参数一个没动，出图逐像素不变。

| 项 | 0.13.0 | 0.14.0 |
| --- | --- | --- |
| 模板 schema | 5 | **6**（`decor.topBar`；`headings.*` 加 `radiusAlt/elev/weight/track/mark/markColor`；纹理加 `lattice`、引用框加 `quotemark`、分隔线加 `fade/dot`、下划线加 `fade/bar`） |
| 内置模板 | 29 套 | **33 套**（`deco` 黑金菱纹 / `pillorange` 橙光胶囊 / `cyanflow` 青蓝流线 / `typograph` 米纸铅字） |
| 参数 | 44 项 / 11 组 | **46 项 / 12 组**（+ 顶部色条 3；分级标题从 12 项涨到 18 项 → 面板 118 个控件） |
| 词条 | 454 | **480**（七语言同步，`i18n-check` 逐键对齐） |
| 样式包 | schema 5 | **schema 6**（schema 5 的包照常导入，新字段回落默认值） |

**这次的"默认不画"清单**（保证 29 套老模板零变化）：

| 新字段 | 默认值 | 默认时生成什么 |
| --- | --- | --- |
| `headings.*.radiusAlt` | `0` | 0 时按 `radius` 输出单值圆角（不是 `a 0 a 0`） |
| `headings.*.elev` | `'none'` | 不写 `box-shadow` |
| `headings.*.weight` | `0` | 不写 `font-weight`（`0` 是"继承骨架"，**不能**写成 `font-weight: 0`） |
| `headings.*.track` | `0` | 不写 `letter-spacing` |
| `headings.*.mark` | `'none'` | 不写 `padding-left`，也不生成 `::before` |
| `decor.topBar` | `height: 0` | 不输出变量、`data-topbar="none"`、不打 `.ly-topbar` 元素、不加 `padding-top` |

`isPlainHead()` 把上述六个字段一起纳入"全默认"判定：**只要有一项非默认才生成这条级别的规则**，
所以 29 套老模板的 `.ly-head` 规则条数一条没变（`beautify-check` C5 的回归断言就是在守这条）。

**三个新坑（这次踩出来的）**：

1. **面板下拉的 `value` 永远是字符串**，`'0'` 是 truthy。所以 `ParamSpec` 加了 `numeric?: boolean`：
   面板写回时 `Number(opt.value)`，高亮时用 `String(opt.value) === String(value)` 比。
   漏了这个，选「继承」会真的写进 `font-weight: 0`，标题直接变隐形。
2. **面板缩略图是静态样例**（`renderGallery()` 只在换模板时重建），改参数它不重画。
   要验"控件点了有没有用"，只能看落盘的模板数据 + `.ce-img` 的像素——量缩略图什么都证明不了。
3. **色块判定必须带高度**。一条 1px 的浅色分隔线同样是"有色横带"，它的宽度可以盖过标题色块：
   橙光胶囊第一版就因此量到 680px 的分隔线，拿 84.9% 险过 85% 的阈值，而胶囊实际只有 32%。
   现在先按"连续行 ≥12 行"拼成块，再在块里取最宽行；高度另用竖带法量（色块里压着字，
   逐行连续色段会被字切碎，胶囊 69px 高会被量成 18 行）。

### 8.7 从 0.14.0 来（0.14.1：安卓导出的韧性）

0.14.0 在安卓手机上「排版 → 导出 PNG / PDF」有两种症状：一直停在「正在渲染…」，
或者直接报失败。查下来不是模板问题——**光栅化只有一条通路，而且整条链上一个超时都没有**。
0.14.1 的桌面像素输出与 0.14.0 逐字节相同（C6 用 sha256 比的），改的全是失败时的行为。

| 症状 | 成因（集中在 `card-capture.ts` / `native.ts`） | 0.14.1 的做法 |
| --- | --- | --- |
| 永远「正在渲染…」，之后点导出全无反应 | `img.onload` 没有超时；WebView 对超长 data URI 可能**不 load 也不 error**，Promise 永不 settle，`busy` 一直为 true | 每步套 6s 上限；`busy` 一律在 `finally` 复位；被占用时给一句提示，不再静默 |
| 带图的稿子卡死 | `fetch(src)`、`img.decode()` 都没有超时，移动网络卡一次就再不继续 | `AbortController` 5s + decode 超时 |
| 报 `card-svg-load-failed`，越试越差 | 失败路径不还原 `img.src`、不摘 host（一张卡 + 一整套 CSS 全留在文档里），内存被反复吃掉 | 全部收进 `try/finally`；host 打 `data-ly-capture` 标记，验收里直接数残留 |
| 白图当成功 | `onload` 成功但 `drawImage` 出来全透明，照样存盘 | 9 点采样，空白或画布被污染就换下一条路 |
| 分享面板划掉也报「导出失败」 | Capacitor Share 取消时 reject `Share canceled`，而文件其实已经写进 Documents | `reason=canceled` 单独提示（"已保存，未分享"），另附路径 |
| 多页导出像死机 | 整段没有让帧，状态栏根本来不及重绘 | 每页之间让一帧，状态栏显示「正在渲染 n/N」 |

**降级链**（桌面永远走第 1 条；第 2 条起只在异常环境才会用到）：

| # | 通路 | 实测（2 页样例、540×720、2 倍） |
| --- | --- | --- |
| 1 | base64 data URI | SVG 394KB → URI 525KB，60ms |
| 2 | blob URL | 本机 Chromium 会把画布标脏（`toBlob` 抛 SecurityError）→ 自动落到第 3 条 |
| 3 | percent data URI | SVG 394KB → URI 444KB，53ms |
| 4 | 同 #1，倍率降到 0.65 | 只在画布/内存出问题时才用得上 |

验收怎么复现这些异常：`card-capture.ts` 认一条 localStorage 键 `lypora:capture-probe`，
写成 `{"fail":["data"],"timeoutMs":6000}` 就能让指定通路失败（`data` / `blob` / `percent` /
`canvas` / `encode`）。只在页面上手动写才有用，正常使用永远读不到；C6 就是靠它把
"某条路不通"在桌面上复现出来的。

顺带修掉的两个小瑕疵：

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 项目符号「星点」 | 词表没有 `tpl.bullet.star`，面板上直接显示键名 | 七语言补齐（词条 480 → **486**） |
| 帮助页「排版」 | 上次改的 `core/src/help/*/layout.md` 只在源码里，产物还是旧版 | 本次构建已带进 bundle（`?raw` 内联） |

`schema` 仍是 6，已导出的样式包（`.zip` / 旧 `.lyt.json`）全部照旧可导入。

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 分组标题（尺寸/分页/颜色/版面度量） | 13px，`--fg-muted` | **14px**（`ui-check` 字号刻度守着） |
| 参数名（正文字号/行高/左右留白） | 11.5px，灰 | **13px**，改用 `--fg` 主色 |
| 参数行 | 26px 高、标签列 82px | 30px 高、标签列 **96px**（两字标签不再挤成竖排） |
| 贴纸那组 | 面板上显示裸键 `card.groupOrn` | 中文「贴纸」（`no-raw-keys` 断言守住，7 语言都补齐） |
| 贴纸形状 | 5 种（五角星/四角星/爆炸/徽标/墨块） | **7 种**，新增**对话气泡**与**气球**（带字，切过去自动补占位词） |

| H1–H4 底色 | 只有「通栏」一种 | 「底色范围」两选一：**通栏** / **仅文字**（字段仍是 `inline`，不影响旧包） |
| 装订件 | 回形针像铁丝圈、订书钉像小板凳 | 按实物重画：回形针（一根线走完 + 三层错位表现圆柱）、订书钉（扁带 + 两端下折）、**长尾夹**（新增） |
| 参数说明 | 无 | 悬停 420ms 浮出自绘说明（触摸屏上点标签触发），约 60 条 × 7 语言，词条 486 → **577** |

**四个坑（都是这次验收时才暴露的）**：

1. **颜色分支不重渲染参数行，于是「∅」永远是 disabled**。`applyPath()` 走颜色时只改模板、
   不调 `renderParams()`，行里的码位和清除键就停在"进来时"的样子——用户选完色**反而清不掉**。
   修法是在 `pick.oninput` 里就地把码位与 `∅` 同步，不等重渲染。（C7 第一版就是因为点了
   一个 disabled 按钮，红底色一直没被收掉，后面所有"找红色"的度量全部量错。）
2. **断言里用 `?.click()` 会假通过**。`clickSeg` 是 `querySelector(...)?.click()`，控件改名后
   它静默空转，整组断言拿同一张图互相比、全绿。C7 自己的 `ornSeg`/`ornNum`/`ornColor`
   一律"找不到就抛"，且**分清控件类型**——贴纸「尺寸」是数值输入（range + number），
   拿分段按钮去点它必然找不到。
3. **量某件东西之前，先把别的同类像素收掉**。H1 的红底色是当时整张卡里最红的东西，
   于是"左中贴纸"量出 `x=59 / 中心 y=149`——那其实是标题的高亮块。先清底色，才量出
   `x=0 / 中心 528`（卡高 1067）。
4. **装订件的度量不能按颜色区间去框**。金属灰区间会同时套住纸纹、抗锯齿和灰字，
   第一版把回形针框成了 5:1 的横贯整卡。正确做法是量**「有装订」与「无装订」的像素差**；
   且区域要给整幅宽（回形针与订书钉是 `translateX(-50%)` 居中的，早先写的 `x<260` 直接把它们排除在外），
   外接框比例还要当心旋转——件带 -5°，42×5 的钉冠会被 `w·sinθ` 撑成 60×14，
   所以另量**中线厚度**与**填充率**（实心带 0.92，描边「⊓」约 1.9）。

5. **`+` 写成 `,` 会让整段 SVG 静默消失**。重画长尾夹时手柄那段抽成了小函数，
   收尾写成 `)(),` 而不是 `)() +`，于是整个表达式变成逗号表达式——返回的只剩后半段 `'<path …/>'`，
   既没有 `<svg>` 也没有 `<defs>`，装订件从画面上彻底消失，而 `tsc` 一声不响（逗号表达式是合法 TS）。
   是 `beautify-check` 的"选了装订后画面必须变"这条红掉的。这类拼接最好一开始就用数组 `join('')`。

### 8.9 从 0.14.2 来（0.14.3：印章的上传图与签名的名字）

两处都是「参数在面板上，但改不动画面」。数据格式没动：`schema` 仍是 6，新增的 `decor.stampText`
缺省为空串，所以旧样式包与 29 套老模板的导出像素都不变。

| 项 | 之前 | 现在 |
| --- | --- | --- |
| 上传印章在左上/右上 | 尺寸滑块无效，图按原始像素铺开，大图盖住标题 | 四角共用一条宽高规则，等比缩进 `stampSize×1.1` 的方框 |
| 签名的字 | 写死「签名」 | 新增「印章文字」一行：填真名就签真名，留空回到预设字 |
| 字号 | 固定 | 字数超出预设长度时按 `room/字数` 收小，不戳出边框、不跑出下划线 |

**两个坑**：

1. **上传图压根没有 `data-stamp`，所以尺寸规则一条都没命中**。当时只有
   `[data-pos="bl"] .ly-stamp-img, [data-pos="br"] .ly-stamp-img { max-height: … }` 这一条，
   而上传分支输出的 `<span class="ly-stamp">` 既没有 `data-stamp` 也没有宽高 ——
   于是左下/右下受约束、左上/右上按原图铺开。这类「一个角能调、另一个角不能调」的 bug
   光看代码很难发现，因为两条分支的 HTML 只差一个属性；是量了四个角的红块面积才看见的。
   修法：上传分支补 `data-stamp="image"`，规则改成四角通用 `width/height` + `object-fit:contain`。
2. **改文字必须先过一遍转义**。`stampText` 会直接进 HTML，`&`/`<` 不转义就会把卡片 DOM 破开；
   同时用 `scrubText(..., 6)` 把长度和花括号剔掉，免得用户输入把模板变量串进去。

**验收（`beautify-check` 新增 C8）**：上传 160×100 纯红 PNG，`size=40` 时四角面积
1344 / 1344 / 1346 / 1345（旧代码左上、右上不随滑块变）；`size=120` 时四角同步放大到
12757 / 12743 / 12727 / 12725（≈9.5 倍，符合面积平方）。签名改「张三丰」与默认图差 5141px，
清空后与默认图**逐像素差 0**。默认字数下 `k` 恰好等于预设字号，所以老模板一像素没动。

**没有改的东西**（免得被误读）：模板数据格式、`--c-*` 变量名、29 套老模板的任何几何。
`isPlainHead()` 的全默认判定照旧，所以老模板的导出像素仍是逐字节不变的（C5 回归断言）。
