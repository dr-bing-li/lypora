# 09 · 美化输出与模板引擎

> 版本 `0.13.0`　来源：从 `Lypora-NEXT` 合并（`ed55355` / `64d16fa`，公共基线 `8583d5a`）；
> 0.10.0 扩到 20 套 + 19 项参数 + 背景/装订两维；0.12.0 扩到 28 套 + 29 项参数 + 引用框/符号/标题/边框/印章

> 0.13.0 扩到 **29 套 + 44 项参数 + 「艺术层」六组字段（外带/内面板/分级标题/分隔线/贴纸/表码图三态）**，

## 1. 这一层解决什么问题

v0.8.2 的输出能力是「8 套风格 = 8 段手写 CSS」。三个问题在真实使用里立刻显形：

1. 用户**没法调**。想改字号，得会写 CSS 并找到对应选择器。
2. 加模板要**重抄一遍**排版规则，抄漏一处就是两套模板行为不一致。
3. 分页与截图依赖 CSS 的测量基准，模板一多，基准就漂。

0.9.0 的答案是：**模板 = 一份 JSON + 一个编译器**。

```ts
interface CardTemplate {
  schema: 3                                                          // 2 → 3（0.10.0 加背景/装订）
  id, name, enName, dark?
  tokens:  { paper, ink, muted, faint, accent, onAccent, rule,
             codeBg, codeInk, quoteBg, quoteRule, mark, shadow }     // 13 个颜色/底色
  metrics: { padX, padTop, padBottom, fontSize, lineHeight,
             radius, titleSize, headRule, pageNo, brand }            // 10 个度量与开关
  decor:   { texture, accent, corner, tape, stamp, cover,
             binding, bg, bgImage, bgOpacity }                       // 10 个装饰位
  code:    { com, str, num, kw, fn }                                  // 5 个高亮色
  font:    { body, head, mono }                                       // 3 个字体栈
}
```

41 个字段，全部可序列化、可校验、可导入导出。

`schema` 从 2 升到 3 **不是破坏性变更**：`normalizeTemplate()` 对缺字段一律回落默认值
（`binding: 'none'` / `bg: 'none'` / `bgImage: ''` / `bgOpacity: 100`），所以 0.9.0 导出的
`.lyt.json` 和旧 localStorage 里的模板照旧能读进来。

## 2. 分层与职责边界

```
┌─────────────────────────────────────────────────────────────┐
│  外壳层：Electron（desktop/）· Capacitor（core/android/）· Web/PWA │
├─────────────────────────────────────────────────────────────┤
│  界面层：menubar · beautify-panel · outline · statusbar        │
├─────────────────────────────────────────────────────────────┤
│  能力层：io/（文件、图片、原生桥）· save-binary（二进制落盘）      │
├─────────────────────────────────────────────────────────────┤
│  输出层：template（模板）→ card-layout（分页）→ card-capture（光栅化）│
├─────────────────────────────────────────────────────────────┤
│  编辑器层：CM6 + live-preview + 高亮 + KaTeX + mdToHtml          │
└─────────────────────────────────────────────────────────────┘
```

**关键边界：输出层绝不反向依赖界面层。** `export/` 里没有任何 DOM 选择器指向编辑器，
只吃一段 markdown 字符串。好处是同一套输出能力可以被菜单、快捷键、未来的 CLI 或
批量导出复用；坏处是它不知道「当前滚动到哪」，所以封面标题要从文档首 h1 推断——这是
刻意的取舍。

### 2.1 集成方式（只有三处触点）

| 位置 | 改动 | 说明 |
| --- | --- | --- |
| `core/src/main.ts` | `import { createBeautifyPanel }` | 引入面板工厂 |
| `core/src/main.ts` | `const beautify = createBeautifyPanel({ getContent, getDocName })` | 注入两个取值函数，面板不碰编辑器实例 |
| `core/src/main.ts` | 文件菜单新增 `{ id: 'file-beautify', action: () => beautify.open() }` | 唯一入口，移动端菜单自动继承（移动端按 id 遍历同一份菜单定义） |

面板本身是**零框架的手写 DOM**，与项目其余 UI 一致（不引入 React/Vue）。它对外只暴露
`open()`，内部状态（当前模板、尺寸、分页模式、页码）自己管，关掉即销毁，不残留监听。

## 3. 模板机制

### 3.1 正交设计：骨架 × 变量 × 装饰位

```
CARD_BASE_CSS（一份，写死排版规则，只读 var(--c-*)）
        +
compileTemplate(t)（每套模板生成一段变量块）
        +
DECOR_CSS（一份，8 纹理 + 4 强调位 + 2 折角，全部靠 data 属性命中）
```

渲染时只看这几个属性：

```html
<div class="ly-card" data-tpl="note" data-tex="grain" data-acc="none"
     data-corner="fold" data-cover="center" data-bg="kraft" data-bind="spiral">
  <i class="ly-bg"></i><i class="ly-bind"></i> …        <!-- 背景层 / 装订层 -->
</div>
```

好处是**组合爆炸但不重复代码**：20 套模板 × 8 纹理 × 4 强调位 × 2 折角 × 7 背景 × 4 装订
≈ 3.6 万种外观组合（还没算 19 项数值参数的连续取值），而 CSS 总量只有一份骨架 +
一份装饰表 + 20 段变量块 —— 全是字符串常量，零额外依赖、零构建期生成。

> **背景层与装订层用真实元素 `<i class="ly-bg">`，不是 `::before`**：`::before` 已被纹理占用，
> 再用一次会和纹理抢同一个伪元素。两个 `<i>` 由 `card-layout.ts` 的 `pageAsFragment()` 插进
> 每张卡片，`z-index: 0`，正文 `z-index: 1` 压在上面。

约束（写在 `compile.ts` 头部注释里，评审时按这条卡）：模板**只能改变量，不能改盒模型**。
一旦允许模板写 `display` / `width` / `padding`，分页的测量基准就不可控了。

### 3.2 参数：44 项表驱动，面板自动生成

`params.ts` 里是一张表：

```ts
{ path: 'metrics.fontSize', kind: 'number', labelKey: 'tpl.p.fontSize', min: 12, max: 22, step: 0.5, unit: 'px' }
{ path: 'decor.texture', kind: 'select', options: [none, grain, grid, dots, ruled, fiber, halo, stripe, perf] }
{ path: 'metrics.headRule', kind: 'toggle' }
{ path: 'metrics.headText', kind: 'text', placeholderKey: 'tpl.p.textHint', maxLength: 40 }   // 0.12.0
{ path: 'decor.quote', kind: 'select', options: [bar, card, quad, bubble, none] }            // 0.12.0
{ path: 'decor.binding', kind: 'select', labelKey: 'tpl.p.binding' }                          // 0.10.0
{ path: 'decor.bgOpacity', kind: 'number', min: 0, max: 100, step: 5, unit: '%' }             // 0.10.0
```

面板遍历这张表 → 生成滑块 / 色盘 / 开关 / 胶囊组 / 文本框。**加一套模板不需要写任何 UI**，
加一个可调项也只需要在表里加一行。读写走 `getPath/setPath`（点路径），不 eval、不拼字符串。

| 分组 | 参数 |
| --- | --- |
| 颜色（7） | 纸张、正文、次级、强调色、代码底色、引文底、引文线 |
| 版面度量（5） | 正文字号、行高、标题字号、左右留白、圆角 |
| 版面元素（2） | 页眉细线、页码 |
| 背景（1 + 专用控件） | 背景不透明度（滑块）；底纹 8 选 1 与「上传 / 清除图片」走**缩略图按钮**，不占参数行 |
| 排版风格（4） | 引用框 5 式、项目符号 6 式、标题装饰 5 式、外边框 5 式（0.12.0 新增） |
| 印章（4） | 开关、4 枚预设、四角位置、大小（0.12.0 从「一个开关」扩成一组） |
| 页眉页脚（3） | 页眉左、页眉右、页脚，支持 `{doc} {sec} {date} {page} {total}` 占位符（0.12.0 新增） |
| 外带与内面板（6） | 带宽度、内面板底色、描边、圆角、阴影形态（无/贴纸硬阴影/软阴影）、内边距（0.13.0 新增） |
| 分隔线（5） | 细线 / 虚线 / 斜纹 / 胶带 / 无，配高度、双色、角度（0.13.0 新增） |
| 表·码·图（3） | 表格与代码块各 3 态（平/框/立体），图片 3 态（平/相框/胶带）（0.13.0 新增） |
| 有序序号（1） | 纯数字 / 圆形徽标 / 方形徽标（0.13.0 新增） |
| 分级标题（12 × 4） | 底色、字色、左右/上下内边距、圆角、旋转、投影、下划线（无/实线/斜纹）、大写、斜体、对齐、行内收窄——**h1~h4 各一套**（0.13.0 新增） |
| 贴纸（8 × n） | 形状、四角位置、尺寸、旋转、填充、描边（描边色兼作徽标文字色）、文字、出血量；最多 6 枚（0.13.0 新增） |

表外另有一行**字体族**选择（无衬线 / 衬线 / 楷体 / 等宽，4 种预设）——它换的是整条
`font.stack`，三处同时改，不适合走「单字段」那套 `path`，所以单独占一行。

**页眉页脚为什么要占位符而不是纯文本**：页码与总页数在分页完成前根本不知道。做法是先写
一个不会出现在正文里的哨兵字符 `TOTAL_MARK = '\u0000'`，等 `paginate()` 收尾时统一
`split/join` 换成真实页数——否则「共 N 页」里的 N 永远是上一版的数字。

**背景为什么不做成参数行**：底纹要「看得见」才好选。面板直接用 `BG_PREVIEW` 里同一份 CSS
画 6 个缩略色块，选中态加边框；上传的自定义图替换第一个色块为图片缩略。参数表里只留
浓度滑块，因为那是唯一天生适合滑块的维度。`BG_PREVIEW` 与 `compile.ts` 的 `buildBgVars()`
**共用同一份 CSS**，避免「面板看到的花纹和出图不一样」这类漂移。

**自定义背景图的安全边界**：只放行 `data:image/(png|jpeg|webp|gif);base64,`，长度上限 3.2 MB
（`sanitizeBgImage()`）。两条理由 —— 一是 `url()` 是 CSS 注入的经典入口；二是卡片光栅化走
`<svg><foreignObject>`，外部图片会让 canvas 变 tainted，`toDataURL` 直接抛 SecurityError。
上传前还会过一遍 `createImageBitmap` → canvas → `webp` 重编码，长边压到 1600px，
手机拍的 8 MB 原图落进模板也就 200 KB 上下。

### 3.3 改参数为什么必须重新分页

字号从 15 调到 21，每页能装的段落数就变了。所以参数一变走的不是「重绘 CSS」，而是
**完整重跑 `paginate()`**：离屏卡片重新测量 → 重新切页 → 重新出图。检查脚本用
「页数变化」来验证这条链路真的接通（实测 4 页 → 5 页）。

代价是每次改动要 100~300ms。用 160ms 防抖合并连续拖动；渲染用递增 token 丢弃过期结果，
快速拖滑块时旧图不会覆盖新图。

### 3.4 模板的进出与安全

| 能力 | 实现 | 关键点 |
| --- | --- | --- |
| 内置模板 | `builtin.ts` 常量数组（28 套） | 前 8 套 id 与 v0.8.2 完全一致，视觉由 token 重新表达 |
| 我的模板 | localStorage `lypora:beautify:userTemplates`（上限 40 套） | 存整份模板对象，含微调；改过名就丢掉 `names`/`enName`，否则卡片上永远显示内置名 |
| 导出样式包 | `.zip`（`pkg.ts` + `zip-read.ts`） | 图抽成 `bg.png`/`stamp.png`，json 里写 `@bg.png`；附 `README.txt` |
| 导入样式包 | 按文件头 `PK\x03\x04` 分流 → 解 zip 还原图；否则按旧 `.lyt.json` 处理 | **id 冲突加后缀，绝不覆盖内置** |
| 恢复默认 | 用同 id 的内置/用户模板替换当前 | — |

**为什么要自己写 zip 读写**：样式包里只有几十 KB，为它引 jszip 会让 bundle 多 90 KB，还要
过一遍许可证。`zip-read.ts` 用 `DecompressionStream('deflate-raw')` + 手写 EOCD / 中央目录解析
（约 70 行），零依赖；写 zip 用 `CompressionStream` 走同一套。store（method 0）与 deflate（method 8）
两种都认，够对付「用户用系统压缩包另存一遍」这种常见情况。

**校验是安全边界，不是格式检查。** 模板里的字符串最终会被拼进 `<style>`，一个 `}`
就能跳出变量块改写整页样式。所以 `io.ts` 按**语法形态**白名单：

```ts
if (/[;{}<>@\\]/.test(s)) return null            // 结构性字符直接拒
if (/url\s*\(|expression\s*\(|javascript:/i.test(s)) return null
// 只放行：具名色白名单 / #hex / rgb(a) / hsl(a) / linear|radial-gradient / 投影
```

数值一律 `clamp` 到区间，枚举一律取白名单内的值，字体栈只允许字母、空格、逗号、引号、连字符。
非法字段**丢弃并回落到默认值**，不是整份拒绝——用户手改 JSON 时最多是「某个参数没生效」，
不会得到一份坏模板或一个坏页面。

**画廊缩略图是真排版**，不是色块：面板把 `CARD_BASE_CSS` + 每套 `compileTemplate()` 的结果
一次性塞进一张 `<style>`，缩略图就是真的 `.ly-card`，只把字号压到 `2.55cqw`（跟着卡片宽度走）。
配 `IntersectionObserver`（`rootMargin: 240px`）懒挂载，进视口才 `innerHTML`。

为什么不用「整页等比缩到 0.33 倍」：540px 的卡片压到 180px，15px 正文只剩 5px，屏幕上是一片
灰糊，28 套看起来都一样。也不用 canvas 光栅化：28 套 × 一次 SVG→canvas，开面板要等好几秒。

## 4. 数据流

```
CM6 doc ──mdToHtml()──► HTML ──DOMParser──► 顶层块数组
                                              │
```

## 5. 离线运行所需条件

「完全本地离线」不是一句承诺，是七个具体条件同时成立：

| # | 条件 | 实现 | 违反会怎样 |
| --- | --- | --- | --- |
| 1 | **无后端依赖** | 全流程在渲染进程内完成 | 断网即不可用 |
| 2 | **字体只用系统栈** | 正文/标题用 `-apple-system / Segoe UI / 微软雅黑 / PingFang / 思源黑体`，楷体用 `KaiTi / STKaiti`，等宽用 `Consolas / Courier New`；**不引任何 webfont** | 缺字、豆腐块、导出图与预览不一致 |
| 3 | **公式样式内联** | `katex-inline.ts` 由 `gen-katex-css.mjs` 生成：20 个 woff2 转 base64 内联，共 360 KB，构建期产物 | 公式退化成平铺文字（`∫₀¹` → `∫01`） |
| 4 | **图片转 data URL** | 截图前 `inlineImages()` 把所有 `<img>` 换成 data URL；拉不到的**直接摘掉** | 外链残留 → canvas tainted → `toDataURL` 抛 SecurityError |
| 5 | **零第三方运行时** | PDF 写入器（DCTDecode 直通）与 ZIP 写入器（store 模式）自研，共约 160 行；不引 jsPDF/html2canvas | 依赖树膨胀、行为不可预测 |
| 6 | **无账号 / 无遥测** | 无登录、无统计上报、无主题商店；模板与设置只落 localStorage | 需要联网才能用 |
| 7 | **资源打包进安装包** | 前端产物在 `resources/app/web`（Windows）、`assets/public`（Android）内，构建时逐文件哈希比对 | 运行时才去下载 |

### 5.1 离线审计（可复现）

`beautify-check.mjs` 在整场操作里拦截所有网络请求，只允许 `127.0.0.1` / `data:` / `blob:` / `file:`：

```js
page.on('request', (req) => {
  const u = req.url()
  if (!u.startsWith('http://127.0.0.1') && !/^(data|blob|file):/.test(u)) external.push(u)
})
```

实测结果：`externalRequests: []`，`count: 0`。覆盖了「灌文档 → 20 套模板逐个出图 →
调 19 项参数 → 换背景 / 换装订 / 上传自定义图 → 导入导出模板 → 导出 PNG/PDF」的全过程。

### 5.2 离线下的能力边界（诚实说明）

- **字体不再「可选」**。用户机器上没有楷体，水墨模板的标题会回落到宋体/衬线，风格会打折。
  这是「不引 webfont」的必然代价；如果将来要保证跨机一致，唯一办法是把字体也打进包（每款增加 2–10 MB）。
- **图片插不了远程图**。Markdown 里的 `https://…` 图片在无网环境拉不到，会被摘掉（卡片少一张图，不报错）。
  本地相对路径图片在 Electron 下可读；Web/PWA 下受浏览器安全策略限制。
- **模板分享靠文件**，不靠链接。`.lyt.json` 可以微信传、U 盘拷，但没有一键分享链接——这是没有服务端的结果。

### 8.3 从 v0.10.0 来（0.11.0 的改动）

**模板契约、参数表、`.lyt.json` 格式一个字都没动**（schema 仍是 3，19 项参数，20 套模板）。变的只有面板
挂在哪里：

| 项 | 0.10.0 | 0.11.0 |
| --- | --- | --- |
| 面板形态 | 居中模态对话框（最大 1180px，`.ce-mask` 铺满视口） | **整屏面板**：铺满编辑区、保留菜单栏作标题，`.ce` 无圆角无阴影 |

| 项 | 0.11.2 | 0.12.0 |

**升级不丢设置**：老的 `lypora:beautify:*` 键照常读入，`normalizeTemplate()` 对缺字段回落默认值，
所以 schema 3 存的模板打开后只是"新装饰都是默认值"。id 全部沿用，用户的"我的模板"不受影响。

**两处用户可感知的修复**（0.11.2 报的）：

1. 「圆角」滑块与「圆切角」选项看着没反应 —— 真因有两层：`.ce-img` 写死白底把圆角填平了；
   `captureCard` 又把 `border-radius` 抹成 0。现在预览走透明底 + 保留圆角，导出 PDF 时才拉平。
   顺带把预览出图从 320px 提到 800px（2 倍屏要 800 设备像素才不糊）。
2. 回形针/订书钉"显示错误" —— 原来是用三个 CSS 边框拼的口袋。现在回形针是一条线走完的 SVG 路径
   （内圈收在中段，不是拖到底部以外），订书钉是填充路径画的扁金属带（冠腿比 1:2，接近真实 24/6 钉）。

### 8.5 从 v0.12 来（0.13.0 的改动）

0.13.0 是**纯增量**：老模板、老样式包、老参数一个没动。

| 项 | 0.12.0 | 0.13.0 |
| --- | --- | --- |
| 模板 schema | 4 | **5**（`decor` 新增 `panel/headings/rule/ornaments/surface/listNo`，`tokens` 新增 `panelBg/patternInk`） |
| 内置模板 | 28 套 | **29 套**（`popart` 波普撞印，带 3 个配色变体） |
| 参数 | 29 项 / 7 组 | **44 项 / 11 组**（+ 4 级标题 ×12、+ 每枚贴纸 ×8；波普在面板上是 107 个控件） |
| 项目符号 | 6 式 | 7 式（加 `★`） |
| 样式包 | schema 4 | **schema 5**（schema 4 的包照常导入，新字段回落默认值） |

**为什么老模板一个像素都不会变**：新字段的默认值全部是"不画"——`--c-band: 0`、
`--c-panel-bg: transparent`、`--c-panel-border: 0`、`--c-panel-shadow: none`；
`headCss()` 对"全是默认值"的级别**直接不生成规则**；`hr` 的默认背景与原来
`border-top: 1px solid var(--c-rule)` 视觉等效。所以 28 套的出图与 0.12.0 逐像素一致
（`beautify-check` B 组的采样色数与 sig 都没变）。

**三个已知坑（写在这里省得下次再踩）**：

1. `card-capture.ts` 会把整份样式表内联进 SVG 的 `<style>`，那里**不能出现裸的小于号**——
   连 CSS 注释里写 `ol 的 start 属性` 都不行。现在 `<style>` 包了 CDATA，从根上解决。
2. 给缩略图加装饰要同时压三个系数：`--c-band-k`（外带）、`--c-pad-k`（内面板内边距）、
   `--o-k`（贴纸）。只压带不压内边距，170px 的缩略图里 `.ly-body` 会溢出 21px。
3. `∅`（清除颜色）这类小按钮必须放在数值列的**左边**。放右边会把整行右移，`ui-check`
   的 `value-column-align` 会立刻红。
