# 09 · 美化输出与模板引擎

> 版本 `0.9.0`　来源：从 `Lypora-NEXT` 合并（`ed55355` / `64d16fa`，公共基线 `8583d5a`）
> 一句话定位：**把「写完之后怎么发出去」做成产品内的一等公民——模板是数据，不是 CSS。**

---

## 1. 这一层解决什么问题

v0.8.2 的输出能力是「8 套风格 = 8 段手写 CSS」。三个问题在真实使用里立刻显形：

1. 用户**没法调**。想改字号，得会写 CSS 并找到对应选择器。
2. 加模板要**重抄一遍**排版规则，抄漏一处就是两套模板行为不一致。
3. 分页与截图依赖 CSS 的测量基准，模板一多，基准就漂。

0.9.0 的答案是：**模板 = 一份 JSON + 一个编译器**。

```ts
interface CardTemplate {
  schema: 2
  id, name, enName, dark?
  tokens:  { paper, ink, muted, faint, accent, onAccent, rule,
             codeBg, codeInk, quoteBg, quoteRule, mark, shadow }   // 13 个颜色/底色
  metrics: { padX, padTop, padBottom, fontSize, lineHeight,
             radius, titleSize, headRule, pageNo, brand }          // 10 个度量与开关
  decor:   { texture, accent, corner, tape, stamp, cover }         // 6 个装饰位
  code:    { com, str, num, kw, fn }                               // 5 个高亮色
  font:    { body, head, mono }                                    // 3 个字体栈
}
```

37 个字段，全部可序列化、可校验、可导入导出。

## 2. 分层与职责边界

```
┌─────────────────────────────────────────────────────────────┐
│  外壳层：Electron（desktop/）· Capacitor（core/android/）· Web/PWA │
├─────────────────────────────────────────────────────────────┤
│  界面层：menubar · beautify-panel · outline · statusbar        │
├─────────────────────────────────────────────────────────────┤
│  能力层：io/（文件、图片、原生桥）· save-binary（二进制落盘）      │
├─────────────────────────────────────────────────────────────┤
│  输出层：template（模板）→ card-layout（分页）→ card-capture（光栅化）│
├─────────────────────────────────────────────────────────────┤
│  编辑器层：CM6 + live-preview + 高亮 + KaTeX + mdToHtml          │
└─────────────────────────────────────────────────────────────┘
```

**关键边界：输出层绝不反向依赖界面层。** `export/` 里没有任何 DOM 选择器指向编辑器，
只吃一段 markdown 字符串。好处是同一套输出能力可以被菜单、快捷键、未来的 CLI 或
批量导出复用；坏处是它不知道「当前滚动到哪」，所以封面标题要从文档首 h1 推断——这是
刻意的取舍。

### 2.1 集成方式（只有三处触点）

| 位置 | 改动 | 说明 |
| --- | --- | --- |
| `core/src/main.ts` | `import { createBeautifyPanel }` | 引入面板工厂 |
| `core/src/main.ts` | `const beautify = createBeautifyPanel({ getContent, getDocName })` | 注入两个取值函数，面板不碰编辑器实例 |
| `core/src/main.ts` | 文件菜单新增 `{ id: 'file-beautify', action: () => beautify.open() }` | 唯一入口，移动端菜单自动继承（移动端按 id 遍历同一份菜单定义） |

面板本身是**零框架的手写 DOM**，与项目其余 UI 一致（不引入 React/Vue）。它对外只暴露
`open()`，内部状态（当前模板、尺寸、分页模式、页码）自己管，关掉即销毁，不残留监听。

## 3. 模板机制

### 3.1 正交设计：骨架 × 变量 × 装饰位

```
CARD_BASE_CSS（一份，写死排版规则，只读 var(--c-*)）
        +
compileTemplate(t)（每套模板生成一段变量块）
        +
DECOR_CSS（一份，8 纹理 + 4 强调位 + 2 折角，全部靠 data 属性命中）
```

渲染时只看四个属性：

```html
<div class="ly-card" data-tpl="note" data-tex="grain" data-acc="none"
     data-corner="fold" data-cover="center"> … </div>
```

好处是**组合爆炸但不重复代码**：12 套模板 × 8 纹理 × 4 强调位 × 2 折角 = 768 种外观，
而 CSS 总量只有一份骨架 + 一份装饰表 + 12 段变量（编译后约 9 KB）。

约束（写在 `compile.ts` 头部注释里，评审时按这条卡）：模板**只能改变量，不能改盒模型**。
一旦允许模板写 `display` / `width` / `padding`，分页的测量基准就不可控了。

### 3.2 参数：17 项表驱动，面板自动生成

`params.ts` 里是一张表：

```ts
{ path: 'metrics.fontSize', kind: 'number', labelKey: 'tpl.p.fontSize', min: 12, max: 22, step: 0.5, unit: 'px' }
{ path: 'decor.texture', kind: 'select', options: [none, grain, grid, dots, ruled, fiber, halo, stripe] }
{ path: 'metrics.headRule', kind: 'toggle' }
```

面板遍历这张表 → 生成滑块 / 色盘 / 开关 / 胶囊组。**加一套模板不需要写任何 UI**，
加一个可调项也只需要在表里加一行。读写走 `getPath/setPath`（点路径），不 eval、不拼字符串。

| 分组 | 参数 |
| --- | --- |
| 颜色（4） | 纸张、正文、强调色、代码底色 |
| 版面度量（5） | 正文字号、行高、标题字号、左右留白、圆角 |
| 版面元素（2） | 页眉、页码 |
| 纹理与装饰（6） | 纹理、强调位、折角、封面排布、顶部胶带、印章 |

表外另有一行**字体族**选择（无衬线 / 衬线 / 楷体 / 等宽，4 种预设）——它换的是整条
`font.stack`，三处同时改，不适合走「单字段」那套 `path`，所以单独占一行。

### 3.3 改参数为什么必须重新分页

字号从 15 调到 21，每页能装的段落数就变了。所以参数一变走的不是「重绘 CSS」，而是
**完整重跑 `paginate()`**：离屏卡片重新测量 → 重新切页 → 重新出图。检查脚本用
「页数变化」来验证这条链路真的接通（实测 4 页 → 5 页）。

代价是每次改动要 100~300ms。用 160ms 防抖合并连续拖动；渲染用递增 token 丢弃过期结果，
快速拖滑块时旧图不会覆盖新图。

### 3.4 模板的进出与安全

| 能力 | 实现 | 关键点 |
| --- | --- | --- |
| 内置模板 | `builtin.ts` 常量数组（12 套） | 前 8 套 id 与 v0.8.2 完全一致，视觉由 token 重新表达 |
| 我的模板 | localStorage `lypora:beautify:userTemplates`（上限 40 套） | 存整份模板对象，含微调 |
| 导出模板 | `.lyt.json`，带 `schema` / `exportedAt` / `app` 元信息 | 走 `saveBinary`，桌面弹原生对话框 |
| 导入模板 | 读文件 → `importTemplate()` 校验 → 落地 | **id 冲突加后缀，绝不覆盖内置** |
| 恢复默认 | 用同 id 的内置/用户模板替换当前 | — |

**校验是安全边界，不是格式检查。** 模板里的字符串最终会被拼进 `<style>`，一个 `}`
就能跳出变量块改写整页样式。所以 `io.ts` 按**语法形态**白名单：

```ts
if (/[;{}<>@\\]/.test(s)) return null            // 结构性字符直接拒
if (/url\s*\(|expression\s*\(|javascript:/i.test(s)) return null
// 只放行：具名色白名单 / #hex / rgb(a) / hsl(a) / linear|radial-gradient / 投影
```

数值一律 `clamp` 到区间，枚举一律取白名单内的值，字体栈只允许字母、空格、逗号、引号、连字符。
非法字段**丢弃并回落到默认值**，不是整份拒绝——用户手改 JSON 时最多是「某个参数没生效」，
不会得到一份坏模板或一个坏页面。

## 4. 数据流

```
CM6 doc ──mdToHtml()──► HTML ──DOMParser──► 顶层块数组
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    │ paginate()：离屏卡片逐块实测 scrollHeight          │
                    │   装不下 → 换页；单块超整页 → 按行二分再拆          │
                    │   页眉/页脚/留白全部来自模板，直接影响可用高度       │
                    └─────────────────────────┬─────────────────────────┘
                                              ▼
                                   CardPage[]（纯 HTML 字符串）
                                              │
        ┌─────────────────────────────────────┼─────────────────────────────────────┐
        ▼                                     ▼                                     ▼
renderPagePreview()                  renderPagesToPng()                    renderPagesToPdf()
  （面板预览，≤320px 宽）              （单页 PNG / 多页 ZIP）                （JPEG → 手写 PDF）
        └─────────────────────────────────────┴─────────────────────────────────────┘
                                              ▼
                    saveBinary()：Electron 原生对话框 / Capacitor 分享 / 浏览器下载
```

三条出口共用 `stylesheetFor(template)` 与 `pageAsFragment(page, size, tpl)`，
所以「预览 / PNG / PDF」三者像素一致，不存在两套渲染。

## 5. 离线运行所需条件

「完全本地离线」不是一句承诺，是七个具体条件同时成立：

| # | 条件 | 实现 | 违反会怎样 |
| --- | --- | --- | --- |
| 1 | **无后端依赖** | 全流程在渲染进程内完成 | 断网即不可用 |
| 2 | **字体只用系统栈** | 正文/标题用 `-apple-system / Segoe UI / 微软雅黑 / PingFang / 思源黑体`，楷体用 `KaiTi / STKaiti`，等宽用 `Consolas / Courier New`；**不引任何 webfont** | 缺字、豆腐块、导出图与预览不一致 |
| 3 | **公式样式内联** | `katex-inline.ts` 由 `gen-katex-css.mjs` 生成：20 个 woff2 转 base64 内联，共 360 KB，构建期产物 | 公式退化成平铺文字（`∫₀¹` → `∫01`） |
| 4 | **图片转 data URL** | 截图前 `inlineImages()` 把所有 `<img>` 换成 data URL；拉不到的**直接摘掉** | 外链残留 → canvas tainted → `toDataURL` 抛 SecurityError |
| 5 | **零第三方运行时** | PDF 写入器（DCTDecode 直通）与 ZIP 写入器（store 模式）自研，共约 160 行；不引 jsPDF/html2canvas | 依赖树膨胀、行为不可预测 |
| 6 | **无账号 / 无遥测** | 无登录、无统计上报、无主题商店；模板与设置只落 localStorage | 需要联网才能用 |
| 7 | **资源打包进安装包** | 前端产物在 `resources/app/web`（Windows）、`assets/public`（Android）内，构建时逐文件哈希比对 | 运行时才去下载 |

### 5.1 离线审计（可复现）

`beautify-check.mjs` 在整场操作里拦截所有网络请求，只允许 `127.0.0.1` / `data:` / `blob:` / `file:`：

```js
page.on('request', (req) => {
  const u = req.url()
  if (!u.startsWith('http://127.0.0.1') && !/^(data|blob|file):/.test(u)) external.push(u)
})
```

实测结果：`externalRequests: []`，`count: 0`。覆盖了「灌文档 → 12 套模板逐个出图 →
调 17 项参数 → 导入导出模板 → 导出 PNG/PDF」的全过程。

### 5.2 离线下的能力边界（诚实说明）

- **字体不再「可选」**。用户机器上没有楷体，水墨模板的标题会回落到宋体/衬线，风格会打折。
  这是「不引 webfont」的必然代价；如果将来要保证跨机一致，唯一办法是把字体也打进包（每款增加 2–10 MB）。
- **图片插不了远程图**。Markdown 里的 `https://…` 图片在无网环境拉不到，会被摘掉（卡片少一张图，不报错）。
  本地相对路径图片在 Electron 下可读；Web/PWA 下受浏览器安全策略限制。
- **模板分享靠文件**，不靠链接。`.lyt.json` 可以微信传、U 盘拷，但没有一键分享链接——这是没有服务端的结果。

## 7. 已知边界

| 项 | 状态 | 说明 |
| --- | --- | --- |
| 分页均衡 | 未做 | 当前「装不下就换页」，大代码块会独占一页留半页空白。改成「先算总高再均分」会拆块，需权衡 |
| 模板缩略图 | 简化 | 画廊用双色斜切块代替真实缩略图（真实缩略图要预渲染 12 张 PNG，收益与成本不划算） |
| 渐变纸张 + `<input type=color>` | 退化 | 色盘只能表达纯色，编辑渐变模板的「纸张」会退化成纯色；想恢复走「恢复默认」 |
| 桌面「另存为」对话框 | IPC 已通，未人工点过 | `saveBinary` 已暴露（`--selftest` 可见），仍需人工点一次确认落盘 |
| Android 真机导出 | 未验证 | `shareBinary` 走 Documents + 分享面板，需装机实测 |
| 用户模板跨设备同步 | 不做 | 无服务端，只能导出/导入文件 |
| 模板库 | 12 套 | 加模板只加数据（`builtin.ts`），但需要有人设计 token |

## 8. 与 v0.8.2 的差异（升级须知）

| 项 | v0.8.2 | 0.9.0 |
| --- | --- | --- |
| 菜单入口 | 文件 → 导出卡片（`file-export-card`） | 文件 → 美化输出（`file-beautify`） |
| 风格数 | 8 套固定 CSS | 12 套模板，全部可调 |
| 可调参数 | 无 | 17 项 + 字体族 |
| 模板进出 | 无 | `.lyt.json` 导入导出、我的模板 |
| localStorage | — | `lypora:beautify:template` / `:userTemplates` / `:beautify-layout` |
| 验收脚本 | `card-check.mjs` | `beautify-check.mjs` |

**设置兼容**：编辑器设置键（`lypora:fontSize` 等）一个没动，0.8.2 → 0.9.0 升级不迁移、
不丢配置。美化输出的键是本次新增，0.8.2 里不存在，所以也不需要迁移。
（合并时这些键从 NEXT 原型里的 `lypora:next:*` 改成了 `lypora:beautify:*`，
理由见 `docs/releases/v0.9.0/decision-log.md`。）
