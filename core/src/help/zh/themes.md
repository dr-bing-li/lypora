# 主题使用与兼容性

## 内置主题

菜单「主题」里 6 套，全部按同一套 CSS 变量实现，切换只改根节点变量，不重建编辑器：

| 主题 | 说明 |
| --- | --- |
| Github | 默认，浅色，等宽感最接近代码仓库的 README |
| Night | 深色，长时间写作 |
| Pixyll | 极简白底，衬线正文 |
| Whitey | 浅灰纸感 |
| Vue | 绿色强调，标题偏细 |
| Newsprint | 报章味，字距松 |

## 导入自定义 CSS

「主题 → 导入主题…」选一个 `.css` 即可，文件会存进浏览器本地库（不上传），在菜单里以「自定义：文件名」出现，可随时删除。

导入时做两件事，不是原样注入：

1. **选择器转译** —— 把 `#write`、`.markdown-body` 这类针对参考实现 DOM 的选择器映射到本项目的编辑器结构。
2. **变量转译** —— 把主题里的颜色 / 字体 / 间距收敛到本项目的 CSS 变量上，避免一套主题把界面别处打乱。

导入后会提示「保留了 N 条规则、M 个变量」，说明有多少内容真的生效了。

## 第三方 Typora 主题的兼容性

**结论先说：能用的部分能用，但不会 100% 还原。**

- 只改颜色、字体、行距、标题样式的主题，基本可以完整迁移。
- 依赖对方 DOM 结构（特定的 `div` 层级、伪元素装饰、液态布局）的主题，只会部分生效。
- `mark` 高亮统一映射到本项目的 `.md-hl`；如果主题里对 `mark` 有背景色，会一并带过来。
- 主题里带外部资源（`@font-face` 指向远程、`background-image: url(http…)`）会被拦下 —— 一是离线环境下加载不出来，二是主题文件属于外部输入，不该让它发请求。

导入后如果显示不对，优先怀疑这三处：选择器没被识别、变量名不同、依赖了对方的结构。

## 深色与界面

- 深色主题会同步改浏览器 / 窗口的 `theme-color`（手机状态栏跟着变）。
- 主题是"这台机器"的偏好，存在本地，不写进文档。
- 切换主题不影响排版导出：导出用的模板有自己的一套颜色变量，与界面主题解耦。
