# 主题使用与兼容性

## 内置主题

菜单「主题」里 6 套，全部按同一套 CSS 变量实现，切换只改根节点变量，不重建编辑器：

| 主题 | 说明 |
| --- | --- |
| Github | 默认，浅色，等宽感最接近代码仓库的 README |
| Night | 深色，长时间写作 |
| Pixyll | 极简白底，衬线正文 |
| Whitey | 浅灰纸感 |
| Vue | 绿色强调，标题偏细 |
| Newsprint | 报章味，字距松 |

## 导入自定义 CSS

「主题 → 导入主题…」选一个 `.css` 即可，文件会存进浏览器本地库（不上传），在菜单里以「自定义：文件名」出现，可随时删除。

导入时做的不是原样注入，而是四步转译：

1. **选择器转译** —— 把 `#write`、`h1`、`pre.md-fences`、`.CodeMirror` 这类针对参考实现 DOM 的选择器，映射到本项目的编辑器结构（`.cm-line.md-*` 与表格/图片/公式容器）。
2. **组合符归一** —— 页面容器后面的 `>` 按"后代"处理；`p + p` 这种"相邻兄弟"在整篇文档是平铺行的模型里无法表达，会整条丢弃并计入统计。
3. **变量转译** —— 颜色 / 字体 / 间距收敛到本项目的 CSS 变量，并对菜单栏、侧栏、状态栏分别做对比度兜底，避免"深色侧栏配深色文字"。
4. **版面保护** —— 会破坏行模型的声明（行上的 `margin`、`width`、`position`）被丢弃；代码块这种"一组行"的块级盒模型（边框 / 圆角 / 投影 / 内边距）拆给首行与末行，保证还是"一块"而不是"每行一个框"。

导入后会提示「保留了 N 条规则、M 个变量」，说明有多少内容真的生效了。

## 第三方 Typora 主题的兼容性

**结论先说：常规版式主题现在能还原到接近原样的程度，但不会 100% 一致。**

已经能带过来的（v0.14.4 起）：

- **纸张纹理与整页渐变**——`html`/`body` 上的渐变会铺到编辑区底色上；
- **标题自动编号**——`counter` + `::before` 的编号照常出现；
- **段落卡片 / 引用色条 / 列表圆点**——伪元素装饰保留，并给行补上定位基准，装饰不会飘到窗口左上角；
- **主题自己的字号基准**——`#write{font-size}`、`html{font-size:11pt}` 会换算成倍率，`rem` 排版不再整体放大约 9%；你拖字号滑块仍是在主题基准上缩放；
- **代码块配色与红绿灯圆点**——圆点只在块首画一套，不会每行一套；边框与圆角也是"整块一圈"。

明确做不到的（是模型差异，不是没修）：

| 主题依赖的东西 | 本项目的模型 | 结果 |
| --- | --- | --- |
| 段落**之间**的间距（`p + p`） | 整篇是平铺的行，行上没有外边距 | 该条规则丢弃 |
| 块内跨行居中的装饰（水印、跨行竖排字） | 一行一个盒子 | 只能落在某一行上 |
| `display:table` 之类把正文重排的布局 | 行序即源序 | 只保文字层，放弃布局层 |
| 远程字体 / 远程背景图 | 离线优先 + 外部输入不发请求 | 拦下 |

导入后如果显示不对，优先怀疑这三处：选择器没被识别、变量名不同、依赖了对方的结构。
想自己核对，可以拿主题包里的 `preview.html`（原作者的预览页）与本项目并排看——
两边都套上同一份 CSS，差异一眼就能看出在哪一档。

## 深色与界面

- 深色主题会同步改浏览器 / 窗口的 `theme-color`（手机状态栏跟着变）。
- 主题是"这台机器"的偏好，存在本地，不写进文档。
- 切换主题不影响排版导出：导出用的模板有自己的一套颜色变量，与界面主题解耦。
