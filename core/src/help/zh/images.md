# 图片引用方法

图片有两个互相独立的策略，都在「设置」菜单里，组合起来共 6 种行为。

## 1. 引用方式（决定 Markdown 里写什么）

| 选项 | 写进文档的内容 | 适用 |
| --- | --- | --- |
| **文件引用**（默认） | `![](assets/photo.png)` 这类路径 | 想和图片一起放进仓库 / 网盘同步 |
| **内嵌 Base64** | `![](data:image/png;base64,iVBOR…)` | 单文件交付，不想带附件目录 |

选了内嵌后，路径策略整段失效（没有路径可写），所以设置里那三项会置灰。

## 2. 路径策略（文件引用下有效）

| 选项 | 写入的路径 | 说明 |
| --- | --- | --- |
| **复制到附件目录**（默认） | `assets/photo.png` | 把图片复制到文档同级的附件目录，最省心 |
| **相对路径** | `../images/photo.png` | 引用图片当前位置，不复制 |
| **绝对路径** | `/home/me/pics/photo.png` | 同一台机器上的固定位置 |

附件目录的选取顺序：正文里已经出现过的目录 → `assets` → `images` → `img` → 都不存在就新建 `assets`。重名时自动加时间戳前缀（`20261112-101530-photo.png`），不会覆盖已有图片。

## 三种插入途径

1. **格式 → 插入图片**（`Ctrl+Shift+I`），或手机工具栏的图片按钮。
2. **拖放**：把图片文件拖进编辑器。
3. **粘贴**：从截图工具、网页里直接 `Ctrl+V`。

三条路最后走同一条管线，所以都可以选择三种路径模式。粘贴截图比较特殊：剪贴板里的位图**没有磁盘路径**，会先落成临时 PNG 再按正常流程处理；临时文件不会自动删除（相对/绝对路径模式下正文引用的就是它，删了图就断）。

## 路径解析的陷阱

- 相对路径的基准是**文档所在目录**，不是应用安装目录。所以切换/另存为文档后，图片的解析基准会立即跟着变。
- 桌面版里，拖放文件拿真实路径要通过 Electron 的 `webUtils`（新版已移除 `File.path`），拿不到时会自动退回内嵌 Base64。
- Android 上相对路径的基准是 `Documents/Lypora`，导出的文档与图片都在这棵树下。

## 建议

- 论文 / 笔记仓库：**文件引用 + 复制到附件目录**。
- 要发给别人一篇带图的文章：**内嵌 Base64**，或者直接用「排版输出」导出 PDF/长图。
- 图片很多、体积敏感：**文件引用 + 相对路径**，自己管理附件目录。
