# Lypora v0.11.0 界面评估报告（美观度 × 易用性）

> 评估对象：`v0.11.0`（commit `d0049d1`，Release #442528322）· 评估日期：2026-11-12
> 评估方式：把 `dist` 跑起来，用真实浏览器渲染后逐屏取证（截图 + `getComputedStyle` 实测 + 对比度计算 + 真实鼠标/键盘操作），不做代码猜测。
> 视口：1440×900 · 1280×860 · 1180/1100/1024/900×860 · 390×844（触屏，DPR 2）
> 主题：Github（默认浅色）· Night（深色）
> 证据截图：`artifacts/ui-audit/key/`（报告内嵌，可直接在本编辑器里看）

## 0. 结论速览

共 20 项发现：**高 4 · 中 9 · 低 7**。

| 优先级 | 数量 | 集中在哪 |
|---|---|---|
| 高 | 4 | 快捷键与标签行为矛盾、弱色令牌大面积不可读、中等宽度正文贴边、确认框没有焦点陷阱 |
| 中 | 9 | 菜单层级与指示器、状态栏信息/操作混排、搜索面板全英文、手机端双栏挤压、排版面板数值输入 |
| 低 | 7 | 字号刻度、单标签空带、点击区尺寸、图标语义、表格宽度、分层 z 序、reduced-motion |

四件事最该先修（理由见各节）：

1. **`Ctrl+N` 不新增标签，而是就地替换当前干净标签**，与菜单「新建」和帮助文档写的行为都相反（TAB-1）。
2. **`--fg-faint` 被当成正文色用了**：空状态引导、菜单快捷键提示、子菜单箭头、确认框的「会丢弃修改」警告、排版面板分组标题 —— 对比度只有 **1.89–2.55**（GLB-1）。
3. **861–1100px 窗口下正文两侧零留白**，字直接贴着侧栏分割线和窗口边（DOC-1）。
4. **三键确认框打开后按一次 Tab 就跑到菜单栏**（DLG-1）。

## 1. 全局层：设计令牌与排版刻度

![](../artifacts/ui-audit/key/editor-default.png)

**GLB-1｜高｜弱色令牌被用于承载信息的文字**

| 项 | 内容 |
|---|---|
| 位置 | `core/src/style.css` 令牌 `--fg-faint`（浅 `#afb8c1` / 深 `#5c6370`）；命中 6 处界面 |
| 现状（实测） | 浅色主题：空状态提示 **1.89:1**、菜单快捷键提示 **2.01**、子菜单箭头 **2.01**、确认框警告 **1.98**；深色主题：空状态 **2.55**、排版面板分组标题与色值文本 **2.32**。全部远低于正文所需的 4.5:1 |
| 影响 | 命中的都不是装饰，而是"必须读"的文案：新用户找不到入口、老用户看不到快捷键、**在"要不要保存"的破坏性确认里看不清楚"不保存会丢弃修改"** |
| 改进方向 | ①`--fg-faint` 退回只做分隔符/装饰，凡是承载信息的文字统一改用 `--fg-muted`；②把两套主题的 `--fg-muted` 提到 ≥4.6:1（浅色 `#6e7781`→`#57606a`≈6.4，深色 `#868e96`→`#9aa4b0`≈5.6，落地后复核）；③确认框警告句改为 `--fg`，并考虑加警示色 |

**GLB-2｜中｜字号刻度没有体系**

| 项 | 内容 |
|---|---|
| 位置 | 菜单栏 / 标签栏 / 侧栏 / 状态栏 |
| 现状 | 实测同时存在 **11 / 11.5 / 12 / 12.5 / 13 / 13.3333 / 14px** 七档；`13.3333px` 是按钮继承默认字号产生的非整值 |
| 影响 | 相邻两档差 0.5px，肉眼分不出层级，只能靠颜色区分主次；13.33px 这类非整值在不同 DPR 下渲染发虚 |
| 改进方向 | 收敛成 4 档：`11`（徽标/快捷键）、`12.5`（chrome 正文）、`14`（标题）、`16`（正文），删掉 11.5/13/13.33 |

**GLB-3｜中｜没有自定义焦点环**

| 项 | 内容 |
|---|---|
| 位置 | 全局；实测 `getComputedStyle(btn).outline` = `rgb(16,16,16) auto 1px` |
| 现状 | `style.css` 里**没有任何 `:focus-visible` 规则**（唯一的品牌色 2px outline 用在 `.ce-bg.on`，那是"选中"不是"焦点"）。所有元素一律吃浏览器默认的 1px 黑框；`.cm-editor` 还被 `outline:none!important` 单独抹掉 |
| 影响 | 键盘操作时看不清焦点在哪；深色主题下黑框几乎消失；与蓝色 hover 态不是一套语言 |
| 改进方向 | 加一条全局规则 `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`，编辑器容器单独保留 `outline:none`（有光标即为焦点指示） |

## 2. 菜单栏与下拉菜单

![](../artifacts/ui-audit/key/menu-file.png)

![](../artifacts/ui-audit/key/menu-settings.png)

**MENU-1｜中｜二级菜单的指示器几乎不存在**

| 项 | 内容 |
|---|---|
| 位置 | `.mi-arrow`（`ui/menubar.ts`），设置菜单 4 项全部有子菜单 |
| 现状（实测） | 指示器是一个文字字符 `›`，**框宽只有 4px**，颜色 `--fg-faint`，对比度 **2.01:1** |
| 影响 | 用户看不出「显示模式 / 语言 / 图片引用方式 / 图片路径处理」可以再展开，只能靠"碰巧把鼠标移上去"发现；这四项恰好是设置里最常用的 |
| 改进方向 | 换成 12–14px 的 chevron 图标（`<svg>` 与侧栏图标同一套），颜色提到 `--fg-muted`；或让整行右侧留出 24px 固定指示位 |

![](../artifacts/ui-audit/key/menu-submenu.png)

**MENU-2｜中｜「设置」菜单缺分组，两类设置混在一起**

| 项 | 内容 |
|---|---|
| 位置 | 设置菜单：显示模式 › / 语言 › / 图片引用方式 › / 图片路径处理 › |
| 现状 | 4 项平铺，只靠 4px 的间距分两组，没有分组标题；前两项是应用级设置，后两项是图片专用设置 |
| 影响 | 层级信息丢失，用户得先点进去才知道是哪一类；四项全部带箭头，视觉上像同质列表 |
| 改进方向 | 加两个不可点的小标题（`--fg-muted`、11px）：「界面」、「图片」；间距按分组统一为 6px |

**MENU-3｜低｜菜单与整屏面板的层级倒挂**

| 项 | 内容 |
|---|---|
| 位置 | `.menu-drop` `z-index:240` vs `.ce-mask` `z-index:120` |
| 现状 | 菜单开着时按 `Ctrl+Shift+P`，排版面板全屏铺开，但菜单浮在面板之上（实测截图可复现）；用 F1 开帮助时同理 |
| 影响 | 偶发、但一旦发生会盖住面板标题栏，看起来像渲染错乱 |
| 改进方向 | 面板打开时主动 `close()` 菜单；同时把 z 序收成一张表（`chrome 60 / popover 240 / panel 300 / modal 400 / toast 500`） |

**MENU-4｜低｜菜单项点击区偏小**

实测菜单项高 **26px**、根按钮 43×24、字号 12.5px。桌面鼠标可用，触屏外接键盘/高分屏偏难命中，建议行高提到 30px、根按钮给 28px 高。

## 3. 标签栏

![](../artifacts/ui-audit/key/tabs-three.png)

**TAB-1｜高｜`Ctrl+N` 不新增标签，与菜单和帮助文档都矛盾**

| 项 | 内容 |
|---|---|
| 位置 | `core/src/main.ts:2021`（全局键分支）vs `main.ts:841` `newDocument()` |
| 现状（实测） | 菜单「文件 → 新建」连点两次：标签数 `1 → 2 → 3` ✅；改用 `Ctrl+N`：**标签数停在 3 不变**；在只有 1 个干净标签时按 `Ctrl+N`，标签就地变成「未命名.md」，原来的「功能演示.md」消失 |
| 影响 | 同一个「新建」命令两条实现：菜单走 `newDocument()`（永远新标签），快捷键走 `loadDocument()`（命中"复用干净无路径标签"的规则）。而帮助文档《快捷键》里明确写着「新建文档（**新标签**） Ctrl+N」——契约与实现直接冲突 |
| 改进方向 | 把 2021 行改成调用 `newDocument()`，一行改动；`loadDocument()` 的复用规则只对"打开文件"生效 |

**TAB-2｜低｜单标签时整条标签栏空着**

实测标签栏高 34px、通栏 1440px，单标签只占 115px，右侧约 1300px 是空带。建议标签数 ≤1 时收起标签栏（`hidden`），或在空白区放"拖文件到此处"的提示。

**TAB-3｜低｜关闭按钮 18×18**

`#tabbar .tb-close` 实测 18×18px，低于 WCAG 2.2 的 24×24 目标尺寸。建议视觉尺寸不变、热区用 `::after` 扩到 24×24。

## 4. 左侧栏（大纲 / 文件树 / 最近）

![](../artifacts/ui-audit/key/sidebar-empty.png)

**SIDE-1｜中｜空状态没有可点的入口**

| 项 | 内容 |
|---|---|
| 位置 | `#pane-files` / `#pane-recent` 的 `.empty-hint` |
| 现状 | 只有两行字：「尚未打开文件夹」/「用「文件 → 打开文件夹」选择目录」，颜色 `--fg-faint`（1.89:1），**没有任何按钮**，下方 600px 全空 |
| 影响 | 空状态是新手第一眼看到的东西，现在既看不清，也没有下一步；用户得记住去菜单里找 |
| 改进方向 | 改成两行正文色文字 + 一个主按钮「打开文件夹…」（直接调 `doOpenWorkspace()`），与菜单同一动作 |

**SIDE-2｜低｜三个页签只有图标，语义靠猜**

侧栏顶部三枚 28×26 的图标（横线 / 文件夹 / 钟表）分别是大纲、文件树、最近。有 `title` 与 `aria-label`，但鼠标悬停才出提示。建议选中态下方加一条 2px 指示条，或把页签改成"图标 + 文字"（侧栏 250px 放得下）。

**SIDE-3｜低｜大纲深层级只靠缩进**

`[data-lv]` 1–6 级的缩进是 12px/级，字号与字重均不变。四级以后（缩进 48px）在 250px 宽的栏里只剩 190px 文字空间，长标题被截断。建议 5–6 级改为 `--fg-muted` 并统一缩进到 8px/级。

## 5. 编辑区（正文）

![](../artifacts/ui-audit/key/width-1024.png)

**DOC-1｜高｜中等宽度下正文两侧零留白**

| 项 | 内容 |
|---|---|
| 位置 | `.editor-host`（`padding: 28px 0 387px`，横向 padding 为 0）+ `--content-width: 860px` 居中 |
| 现状（实测 × 6 档） | 1440→左 415/右 165；1280→335/85；1180→285/35；**1100→左 250 / 右 0**；**1024→250 / 0**；**900→250 / 0**。也就是说窗口在 861–1160px 区间时，正文左边缘正好压在侧栏分割线上、右边缘贴着窗口边 |
| 影响 | 这是笔记本 13–14 寸最常见的工作宽度；正文贴边读起来憋闷，且 H1 与侧栏分割线粘在一起，界面显得"没做完" |
| 改进方向 | 给 `.editor-host` 加横向内边距 `padding-inline: clamp(16px, 3vw, 32px)`，让"正文最大宽度"与"最小呼吸区"两个约束同时成立；1440 下视觉不变（留白仍由居中产生） |

**DOC-2｜低｜帮助文档里表格比正文窄**

`help/zh/shortcuts.md` 的表格实测宽 642px，同页正文行宽 686px，右边短一截。建议表格 `width:100%` 与行宽对齐（若为列宽自动分配导致，可只对两列表格设 `table-layout:fixed` + 30/70）。

## 6. 状态栏

![](../artifacts/ui-audit/key/editor-default.png)

**STAT-1｜中｜只读信息与可点按钮同字号同色混排**

| 项 | 内容 |
|---|---|
| 位置 | `.statusbar` 右半段：`1,050 字 · 94 行 · UTF-8 · Markdown · 拷贝 · 源码模式 · 专注 · 打字机` |
| 现状 | 两类东西都是 11.5px、同一个 `--fg-muted`，中间只隔一个 `·`；「拷贝」是图片路径开关（35×19）、后三个是模式开关，视觉上与左边四个只读值完全同质 |
| 影响 | 用户不知道哪里能点；四个模式名还都是名词，看不出是开关（当前开/关只靠 `.on` 的底色） |
| 改进方向 | 只读值降为 `--fg-faint`（此时它就是装饰尺度，可以）、开关项换 `--fg` 并给 3px 圆角 hover 底；模式项在开启时补一个圆点或勾，让状态可见而不是只靠底色 |

**STAT-2｜中｜状态栏按钮只有 19px 高**

实测 `#btn-source` 70×19、`#btn-image-path` 35×19。文字能读，但热区只有 19px 高，触屏和外接鼠标都容易点空。建议保持视觉大小、把热区用上下负 margin + padding 撑到 28px。

**STAT-3｜低｜手机上整条状态栏消失**

`≤860px` 时 `.statusbar { display:none }`，于是**字数、行数在任何手机上都无法查看**。写作类应用里这是常用指标。建议在手机顶栏右侧保留"字数"，或收进「显示」菜单项。

## 7. 对话框与浮层

![](../artifacts/ui-audit/key/confirm.png)

**DLG-1｜高｜三键确认框没有焦点陷阱，也没有对话框语义**

| 项 | 内容 |
|---|---|
| 位置 | `core/src/ui/confirm.ts`（只有 `data-role="save-confirm"`，无 `role="dialog"` / `aria-modal`） |
| 现状（实测） | 打开后焦点正确落在「保存」；但**按一次 Tab 就跳出对话框**落到菜单栏容器，再按 Tab 依次是「文件 / 编辑 / 段落…」——也就是焦点跑到了遮罩后面；`document.querySelector('[role="dialog"]')` 为 `null` |
| 影响 | 键盘用户/读屏用户会以为对话已经关掉；在"关窗口会不会丢东西"这种关键时刻误导性很强 |
| 改进方向 | `role="dialog" aria-modal="true" aria-labelledby`；打开时记录 `document.activeElement`，把 Tab 循环限制在三个按钮内（首尾互跳），关闭后焦点还给原处。Esc/Enter 已经在捕获阶段处理，逻辑可复用 |

**DLG-2｜中｜破坏性提示是全界面最淡的一行字**

标题 13.5px/600 正常，紧跟的「选择「不保存」会丢弃本次修改。」是 11.5px、`--fg-faint`、**1.98:1**（属 GLB-1 根因，但这里后果最重）。建议这一句改用 `--fg`，并允许它换行成两行（现在挤在一行里，宽度只 300px 的框）。遮罩 `rgba(20,22,26,.28)` 也偏淡，可提到 `.4`。

![](../artifacts/ui-audit/key/search-en.png)

**DLG-3｜中｜搜索面板整体是英文，且是 CodeMirror 默认皮肤**

| 项 | 内容 |
|---|---|
| 位置 | `Ctrl+F` 打开的面板 |
| 现状 | 按钮与占位文字全英文：`Find / next / previous / all / match case / regexp / by word / Replace / replace / replace all`，与小标题行用的是 CM 自带样式，宽度定死 640px 浮在正文上方 |
| 影响 | 一个中文界面里突然出现全英文控件，第一次用会愣住；这也是唯一一处没有走 i18n 的界面文案 |
| 改进方向 | 给 `@codemirror/search` 传 `phrases` 配置（`find`/`replace`/`next`/`prev`/`all`/`matchCase`/`regexp`/`byWord`/`replaceAll`），词条进 `zh-CN.ts`；样式上把 `.cm-panel.cm-search` 的按钮对齐菜单按钮的圆角与边框 |

## 8. 排版面板

![](../artifacts/ui-audit/key/layout-desktop.png)

![](../artifacts/ui-audit/key/layout-params.png)

**LAYOUT-1｜中｜数值只能拖，不能输入**

| 项 | 内容 |
|---|---|
| 位置 | 「版面度量」与「背景」里的 5 个 `input[type=range]`：正文字号 15px / 行高 1.78 / 标题字号 36px / 左右留白 48px / 圆角 4px |
| 现状 | 数值显示在滑块最右侧（右对齐），只能拖动；想要"正好 40px"要试好几下 |
| 影响 | 排版是精度活，尤其做系列模板时希望复用同一组数值 |
| 改进方向 | 数字改成可编辑输入框（`inputmode=numeric`，失焦 clamp 到现有范围），拖动与输入共用一个 updater；顺带把数值列与颜色 hex 列统一右对齐成一列 |

![](../artifacts/ui-audit/key/mobile-layout.png)

**LAYOUT-2｜中｜手机上面板被预览挤掉一半**

| 项 | 内容 |
|---|---|
| 位置 | `≤760px` 的分段布局 |
| 现状（实测 390×844） | 面板可用高 800（顶边 44）：预览固定 **282px（35%）**、参数区 **389px（46%）**，而参数区内容高 **1851px** —— 需要滚 **4.8 屏**才到底；底部操作条 78px 固定在屏内（这点做得对） |
| 影响 | 手机上改一个参数要在 389px 的窗口里翻近 5 屏，且预览一直占着三分之一屏 |
| 改进方向 | 预览改为可折叠（默认 160px 一条，点击展开全屏预览）；参数区改成分段 Tab（模板 / 尺寸 / 颜色 / 装饰），把纵向长列表摊成横向分区 |

**LAYOUT-3｜低｜模板卡片的名字太小**

实测卡片 208×64，缩略图高约 48px、名称 **9px**。20 套模板的差异主要靠缩略图辨认，而缩略图里只有一个标题条和一个色块，实际区分度有限。建议名称提到 11px，卡片加 hover 时放大预览。

**LAYOUT-4｜低｜数值列不对齐**

颜色分组的 hex 值（`#ffffff` 等）在色块右侧左对齐，滑块数值在行末右对齐，两列不在同一条竖线上。建议统一成右对齐的 48px 数值列。

## 9. 手机端外壳（≤860px）

![](../artifacts/ui-audit/key/mobile-editor.png)

**MOB-1｜中｜底部两层工具栏占掉 18% 屏高，格式条还横向溢出**

| 项 | 内容 |
|---|---|
| 位置 | `#mobile-toolbar`（12 个格式按钮）+ `#mobile-dock`（7 个导航按钮） |
| 现状（实测） | 格式条 390×50、dock 390×103（按钮 53×48），合计 **153px**；格式条 12 个按钮在 390px 里放不下，最后一个「图片」被切成半截，**没有任何渐隐或指示**说明还能滑 |

## 11. 已经做得好的地方（改的时候别动）

- **正文排版本身**：16px/28px 行高、`--content-width` 单一真源、标题字重梯度清楚，正文可读性是全界面最好的部分。
- **标签栏信息密度**：33px 高、标题 12.5px、脏标记固定 8px 占位不抖动、长文件名正确省略号截断（实测 `scrollWidth 432 / clientWidth 163 → ellipsis`）。

- **排版面板的信息组织**：模板画廊 4 列 20 套 + 参数分组（尺寸/分页/颜色/版面度量/背景/纹理与装饰/装订），比多数同类工具更系统。
- **手机底部 dock**：7 个按钮 53×48，均超过 44px 触控下限；打开/保存/大纲/导出/排版/主题/菜单 的优先级排序是对的。
- **只读帮助文档**：干净、无 `#`/管道符泄漏，表格与列表都正确渲染。
